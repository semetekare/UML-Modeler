# 19 Развёртывание

> **UML 2.5.1** (formal/2017-12-05) · Раздел 19 · печатные стр. 653–668 · PDF стр. 695–710

## 19.1 Краткое описание

Пакет «Развёртывание» определяет конструкции, которые можно использовать для определения архитектуры выполнения систем и назначения программных артефактов элементам системы. Предоставляется упрощённая модель развёртывания, достаточная для большинства современных приложений. Там, где требуются более сложные модели развёртывания, пакет может быть расширен через профили или метамодели, чтобы представлять конкретные аппаратные и/или программные среды.

## 19.2 Развёртывание

### 19.2.1 Краткое описание

Развёртывание фиксирует связи между логическими и/или физическими элементами систем и назначенными им информационно-технологическими активами.

### 19.2.3 Семантика

Развёртывание фиксирует связь между конкретным концептуальным или физическим элементом моделируемой системы и назначенными ему информационными активами. Элементы системы представляются целями развёртывания (DeployedTarget), а информационные активы — развёртываемыми артефактами (DeployedArtifact). Цели развёртывания и развёртываемые артефакты — абстрактные классы, которые не могут быть созданы непосредственно. Однако они конкретизируются как конкретные классы, как описано в последующих подпунктах об артефактах и узлах.

Отдельные отношения развёртывания можно приспособить к конкретным применениям, добавив спецификации развёртывания, содержащие конфигурационную и/или параметрическую информацию, и они могут быть расширены в конкретных профилях компонентов. Например, стандартные ненормативные стереотипы, которые профиль мог бы добавить к спецификации развёртывания, включают «concurrencyMode» с помеченными значениями {thread, process, none} и «transactionMode» с помеченными значениями {transaction, nestedTransaction, none}.

Информация спецификации развёртывания становится входными данными времени выполнения для компонентов, связанных с целями развёртывания через их связи deployedElements. Используя эти связи, спецификации развёртывания могут адресоваться конкретным видам контейнеров, если только контейнеры являются видами компонентов. Как показано на рисунке 19.1, спецификации развёртывания могут быть зафиксированы как элементы отношений развёртывания, поскольку они являются артефактами (описаны в следующем подпункте). Кроме того, спецификации развёртывания могут быть связаны только с целями развёртывания, являющимися средами выполнения (описаны в подпункте об узлах ниже).

Отношение развёртывания между развёртываемым артефактом и целью развёртывания может быть определено на уровне «типа» и на уровне «экземпляра». На уровне «типа» развёртывание соединяет виды целей развёртывания с видами развёртываемых артефактов. На уровне «экземпляра» развёртывание соединяет конкретные экземпляры целей развёртывания с конкретными экземплярами развёртываемых артефактов. Например, развёртывание уровня «типа» могло бы соединять «сервер приложений» с «обработчиком запросов на ввод заказов». Напротив, на уровне «экземпляра» три конкретные службы приложений (скажем, “app-server1”, “app-server-2” и “app-server3”) могут быть целями развёртывания для шести разных экземпляров «обработчика запросов».

Для моделирования сложных моделей, состоящих из составных структур, свойство, функционирующее как часть (то есть принадлежащее композиции), может быть целью развёртывания. Аналогично спецификации экземпляра могут быть целями развёртывания в отношении развёртывания, если они представляют узел, функционирующий как часть внутри объемлющей иерархии композиции узлов, или если они представляют артефакт.

### 19.2.4 Нотация

Цели развёртывания показываются как перспективное изображение куба с меткой — именем цели развёртывания, перед которым стоит двоеточие. Элементы системы, развёрнутые на цели развёртывания, и развёртывания, соединяющие их, могут рисоваться внутри перспективного куба. Либо развёрнутые элементы системы могут показываться текстовым списком имён элементов.

Развёртывания изображаются той же нотацией пунктирной линии, что и зависимости. Когда отношения развёртывания показаны внутри графики цели развёртывания, метка не требуется. Либо отношения развёртывания могут быть украшены ключевым словом «deploy», когда они не содержатся внутри графики цели развёртывания. Стрелки развёртывания, как правило, рисуются от развёртываемых артефактов к целям развёртывания.

Спецификации развёртывания графически отображаются как прямоугольники классификатора и могут быть украшены ключевым словом «deployment spec». Они могут присоединяться к компоненту, развёрнутому в контейнере, обычной стрелкой зависимости.

## 19.3 Артефакты

### 19.3.1 Краткое описание

Артефакт представляет некоторый (обычно материализуемый) элемент информации, используемый или порождаемый процессом разработки программного обеспечения либо работой системы. Примеры артефактов включают файлы моделей, исходные файлы, сценарии, исполняемые файлы, таблицы баз данных, результаты разработки, документы текстовых процессоров и почтовые сообщения.

### 19.3.2 Абстрактный синтаксис

```text

                     + nestedArtifact
             {subsets ownedMember}
                                                                        {subsets client,   {subsets ownedElement,
                                                                        subsets owner}     subsets clientDependency}
                    0..1                        Artifact                 + artifact          + manifestation      Manifestation
                 + artifact             + fileName : String [0..1]
                                                                          1                               *
              {subsets namespace}
                                                                     {subsets namespace,                                   {subsets supplierDependency}
       {subsets featuringClassifier,                                 subsets classifier}                                  + manifestation
       subsets namespace, subsets      0..1                  0..1    + artifact                                      *
       redefinitionContext} + artifact
         {ordered, subsets feature,                                  {ordered, subsets

         subsets ownedMember}                                        ownedMember}                                          {subsets supplier}
                   + ownedOperation       *                    *     + ownedAttribute                                1    + utilizedElement

```

### 19.3.3 Семантика

Артефакты конкретизируют и материализуют абстрактное понятие развёртываемого артефакта. Они представляют конкретные элементы физического мира, могут иметь свойства, представляющие их характеристики, и операции, которые могут выполняться их экземплярами, а также могут создаваться многократно, так что разные экземпляры могут развёртываться на различные цели развёртывания, каждый со своими значениями свойств.

Более сложные артефакты могут создаваться их организацией в иерархии композиции. Так, спецификация развёртывания для компонента может содержаться внутри артефакта, что позволяет развернуть компонент и его параметры как один экземпляр артефакта.

Артефакты могут расширяться, чтобы лучше представлять потребности конкретных информационных элементов. Например, профили могут расширять артефакт для моделирования наборов файлов. UML определяет несколько стандартных стереотипов для артефактов, включая «source» и «executable», которые могут далее специализироваться по мере необходимости. Например, профиль EJB мог бы определить «jar» как подкласс «executable» для исполняемых архивов Java.

Артефакт может воплощать, или манифестировать, ряд элементов модели. Артефакту принадлежат манифестации, каждая из которых представляет использование некоторого упаковываемого элемента. Профили могут расширять отношение манифестации, чтобы указывать конкретные формы воплощения. Например, «tool generated» и «custom code» могли бы быть двумя манифестациями для разных классов, воплощённых в артефакте.

### 19.3.4 Нотация

Артефакт представляется обычным прямоугольником класса с ключевым словом «artifact». Либо он может изображаться значком (например, значком документа, показанным на рисунке 19.9). По выбору подчёркивание имени экземпляра артефакта может быть опущено, так как предполагается, что контекст известен пользователям.

Манифестация нотируется так же, как абстракция, то есть пунктирной линией с открытым наконечником, помеченной ключевым словом «manifest».

## 19.4 Узлы

### 19.4.1 Краткое описание

Узлы конкретизируют и материализуют абстрактное понятие целей развёртывания. Они могут быть вложенными и соединяться в системы произвольной сложности с помощью путей связи. Как правило, узлы представляют либо аппаратные устройства, либо программные среды выполнения.

### 19.4.2 Абстрактный синтаксис

```text
                              Class       DeploymentTarget
      {subsets ownedMember}
               + nestedNode
                        *
                0..1
                              Node
               + node                                               Association
   {subsets namespace}
                 Device         ExecutionEnvironment            CommunicationPath
Figure 19.11 Nodes
```

### 19.4.3 Семантика

Узел — вычислительный ресурс, на который могут развёртываться артефакты через отношения развёртывания для выполнения. Для сложных приложений моделирования узлы могут иметь сложную внутреннюю структуру, заданную вложенностью, и могут соединяться между собой для представления конкретных ситуаций. Внутренняя структура узлов может состоять только из других узлов. Помимо участия в развёртываниях, узлы приобретают набор связанных элементов, выводимых из отношений манифестации развёрнутых на них артефактов.

Узлы могут далее подтипизироваться как устройства и среды выполнения. Устройства представляют физические компоненты машины. Среды выполнения представляют стандартные программные системы, которые могут требоваться компонентам приложений во время выполнения. Конкретные профили могли бы, например, определять стереотипы для сред выполнения, такие как «OS», «workflow engine», «database system» и «J2EE container».

Устройство — физический вычислительный ресурс с вычислительными возможностями, на который могут развёртываться артефакты для выполнения. Устройства могут быть сложными (то есть состоять из других устройств) — либо через принадлежность пространству имён, либо через атрибуты, которые сами типизированы устройствами. Целые физические вычислительные системы могут разлагаться на составные части таким образом. Примеры устройств могут включать «application server», «client workstation», «mobile device» и «embedded device».

Как правило, среды выполнения назначаются некоторому, часто более высокоуровневому, устройству или общему системному узлу через отношение композиции, определённое для узла. Среды выполнения могут быть вложенными (например, среда выполнения базы данных может быть вложена в среду выполнения операционной системы). У среды выполнения могут быть явные интерфейсы для служб системного уровня, которые могут вызываться развёрнутыми элементами. В таких случаях службы программной среды выполнения следует моделировать явно. Компоненты приложений подходящего типа затем развёртываются отношением развёртывания на конкретные узлы среды выполнения или через отношения манифестации развёртываемых артефактов. Для каждого развёртывания компонента аспекты этих служб могут определяться свойствами в спецификации развёртывания для конкретного вида среды выполнения.

Узлы могут соединяться для представления конкретных сетевых топологий с помощью путей связи, задающих конкретные соединения между экземплярами узлов. Путь связи — это ассоциация между двумя целями развёртывания, через которую они могут обмениваться сигналами и сообщениями.

### 19.4.4 Нотация

Узел изображается тем же графическим представлением, что и цель развёртывания.

Устройство показывается графикой узла с ключевым словом «device».

Среда выполнения нотируется узлом, аннотированным ключевым словом «executionEnvironment».

Пути связи между узлами изображаются так же, как обычные связи-ассоциации.

Пунктирные стрелки с ключевым словом «deploy» показывают возможность узла поддерживать развёртываемый артефакт, изображённый снаружи. Либо это может показываться вложением графики развёртываемого артефакта в символы узла.

## 19.5 Описания классификаторов

### 19.5.1 Artifact (артефакт) [Class]

#### 19.5.1.1 Описание

Артефакт — это спецификация физической части информации, используемой или порождаемой процессом разработки программного обеспечения либо развёртыванием и работой системы. Примеры артефактов включают файлы моделей, исходные файлы, сценарии и двоичные исполняемые файлы, таблицу в системе баз данных, результат разработки, документ текстового процессора, почтовое сообщение. Артефакт — источник развёртывания на узел.

#### 19.5.1.2 Диаграммы

Развёртывания, артефакты

#### 19.5.1.3 Обобщения

Classifier, DeployedArtifact

#### 19.5.1.4 Специализации

DeploymentSpecification

#### 19.5.1.5 Атрибуты

- fileName : String [0..1]

  конкретное имя, используемое для ссылки на артефакт в физическом контексте. Пример: имя в файловой системе, универсальный указатель ресурса.

#### 19.5.1.6 Концы ассоциаций

- ♦ manifestation : Manifestation [0..*]{subsets Element::ownedElement, subsets NamedElement::clientDependency} (opposite A_manifestation_artifact::artifact) набор элементов модели, манифестируемых в артефакте. То есть эти элементы модели используются при построении (или порождении) артефакта.

- ♦ nestedArtifact : Artifact [0..*]{subsets Namespace::ownedMember} (opposite A_nestedArtifact_artifact::artifact) артефакты, определённые (вложенные) внутри артефакта. Эта ассоциация — специализация ассоциации ownedMember от пространства имён к именованному элементу.

- ♦ ownedAttribute : Property [0..*]{ordered, subsets Classifier::attribute, subsets Namespace::ownedMember} (opposite A_ownedAttribute_artifact::artifact) атрибуты или концы ассоциаций, определённые для артефакта. Эта ассоциация — специализация ассоциации ownedMember.

- ♦ ownedOperation : Operation [0..*]{ordered, subsets Classifier::feature, subsets A_redefinitionContext_redefinableElement::redefinableElement, subsets Namespace::ownedMember} (opposite A_ownedOperation_artifact::artifact) операции, определённые для артефакта. Эта ассоциация — специализация ассоциации ownedMember.

#### 19.5.2.1 Описание

Путь связи — это ассоциация между двумя целями развёртывания, через которую они могут обмениваться сигналами и сообщениями.

#### 19.5.2.2 Диаграммы

Узлы

#### 19.5.2.3 Обобщения

#### 19.5.2.4 Ограничения

### 19.5.3 DeployedArtifact (развёртываемый артефакт) [Abstract Class]

#### 19.5.3.1 Описание

Развёртываемый артефакт — это артефакт или экземпляр артефакта, развёрнутый на цель развёртывания.

#### 19.5.3.2 Диаграммы

Развёртывания, артефакты, экземпляры

#### 19.5.3.3 Обобщения

NamedElement

#### 19.5.3.4 Специализации

Artifact, InstanceSpecification

### 19.5.4 Deployment (развёртывание) [Class]

#### 19.5.4.1 Описание

Развёртывание — это назначение артефакта или экземпляра артефакта цели развёртывания. Развёртывание компонента — это развёртывание одного или нескольких артефактов или экземпляров артефактов на цель развёртывания, по выбору параметризованное спецификацией развёртывания. Примеры — исполняемые файлы и конфигурационные файлы.

#### 19.5.4.2 Диаграммы

Развёртывания

#### 19.5.4.3 Обобщения

Dependency

#### 19.5.4.4 Концы ассоциаций

- ♦ configuration : DeploymentSpecification [0..*]{subsets Element::ownedElement} (opposite DeploymentSpecification::deployment) спецификация свойств, параметризующих развёртывание и выполнение одного или нескольких артефактов.

- deployedArtifact : DeployedArtifact [0..*]{subsets Dependency::supplier} (opposite A_deployedArtifact_deploymentForArtifact::deploymentForArtifact) артефакты, развёрнутые на узел. Эта ассоциация специализирует ассоциацию поставщика.

- location : DeploymentTarget [1..1]{subsets Dependency::client, subsets Element::owner} (opposite DeploymentTarget::deployment) цель развёртывания, являющаяся целью данного развёртывания.

### 19.5.5 DeploymentSpecification (спецификация развёртывания) [Class]

#### 19.5.5.1 Описание

Спецификация развёртывания задаёт набор свойств, определяющих параметры выполнения артефакта компонента, развёрнутого на узле. Спецификация развёртывания может быть нацелена на конкретный вид контейнера. Артефакт, материализующий или реализующий свойства спецификации развёртывания, — это дескриптор развёртывания.

#### 19.5.5.2 Диаграммы

Развёртывания

#### 19.5.5.3 Обобщения

Artifact

#### 19.5.5.4 Атрибуты

- deploymentLocation : String [0..1]

  место, в которое артефакт развёрнут на узле. Как правило, это «каталог» или «адрес в памяти».

- executionLocation : String [0..1]

  место, в котором выполняется артефакт компонента. Это может быть локальное или удалённое место.

#### 19.5.5.5 Концы ассоциаций

- deployment : Deployment [0..1]{subsets Element::owner} (opposite Deployment::configuration)

  развёртывание, с которым связана спецификация развёртывания.

#### 19.5.5.6 Ограничения

- **deployment_target**

  Цель развёртывания спецификации развёртывания — вид среды выполнения.

  ```ocl
  inv: deployment->forAll (location.oclIsKindOf(ExecutionEnvironment))
  ```

- **deployed_elements**

  deployedElements цели развёртывания, участвующие в развёртывании, с которым связана спецификация развёртывания, — вид компонента (то есть конфигурируемые компоненты).

  ```ocl
  inv: deployment->forAll (location.deployedElement->forAll (oclIsKindOf(Component)))
  ```

### 19.5.6 DeploymentTarget (цель развёртывания) [Abstract Class]

#### 19.5.6.1 Описание

Цель развёртывания — место для развёрнутого артефакта.

#### 19.5.6.2 Диаграммы

Развёртывания, узлы, свойства, экземпляры

#### 19.5.6.3 Обобщения

NamedElement

#### 19.5.6.4 Специализации

Node, InstanceSpecification, Property

#### 19.5.6.5 Концы ассоциаций

- /deployedElement : PackageableElement [0..*]{} (opposite A_deployedElement_deploymentTarget::deploymentTarget) набор элементов, манифестируемых в артефакте, который участвует в развёртывании на цель развёртывания.

- ♦ deployment : Deployment [0..*]{subsets Element::ownedElement, subsets NamedElement::clientDependency} (opposite Deployment::location) набор развёртываний для цели развёртывания.

#### 19.5.6.6 Операции

- deployedElement() : PackageableElement [0..*] вывод для DeploymentTarget::/deployedElement

  ```ocl
  body: deployment.deployedArtifact->select(oclIsKindOf(Artifact))-
  >collect(oclAsType(Artifact).manifestation)->collect(utilizedElement)->asSet()
  ```

### 19.5.7 Device (устройство) [Class]

#### 19.5.7.1 Описание

Устройство — физический вычислительный ресурс с вычислительными возможностями, на который могут развёртываться артефакты для выполнения. Устройства могут быть сложными (то есть состоять из других устройств).

#### 19.5.7.2 Диаграммы

Узлы

#### 19.5.7.3 Обобщения

Node

### 19.5.8 ExecutionEnvironment (среда выполнения) [Class]

#### 19.5.8.1 Описание

Среда выполнения — узел, предоставляющий среду выполнения для конкретных видов компонентов, развёртываемых на нём в форме исполняемых артефактов.

#### 19.5.8.2 Диаграммы

Узлы

#### 19.5.8.3 Обобщения

Node

### 19.5.9 Manifestation (манифестация) [Class]

#### 19.5.9.1 Описание

Манифестация — конкретное физическое выражение одного или нескольких элементов модели артефактом.

#### 19.5.9.2 Диаграммы

Артефакты

#### 19.5.9.3 Обобщения

Abstraction

#### 19.5.9.4 Концы ассоциаций

- utilizedElement : PackageableElement [1..1]{subsets Dependency::supplier} (opposite A_utilizedElement_manifestation::manifestation) элемент модели, используемый в манифестации в артефакте.

### 19.5.10 Node (узел) [Class]

#### 19.5.10.1 Описание

Узел — вычислительный ресурс, на который могут развёртываться артефакты для выполнения. Узлы могут соединяться между собой путями связи, чтобы определять сетевые структуры.

#### 19.5.10.2 Диаграммы

Развёртывания, узлы

#### 19.5.10.3 Обобщения

Class, DeploymentTarget

#### 19.5.10.4 Специализации

Device, ExecutionEnvironment

#### 19.5.10.5 Концы ассоциаций

- ♦ nestedNode : Node [0..*]{subsets Namespace::ownedMember} (opposite A_nestedNode_node::node)

  узлы, определённые (вложенные) внутри узла.

#### 19.5.10.6 Ограничения

- **internal_structure**

  Внутренняя структура узла (если она определена) состоит только из частей типа «узел».

  ```ocl
  inv: part->forAll(oclIsKindOf(Node))
  ```
