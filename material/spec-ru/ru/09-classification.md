# 9 Классификация

> **UML 2.5.1** (formal/2017-12-05) · Раздел 9 · печатные стр. 99–166 · PDF стр. 141–208

## 9.1 Краткое описание

Классификация — важный приём организации. В этом пункте определяются понятия, относящиеся к классификации. Основное понятие — классификатор (Classifier), абстрактный метакласс, конкретные подклассы которого используются для классификации различных видов значений. Остальные метаклассы этого пункта представляют составные части классификаторов, модели того, как классификаторы создаются с помощью спецификаций экземпляра, и различные связи между всеми этими понятиями.

## 9.2 Классификаторы

### 9.2.1 Краткое описание

Классификатор представляет классификацию экземпляров по их характеристикам. Классификаторы организуются в иерархии посредством обобщений. Переопределяемые элементы могут быть переопределены в контексте иерархий обобщения.

### 9.2.3 Семантика

#### 9.2.3.1 Классификаторы

Классификатор имеет набор характеристик, некоторые из которых являются свойствами, называемыми атрибутами классификатора. Каждая из характеристик является членом классификатора (см. подпункт 7.4 «Пространства имён»).

Значения, которые классифицируются классификатором, называются экземплярами классификатора. Классификатор может быть переопределён (см. ниже).

Классификатор может владеть использованиями кооперации, которые связывают классификатор с кооперациями. Кооперации описывают аспекты этого классификатора. См. 11.7 «Кооперации». Классификатор может владеть вариантами использования. См. 18.1 «Варианты использования».

#### 9.2.3.2 Обобщение

Обобщения определяют отношения обобщения/специализации между классификаторами. Каждое обобщение связывает специфический классификатор с более общим классификатором. Для данного классификатора транзитивное замыкание его общих классификаторов часто называется его обобщениями, а транзитивное замыкание его специфических классификаторов называется его специализациями. Непосредственные обобщения также называются родителями классификатора, а если классификатор является классом — его суперклассами (см. 11.4).

ПРИМЕЧАНИЕ. Понятие родителя (отношение обобщения между классификаторами) не связано с понятием владельца (отношение композиции между экземплярами).

Экземпляр классификатора является также (косвенным) экземпляром каждого из его обобщений. Любые ограничения, применимые к экземплярам обобщений, применимы также к экземплярам классификатора.

Когда классификатор обобщается, некоторые члены его обобщений наследуются, то есть ведут себя так, как если бы были определены в самом наследующем классификаторе. Например, унаследованный член, являющийся атрибутом, может иметь значение или набор значений в любом экземпляре наследующего классификатора, а унаследованный член, являющийся операцией, может быть вызван у экземпляра наследующего классификатора.

Набор членов, которые наследуются, называется inheritedMembers. Если для конкретного вида классификатора не указано иное, inheritedMembers — это члены, не имеющие видимости private.

Соответствие типов означает, что если один тип соответствует другому, то любой экземпляр первого типа может использоваться как значение типизированного элемента, тип которого объявлен как второй тип. Классификатор является типом и соответствует самому себе и всем своим обобщениям.

Свойство isAbstract классификатора, будучи истинным, указывает, что классификатор абстрактен, то есть не имеет непосредственных экземпляров: каждый экземпляр абстрактного классификатора должен быть экземпляром одной из его специализаций.

Если один классификатор (родитель) обобщает другой (потомок), то не обязательно верно, что экземпляры потомка могут заменять экземпляры родителя при любых обстоятельствах. Например, Circle может быть определён как специализация Ellipse, и его экземпляры были бы заменяемы при любых обстоятельствах, связанных с доступом к свойствам Ellipse. Однако если бы Ellipse определял поведение растяжения, изменяющее только длину его главной оси, то объект Circle не смог бы реализовать такое поведение. Свойство isSubstitutable может использоваться для указания того, можно ли использовать специфический классификатор при любых обстоятельствах, при которых можно использовать общий классификатор.

#### 9.2.3.3 Переопределение

Любой член (являющийся видом переопределяемого элемента) обобщения специализирующего классификатора может быть переопределён вместо того, чтобы наследоваться. Переопределение выполняется для того, чтобы дополнить, ограничить или заместить переопределяемые члены в контексте экземпляров специализирующего классификатора. Когда это происходит, переопределяющий член вносит вклад в структуру или поведение специализирующего классификатора вместо переопределяемых членов; в частности, любая ссылка на переопределённый член в контексте экземпляра специализирующего классификатора должна разрешаться в переопределяющий член (отметим, что во избежание зацикливания «любая ссылка» здесь исключает саму ссылку redefinedElement).

Классификатор, из которого член может быть переопределён, называется контекстом переопределения (redefinitionContext). Хотя в метамодели redefinitionContext имеет кратность «*», в спецификации UML нет случаев, когда контекстов переопределения больше одного. Контекст переопределения определяется для каждого вида переопределяемого элемента; часто, но не всегда, это владелец члена.

Переопределяющий элемент должен быть согласован с переопределяемым элементом, но он может добавлять специфические ограничения или иные подробности, характерные для экземпляров специализирующего контекста переопределения и не противоречащие ограничениям в общем контексте.

Один переопределяющий элемент может переопределять несколько переопределяемых элементов. Кроме того, переопределяемый элемент может быть переопределён несколько раз, если только однозначно, какое определение применяется к конкретному экземпляру.

Свойство isLeaf, будучи истинным для конкретного переопределяемого элемента, указывает, что он не должен иметь переопределений.

Подробная семантика переопределения различается для каждой специализации переопределяемого элемента. Существуют различные виды совместимости между переопределённым элементом и переопределяющим элементом, например совместимость имён (переопределяющий элемент имеет то же имя, что и переопределённый), структурная совместимость (свойства переопределённого элемента, видимые клиенту, являются также свойствами переопределяющего элемента) или поведенческая совместимость (переопределяющий элемент заменяем для переопределённого элемента). Любой вид совместимости влечёт ограничение на переопределения.

Классификатор сам является переопределяемым элементом. Это может проявляться, когда классификатор вложен в класс или интерфейс, который становится контекстом переопределения. Переопределение классификатора в контексте специализирующего класса или интерфейса приводит к тому, что любые ссылки на переопределённый классификатор из экземпляра специализирующего класса или интерфейса разрешаются в переопределяющий классификатор.

#### 9.2.3.4 Подстановка

Подстановка (Substitution) — это связь между двумя классификаторами, означающая, что подставляющий классификатор соблюдает контракт, заданный классификатором-контрактом. Это подразумевает, что экземпляры подставляющего классификатора заменяемы во время выполнения там, где ожидаются экземпляры классификатора-контракта. Зависимость подстановки обозначает заменяемость во время выполнения, не основанную на специализации. Подстановка, в отличие от специализации, не подразумевает наследования структуры, а лишь соблюдение открыто доступных контрактов. Она требует, чтобы:

- интерфейсы, реализуемые классификатором-контрактом, реализовались также подставляющим классификатором, либо подставляющий классификатор реализовал более специализированный тип интерфейса;

- любой порт, принадлежащий классификатору-контракту, имел соответствующий порт (см. 11.3.3), принадлежащий подставляющему классификатору.

### 9.2.4 Нотация

#### 9.2.4.1 Классификаторы

Классификатор — абстрактный метакласс. Тем не менее удобно в одном месте определить нотацию по умолчанию, доступную для любого конкретного подкласса классификатора. Некоторые специализации классификатора имеют собственную особую нотацию.

Нотация по умолчанию для классификатора — прямоугольник со сплошным контуром, содержащий имя классификатора, с разделами, отделёнными горизонтальными линиями под именем. Имя классификатора следует центрировать полужирным шрифтом. Для тех языков, в которых различаются прописные и строчные буквы, имена классификаторов следует начинать с прописной буквы.

Если для классификатора используется нотация по умолчанию, ключевое слово, соответствующее метаклассу классификатора, должно показываться в кавычках-ёлочках над именем. Ключевые слова для каждого метакласса перечислены в Приложении C и указаны в нотации каждого подкласса классификатора. Для указания того, что метакласс — Class, ключевое слово не требуется.

Любые ключевые слова (включая имена стереотипов) также следует центрировать обычным шрифтом в кавычках-ёлочках над именем классификатора. Если к одному и тому же элементу модели применяется несколько ключевых слов и/или имён стереотипов, каждое может быть заключено в отдельную пару кавычек-ёлочек и перечислено одно за другим. Либо все они могут находиться между одной парой кавычек-ёлочек, разделённые запятыми.

Имя абстрактного классификатора показывается курсивом, если это позволяет используемый шрифт. Либо, дополнительно или вместо этого, абстрактный классификатор может показываться с текстовой аннотацией {abstract} после или под его именем.

Некоторые разделы в фигурах классификатора обязательны и должны поддерживаться инструментами, которые обеспечивают соответствие конкретному синтаксису. Другие необязательны, в том смысле, что соответствующий инструмент может их не поддерживать.

Любой раздел может быть скрыт. Для скрытого раздела разделительная линия не рисуется. Если раздел скрыт, нельзя делать никаких выводов о наличии или отсутствии в нём элементов.

Раздел с именем “attributes” содержит нотацию свойств, достигаемых через свойство attribute. Раздел атрибутов обязателен и всегда располагается над другими разделами, если он не скрыт.

Раздел с именем “operations” содержит нотацию операций. Раздел операций обязателен и всегда располагается под разделом атрибутов, если он не скрыт. Раздел операций используется для классификаторов, владеющих операциями, включая Class (см. 11.4), DataType (см. 10.2) и Interface (см. 10.4).

Раздел с именем “receptions” содержит нотацию приёмов. Раздел приёмов обязателен и всегда располагается под разделом операций, если он не скрыт. Раздел приёмов используется для классификаторов, владеющих приёмами, включая Class (см. 11.4).

Любой раздел, содержащий нотацию характеристик, может показывать эти характеристики сгруппированными под литералами public, private и protected, представляющими их видимость. Литералы видимости выравниваются по левому краю в разделе, а нотация характеристик показывается с отступом под ними. Группы могут следовать в любом порядке. Группировка по видимости необязательна: соответствующий инструмент может её не поддерживать.

Соответствующий инструмент может предоставлять возможность скрывать отдельные характеристики в разделе, содержащем нотацию характеристик.

Соответствующий инструмент может по выбору поддерживать именование разделов. Имя раздела может показываться для устранения неоднозначности или может быть скрыто. Имена разделов следует центрировать и начинать со строчных букв. Имена разделов могут содержать пробелы и не должны содержать знаков препинания (включая кавычки-ёлочки). Если классификатор имеет принадлежащие ему члены, являющиеся классификаторами (включая поведения — см. 13.2), соответствующий инструмент может предоставлять возможность показывать принадлежащие классификаторы и связи между ними графически вложенными в отдельный раздел прямоугольника владеющего классификатора. Если не указано иное, имя такого раздела должно выводиться из соответствующего свойства метамодели и ставиться во множественном числе, если это свойство имеет кратность больше 1. Так, например, раздел, показывающий содержимое свойства nestedClassifier для Class (см. 11.4.2), должен называться “nested classifiers”; раздел, показывающий содержимое свойства ownedBehavior для классификатора с поведением, должен называться “owned behaviors”. Если классификатор владеет ограничениями, соответствующий инструмент может реализовать раздел, показывающий принадлежащие ограничения перечисленными в отдельном разделе прямоугольника владеющего классификатора. Имя этого необязательного раздела — “constraints”.

#### 9.2.4.2 Прочие элементы

Обобщение показывается линией с полым треугольником в качестве наконечника между символами участвующих классификаторов. Наконечник указывает на символ, представляющий общий классификатор. Несколько отношений обобщения, ссылающихся на один и тот же общий классификатор, могут показываться отдельными линиями с отдельными наконечниками. Эта нотация называется «стилем отдельных целей». Либо они могут быть присоединены к одному наконечнику в «стиле общей цели».

Общей нотации для переопределяемого элемента нет. Конкретные нотации см. в подклассах переопределяемого элемента.

Подстановка показывается как зависимость с присоединённым к ней ключевым словом «substitute».

Члены, унаследованные классификатором, могут показываться на диаграмме этого классификатора добавлением символа «крышки» ’^’ перед текстовым представлением, которое было бы показано, если бы член не наследовался. Таким образом, нотация унаследованного свойства определяется так: <inherited-property> ::= ’^’ <property>, где <property> задано в 9.5.4.

Аналогично нотация унаследованного коннектора определяется так: <inherited-connector> ::= ’^’ <connector>, где <connector> задано в 11.2.4.

Аналогичные нотации могут использоваться для всех именованных элементов, являющихся inheritedMembers классификатора, чтобы указать, что они унаследованы.

Унаследованные члены могут также показываться более светлым цветом, чтобы помочь отличить их от неунаследованных членов. Соответствующая реализация не обязана предоставлять эту возможность.

### 9.3.3 Семантика

#### 9.3.3.1 Шаблонные и связанные классификаторы

Значения терминов «шаблон» и «связанный элемент» определены в 7.3 «Шаблоны».

Классификатор, параметризованный с помощью переопределяемой сигнатуры шаблона, называется шаблонным классификатором, а классификатор с одним или несколькими связываниями шаблона — связанным классификатором.

Общая семантика шаблонов определена в подпункте 7.3.3. Там подробности того, как содержимое объединяется в связанный элемент, оставлены открытыми. В случае классификатора семантика эквивалентна вставке анонимного общего связанного классификатора, представляющего промежуточный результат для каждого связывания, и специализации всех этих промежуточных результатов связанным классификатором.

Члены развёрнутого связанного классификатора могут использоваться как фактические параметры в связывании.

Связанный классификатор может иметь содержимое в дополнение к тому, что получается в результате его связываний.

Параметры шаблонного классификатора могут быть любого вида параметра шаблона. Семантика и нотация определены только тогда, когда параметр является классификатором, литеральной спецификацией, свойством или операцией.

Когда параметр является классификатором, представленным параметром шаблона классификатора, семантика и нотация определены в этом пункте.

Когда параметр является литеральной спецификацией, семантика и нотация соответствуют указанным в 7.3.

Когда параметр является операцией, семантика и нотация соответствуют указанным в 9.6.

Когда параметр является свойством, семантика и нотация соответствуют указанным в 9.5.

#### 9.3.3.2 Специализация шаблонного классификатора

Переопределяемая сигнатура шаблона специализирует и сигнатуру шаблона, и переопределяемый элемент, чтобы позволить добавление новых формальных параметров шаблона в контексте специализирующего шаблонного классификатора.

Переопределяемая сигнатура шаблона переопределяет переопределяемые сигнатуры шаблона всех родительских классификаторов, являющихся шаблонами. Все формальные параметры шаблона расширяемых (переопределяемых) сигнатур включаются как формальные параметры шаблона расширяющей сигнатуры вместе с любыми параметрами шаблона, локально указанными для расширяющей сигнатуры.

#### 9.3.3.3 Параметры шаблона классификатора

Параметр шаблона классификатора (ClassifierTemplateParameter) — это параметр шаблона, в котором parameteredElement является классификатором в его качестве вида параметризуемого элемента.

Все подклассы классификатора (такие как класс, кооперация, компонент, тип данных, интерфейс, сигнал и варианты использования) могут быть параметризованы, связаны и использованы как параметры шаблона. То же относится к Behavior как подклассу Class и тем самым ко всем подклассам Behavior (таким как Activity, Interaction, StateMachine).

Свойство constrainingClassifier параметра шаблона классификатора задаёт набор классификаторов, которые ограничивают аргумент, допустимый для параметра. Если в этом наборе есть какие-либо классификаторы, то аргумент должен быть совместим со всеми ними в следующем смысле:

- если allowSubstitutable ложно, то совместимость означает быть тем же самым, что и все constrainingClassifiers, или их специализацией;

- если allowSubstitutable истинно, то совместимость дополнительно допускает подстановку, контрактом которой является constrainingClassifier.

Кроме того, если есть какие-либо constrainingClassifiers, parameteredElement должен быть ограничен следующим образом:

- если allowSubstitutable ложно, то совместимость означает быть тем же самым, что и все constrainingClassifiers, или их непосредственной специализацией, без дополнительных характеристик;

- если allowSubstitutable истинно, то совместимость дополнительно допускает подстановку, контрактом которой является constrainingClassifier.

Во всех случаях, если parameteredElement не абстрактен, то классификатор, используемый как аргумент, не должен быть абстрактным. Помимо этого, если свойство constrainingClassifier пусто, никаких ограничений на классификатор, который может использоваться как аргумент, нет. В этом случае parameteredElement не должен иметь обобщений и характеристик, а allowSubstitutable должно быть ложным.

### 9.3.4 Нотация

Общую нотацию отображения шаблона и связанного элемента см. в разделе о шаблонизируемом элементе.

Когда связанный классификатор используется непосредственно как тип свойства, то <template-param-name> выступает в роли типа свойства в его нотации (см. раздел о свойствах).

Общая нотация параметров шаблона, указанная в 7.3.4, расширяется для параметров шаблонного классификатора следующим образом: <template-parameter> ::= <classifier-template-parameter> | <operation-template-parameter>| <connectable- element-template-parameter>

Параметр шаблона классификатора расширяет нотацию параметра шаблона, включая необязательное ограничение типа: <classifier-template-parameter> ::= <parameter-name> [ ‘:‘ <parameter-kind> ] [‘>’ <constraint>] [‘=’ <default>] <constraint> ::= [‘{contract }’] <classifier-name>* <default> ::= <classifier-name>. Вид параметра указывает метакласс элемента parameteredElement. Его можно опустить, если это ‘Class.’

Классификатор-имя в ограничении обозначает constrainingClassifier, которых может быть ноль или более, со значением, указанным в семантике выше. Вариант ‘contract’ указывает, что allowSubstitutable истинно.

### 9.4.3 Семантика

#### 9.4.3.1 Характеристики

Каждая характеристика связана с классификатором, который называется её классификатором-носителем (featuringClassifier). Характеристика представляет некоторую структурную или поведенческую особенность своего классификатора-носителя, за исключением свойств, действующих как квалификаторы (см. 9.5.3).

Свойство isStatic определяет, относится ли особенность к экземплярам классификатора, рассматриваемым по отдельности (isStatic=false), или к самому классификатору (isStatic=true). Вся семантика, касающаяся характеристик, в которой явно не указано, является ли характеристика статической, должна считаться относящейся к нестатическим характеристикам. Там, где семантика для статических характеристик явно не указана, эти семантики не определены.

#### 9.4.3.2 Структурные характеристики

Структурная характеристика — это типизированная характеристика классификатора, задающая структуру экземпляров этого классификатора.

Структурные характеристики классификатора, являющиеся свойствами, называются атрибутами классификатора (см. 9.2.3). В UML свойство — единственный вид структурной характеристики, поэтому все структурные характеристики классификатора являются свойствами и, следовательно, атрибутами.

Для каждого экземпляра классификатора существует значение или набор значений для каждого прямого или унаследованного нестатического атрибута классификатора, а именно:

- если кратность атрибута равна 0..1, то должно быть либо ни одного значения, либо единственное значение, тип которого соответствует типу атрибута;

- если кратность атрибута равна 1..1, то должно быть единственное значение, тип которого соответствует типу атрибута;

- если кратность атрибута равна j..k, где k не равно 1, то должен быть набор значений, размер которого не меньше j и не больше k, причём тип каждого из них соответствует типу атрибута;

- если кратность атрибута равна 0..0, то не должно быть ни одного значения.

Если структурная характеристика помечена isStatic = true, то приведённые выше пункты относятся к самому классификатору, рассматриваемому как идентифицируемая особь в некоторой области выполнения, а не к отдельным экземплярам. (Обсуждение области выполнения см. в подпункте 6.3.1.)

В семантически соответствующем инструменте каждая унаследованная статическая структурная характеристика должна иметь одну из двух альтернативных семантик:

1.   В пределах области выполнения значение или набор значений структурной характеристики всегда совпадает для любого наследующего классификатора с её значением или набором значений для владеющего классификатора. Эта семантика соответствует семантике статических членов в Java и C#.

2.   В пределах области выполнения структурная характеристика имеет отдельное и независимое значение или набор значений для своего владеющего классификатора и для каждого классификатора, который её наследует. Эта семантика соответствует семантике переменных экземпляра класса в Ruby и Smalltalk.

Если структурная характеристика помечена isReadOnly = true, то она не может быть обновлена после присваивания начального значения. Наоборот, когда isReadOnly ложно (значение по умолчанию), значение может быть изменено.

#### 9.4.3.3 Поведенческие характеристики

Нестатическая поведенческая характеристика задаёт, что экземпляр её классификатора-носителя будет реагировать на вызов поведенческой характеристики выполнением определённой поведенческой реакции. Подклассы поведенческой характеристики моделируют различные поведенческие аспекты классификатора.

Список ownedParameters описывает порядок, тип и направление аргументов, которые могут быть переданы при вызове поведенческой характеристики или которые выводятся и возвращаются при завершении вызова.

Параметры ownedParameters с направлением in или inout определяют аргументы, которые должны быть предоставлены при вызове поведенческой характеристики. Параметры ownedParameters с направлением out, inout или return определяют аргументы, которые будут выведены и возвращены при успешном вызове.

Поведенческая характеристика может возбуждать исключение во время своего вызова. Возможные типы исключений могут быть указаны путём присоединения их к поведенческой характеристике с помощью ассоциации raisedException.

Один из способов определить поведенческую реакцию поведенческой характеристики — задать одно или несколько поведений в качестве методов, реализующих эту поведенческую характеристику. Тогда вызов поведенческой характеристики приводит к выполнению одного из связанных методов (как далее обсуждается в подпункте 13.2 о поведениях). Свойство isAbstract, будучи истинным, указывает, что поведенческая характеристика не имеет реализующих её методов, при том что реализация будет предоставлена более специфическим элементом.

Свойство concurrency задаёт семантику параллельных вызовов одного и того же экземпляра. Его тип — CallConcurrencyKind, перечисление со следующими литералами:

sequential     С поведенческой характеристикой не связан никакой механизм управления конкурентностью, поэтому

конфликты параллельного доступа могут возникать. Экземплярам, вызывающим поведенческую характеристику, нужно согласовывать

работу так, чтобы в любой момент времени происходил только один вызов цели по любой поведенческой характеристике.

guarded        К одному экземпляру могут поступать несколько вызовов поведенческой характеристики, перекрывающихся

по времени, но начаться разрешено только одному. Остальные блокируются, пока выполнение текущей

поведенческой характеристики не завершится. Проектировщик системы отвечает за то, чтобы взаимные блокировки

не возникали из-за одновременной блокировки.

concurrent     К одному экземпляру могут поступать несколько вызовов поведенческой характеристики, перекрывающихся

по времени, и все они могут выполняться параллельно.

#### 9.4.3.4 Параметры

Параметр — это спецификация аргумента, используемого для передачи информации внутрь или наружу при вызове поведенческой характеристики. Тип и кратность параметра ограничивают, какие значения могут быть переданы, сколько их и упорядочены ли они. Кратность определяет нижнюю и верхнюю границы значений, передаваемых параметру во время выполнения. Нижняя граница, равная нулю, означает, что параметр необязателен. Действия, использующие параметр, могут выполняться, не имея значения для необязательных параметров. Нижняя граница больше нуля означает, что значения для параметра должны поступить когда-либо во время выполнения действия.

Если для параметра указано defaultValue, то оно вычисляется в момент вызова и используется как аргумент этого параметра тогда и только тогда, когда при вызове поведенческой характеристики аргумент не предоставлен.

Параметру может быть дано имя, которое затем однозначно идентифицирует параметр среди параметров той же поведенческой характеристики. Если параметр не назван, он различается только своим положением в упорядоченном списке параметров.

Свойство direction задаёт, передаётся ли значение внутрь владеющей поведенческой характеристики, наружу из неё или и туда, и оттуда. Его тип — ParameterDirectionKind, перечисление со следующими значениями литералов:

in            Указывает, что значения параметра передаются вызывающей стороной. inout         Указывает, что значения параметра передаются вызывающей стороной и (возможно, другие) значения передаются

наружу вызывающей стороне. out           Указывает, что значения параметра передаются наружу вызывающей стороне. return        Указывает, что значения параметра передаются обратно вызывающей стороне как возвращаемые значения.

Не более одного параметра поведенческой характеристики может быть помечено как возвращаемый путём установки его направления в return.

Свойство effect может использоваться для указания того, что происходит с объектами, передаваемыми внутрь или наружу через параметр. Оно не применяется к параметрам, типизированным типами данных, поскольку у них нет идентичности, по которой можно было бы обнаруживать изменения. Это объявление намерения моделировщика, которое должно быть согласовано с поведениями, имеющими этот эффект. Во время выполнения могут происходить несколько эффектов, указан ли эффект или нет. Например, эффект update не исключает чтения во время выполнения, а отсутствие значения у effect не препятствует возникновению эффектов во время выполнения. Эффект задаётся перечислимым значением с типом ParameterEffectKind — перечисления со следующими литералами:

create       Объекты, передаваемые наружу при выполнениях поведения как значения параметра, не существуют до начала

этих выполнений.

read         У объектов, являющихся значениями параметра, во время выполнений поведения извлекаются значения их свойств,

или связи, в которых они участвуют, или их классификаторы.

update       У объектов, являющихся значениями параметра, во время выполнений поведения изменяются значения их свойств,

или связи, в которых они участвуют, или их классификация.

delete       Объекты, являющиеся значениями параметра, не существуют после завершения выполнений поведения.

Только параметры in и inout могут иметь эффект delete. Только параметры out, inout и return могут иметь эффект create.

Свойство isException применяется к выходным параметрам. Выход, переданный параметру с isException = true во время вызова поведенческой характеристики, исключает передачу выходов любым другим выходам этой поведенческой характеристики во время того же вызова. Тип такого параметра исключения может быть включён в набор raisedException, но не обязан включаться.

Свойство isStream, будучи истинным, обозначает потоковый параметр. Потоковый параметр выражает ожидание того, что любое поведение, реализующее эту характеристику, будет проявлять потоковое поведение в отношении этого параметра — см. подпункт 13.2. Семантика параметра, обозначенного как потоковый, когда реализующее поведение не проявляет потокового поведения, не определена.

Набор параметров (ParameterSet), принадлежащий поведенческой характеристике, — это элемент, который предоставляет альтернативные наборы входов или выходов, которые могут использовать поведения, реализующие эту поведенческую характеристику. Параметры в наборе параметров должны быть все входами или все выходами одной и той же поведенческой характеристики: набор параметров, состоящий целиком из входов, называется входным набором параметров, а состоящий целиком из выходов — выходным набором параметров.

Поведенческая характеристика с входными наборами параметров может принимать за один вызов входы только от параметров одного из наборов. Поведенческая характеристика с выходными наборами параметров может возвращать за один вызов выходы только параметрам одного из наборов. Семантика условий на входных и выходных наборах параметров поведенческих характеристик совпадает, соответственно, с семантикой предусловий и постусловий операций, но применяется только к вызовам, которые принимают входы от параметров набора параметров, имеющего это условие, или возвращают им выходы.

Более подробную семантику и примеры наборов параметров можно найти в подпункте 16.3.

### 9.4.4 Нотация

Общей нотации для характеристики нет. Подклассы определяют собственную нотацию. Статические характеристики подчёркиваются.

Когда характеристики показываются в списках, многоточие (...) в качестве последнего элемента списка характеристик может использоваться для указания того, что существуют дополнительные характеристики, но в этом списке они не показаны.

Структурная характеристика, доступная только для чтения, показывается с использованием {readOnly} как части нотации этой структурной характеристики. Эта аннотация может быть скрыта, и в этом случае определить её значение по диаграмме невозможно. Либо соответствующий инструмент может разрешать скрытие аннотации {readOnly} только тогда, когда isReadOnly=false (значение по умолчанию). В этом случае можно предполагать это значение во всех случаях, когда {readOnly} не показано.

Переопределения характеристик могут быть либо явно обозначены с помощью строки свойств {redefines <x>} у характеристики, либо неявно — наличием характеристики, которую нельзя отличить с помощью isDistinguishableFrom() от другой характеристики в одном из более общих классификаторов владеющего классификатора. В обоих случаях переопределённая характеристика должна соответствовать ограничению совместимости на переопределения. Параметр показывается как текстовая строка вида: <parameter> ::= [<direction>] <parameter-name> ’:’ <type-expression> [’[’<multiplicity-range>’]’] [’=’ <default>]

[’{’ <parm-property> [’,’ <parm-property>]* ’}’], где:

- <direction> ::= ’in’ | ’out’ | ’inout’ (по умолчанию ’in’, если опущено).

- <parameter-name> — имя параметра.

- <type-expression> — выражение, задающее тип параметра.

- <multiplicity-range> — кратность параметра. (См. элемент кратности — подпункт 7.5.)

- <default> — выражение, определяющее спецификацию значения по умолчанию для параметра.

- <parm-property> обозначает дополнительные значения свойств, применимые к параметру.

<parm-property> ::= ’ordered’ | ’unordered’ | ’unique’ | ’nonunique’ | ’seq’ | ’sequence’, где

- ’ordered’ применяется, когда параметр многозначный, и означает, что его значения упорядочены;

- ’unordered’ применяется, когда параметр многозначный, и означает, что его значения не упорядочены;

- ’unique’ применяется, когда параметр многозначный, и означает, что его значения не имеют дубликатов;

- ’nonunique’ применяется, когда параметр многозначный, и означает, что его значения могут иметь дубликаты;

- ’seq’ или ’sequence’ применяется, когда параметр многозначный, и означает, что его значения составляют упорядоченный набор-мешок, то есть isUnique = false и isOrdered = true.

Нотацию наборов параметров на диаграммах деятельности можно найти в подпункте 16.3.4. На других диаграммах нотации для наборов параметров нет.

### 9.5.3 Семантика

Свойство может представлять атрибут классификатора, конец-член ассоциации или в некоторых случаях и то и другое одновременно.

Полезное соглашение для общих сценариев моделирования состоит в том, что свойство, тип которого является видом класса, — это конец ассоциации, а свойство, тип которого является видом типа данных, — нет. Это соглашение не навязывается UML.

Свойство представляет объявленное состояние одного или нескольких экземпляров в терминах именованной связи со значением или значениями. Когда свойство является нестатическим атрибутом классификатора, значение или значения связываются с экземпляром классификатора тем, что хранятся в слотах экземпляра. Когда свойство является концом-членом ассоциации, значение или значения связываются с экземпляром или экземплярами на другом конце (концах) ассоциации (см. 11.5 «Ассоциации»). Когда свойство является статическим атрибутом классификатора, значение или значения связываются с самим классификатором в пределах некоторой области выполнения.

Свойство, являющееся концом-членом, само может иметь другие свойства, служащие квалификаторами.

Когда свойством владеет классификатор, не являющийся ассоциацией, через ownedAttribute, то оно представляет атрибут классификатора. Когда оно связано с ассоциацией через memberEnd, оно представляет конец ассоциации. Для бинарной ассоциации оно может быть и тем и другим одновременно. В любом случае при создании свойство представляет значение или набор значений, связанных с экземпляром одного классификатора (или, в случае тернарной ассоциации или ассоциации более высокого порядка, более чем одного). Этот набор классификаторов называется контекстом свойства: в случае атрибута контекст — это владеющий классификатор, а в случае конца ассоциации контекст — это набор классификаторов на другом конце или концах ассоциации.

Если для свойства указано defaultValue, это значение по умолчанию вычисляется при создании экземпляра свойства при отсутствии конкретной установки для свойства или ограничения в модели, требующего, чтобы свойство имело конкретное значение. Вычисленное значение по умолчанию затем становится начальным значением (значениями) свойства.

Если свойство имеет isDerived = true, оно производное, и его значение или значения могут вычисляться из другой информации. Действия, включающие производное свойство, ведут себя так же, как для непроизводного свойства. Производные свойства часто задаются доступными только для чтения (то есть клиенты не могут напрямую изменять значения). Но если производное свойство изменяемо, предполагается, что реализация вносит соответствующие изменения в модель, чтобы были выполнены все ограничения, в частности ограничение вывода для производного свойства. Вывод для производного свойства может быть задан ограничением.

Свойство косвенно является видом переопределяемого элемента, поэтому свойства могут быть переопределены. Имя и видимость свойства не обязаны совпадать с именем и видимостью любого свойства, которое оно переопределяет.

Производное свойство может переопределять непроизводное. Реализация должна обеспечивать соблюдение ограничений, подразумеваемых выводом, если свойство обновляется.

Если у свойства указано значение по умолчанию и это свойство переопределяет другое свойство с указанным значением по умолчанию, то используется значение по умолчанию переопределяющего свойства вместо более общего значения по умолчанию из переопределённого свойства.

Иногда свойство используется для моделирования обстоятельств, в которых один экземпляр используется для объединения набора экземпляров; это называется агрегацией. Чтобы представить такие обстоятельства, свойство имеет свойство aggregation типа AggregationKind; экземпляр, представляющий всю группу, классифицируется владельцем свойства, а экземпляры, представляющие сгруппированных индивидов, классифицируются типом свойства. AggregationKind — перечисление со следующими значениями литералов:

none          Указывает, что свойство не имеет семантики агрегации.

shared        Указывает, что свойство имеет семантику разделяемой агрегации. Точная семантика разделяемой агрегации

зависит от прикладной области и моделировщика.

composite     Указывает, что свойство агрегировано композитно, то есть составной объект отвечает за

существование и хранение составных объектов (см. определение частей в 11.2.3).

Композитная агрегация — сильная форма агрегации, требующая, чтобы объект-часть входил не более чем в один составной объект одновременно. Если составной объект удаляется, все его экземпляры-части, являющиеся объектами, удаляются вместе с ним.

ПРИМЕЧАНИЕ. Объект-часть может (если это вообще допускается) быть удалён из составного объекта до того, как составной объект будет удалён, и, таким образом, не удаляться как часть составного объекта.

Композиции могут быть связаны в направленный ациклический граф с транзитивными характеристиками удаления; то есть удаление объекта в одной части графа приведёт также к удалению всех объектов подграфа ниже этого объекта. Точная семантика жизненного цикла композитной агрегации намеренно не определена. Порядок и способ создания составных объектов намеренно не определены. Семантика композитной агрегации, когда контейнер или часть типизированы типом данных, намеренно не определена.

Свойство может быть помечено как подмножество другого subsettedProperty. В этом случае вычисляется множество путём устранения дубликатов из набора значений, обозначаемого подмножеством свойства в некотором контексте. Затем это множество должно быть включено в (или совпадать с) множество, вычисленное путём устранения дубликатов из набора значений, обозначаемого subsettedProperty в том же контексте.

Свойство может быть помечено как производное объединение установкой isDerivedUnion в true. Это означает, что набор значений, обозначаемый свойством в некотором контексте, является производным как строгое объединение всех значений, обозначаемых в том же контексте свойствами, определёнными как его подмножества. Если свойство имеет верхнюю границу кратности 1, это означает, что значения всех подмножеств должны быть нулевыми или одинаковыми.

Когда атрибут, помеченный как производное объединение, помечен isOrdered = true, и в конкретном контексте все его свойства-подмножества являются атрибутами, помеченными как упорядоченные или с верхней границей 1, и значение в этом контексте операции Classifier::allAttributes() даёт корректно определённый порядок, то порядок объединения определяется вычислением свойств-подмножеств в том порядке, в котором они появляются в результате allAttributes(), и объединением результатов. Во всех остальных случаях порядок свойства, помеченного как упорядоченное производное объединение, не определён.

Свойство может быть помечено через свойство isID как (часть) идентификатора (если таковой есть) для классификаторов, членом которых оно является. Интерпретация этого оставлена открытой, но это может отображаться на такие реализации, как первичные ключи таблиц реляционных баз данных или атрибуты ID в XML. Если несколько свойств помечены как isID (возможно, в обобщающих классификаторах), то именно сочетание пар (свойство, значение) логически обеспечивает уникальность для любого экземпляра. Следовательно, нет нужды в указании порядка, и возможно, что некоторые значения свойств будут пустыми. Если свойство многозначное, включаются все значения.

Свойство специализирует параметризуемый элемент, чтобы указать, что свойство может быть представлено как формальный параметр шаблона присоединяемого элемента (см. 11.2.3) и предоставлено как фактический параметр в связывании шаблона. Внутри шаблона параметр шаблона-свойство может использоваться как любое другое доступное свойство. Любые ссылки на параметр шаблона-свойство внутри шаблона окажутся ссылками на фактическое свойство в связанном элементе.

### 9.5.4 Нотация

Для свойств определена следующая общая нотация.

ПРИМЕЧАНИЕ. Некоторые специализации свойства могут также иметь дополнительные формы нотации. Они рассматриваются в соответствующих подпунктах «Нотация» этих классов. <property> ::= [<visibility>] [‘/’] <name> [‘:’ <prop-type>] [‘[‘ <multiplicity-range> ‘]’] [‘=’ <default>] [‘{‘ <prop-modifier > [‘,’ <prop-modifier >]* ’}’], где:

- <visibility> — видимость свойства. (См. VisibilityKind — подпункт 7.4.) <visibility> ::= ‘+’ | ‘-‘ | ‘#’ | ‘~’

- ‘/’ означает, что свойство производное.

- <name> — имя свойства или пустая строка, если свойство не имеет имени.

- <prop-type> — имя классификатора, являющегося типом свойства.

- <multiplicity-range> — диапазон кратности свойства. Если этот член опущен, подразумевается кратность 1 (ровно одна). (См. элемент кратности — подпункт 7.5.)

- <default> — выражение, вычисляемое в значение или значения свойства по умолчанию.

- <prop-modifier> обозначает модификатор, применимый к свойству. <prop-modifier> ::= ‘readOnly’ | ‘union’ | ‘subsets’ <property-name> | ‘redefines’ <property-name> | ‘ordered’ | ‘unordered’ | ‘unique’ | ‘nonunique’ | ‘seq’ | ‘sequence’ | ‘id’ | <prop-constraint>, где:

- ‘readOnly’ означает, что свойство доступно только для чтения;

- ‘union’ означает, что свойство является производным объединением своих подмножеств;

- ‘subsets’ <property-name> означает, что свойство является собственным подмножеством свойства, идентифицируемого <property-name>, причём <property-name> может быть полным;

- ‘redefines’ <property-name> означает, что свойство переопределяет унаследованное свойство, идентифицируемое <property-name>, причём <property-name> может быть полным;

- ‘ordered’ означает, что свойство упорядочено, то есть isOrdered = true;

- ‘unordered’ означает, что свойство не упорядочено, то есть isOrdered = false;

- ‘unique’ означает, что в многозначном свойстве нет дубликатов, то есть isUnique = true;

- ‘nonunique’ означает, что в многозначном свойстве могут быть дубликаты, то есть isUnique = false;

- ‘seq’ или ‘sequence’ означает, что свойство представляет упорядоченный мешок, то есть isUnique = false и isOrdered = true;

- ‘id’ означает, что свойство является частью идентификатора класса;

- <prop-constraint> — выражение, задающее ограничение, применимое к свойству.

Нотация квалификаторов определена в 11.5 «Ассоциации».

Нотация агрегации свойства определена в 11.5 «Ассоциации».

В классификаторе тип, видимость, значение по умолчанию, кратность и строку свойств можно не показывать, даже если в модели есть значения.

В классификаторе отдельные свойства атрибута могут показываться в столбцах, а не в виде непрерывной строки.

### 9.6.3 Семантика

#### 9.6.3.1 Операции

Операция — это поведенческая характеристика интерфейса, типа данных или класса. Операция может быть вызвана непосредственно у экземпляров её классификаторов-носителей. Операция задаёт имя, тип, параметры и ограничения для таких вызовов.

Если есть возвращаемый параметр, тип операции совпадает с типом этого параметра. Иначе операция не имеет типа.

Предусловия операции определяют условия, которые должны быть истинны при вызове операции. Эти предусловия могут предполагаться реализацией данной операции. Поведение вызова операции при невыполненном предусловии в UML не определено.

Постусловия операции определяют условия, которые будут истинны при успешном завершении вызова операции, при условии что предусловия были выполнены. Эти постусловия должны выполняться любой реализацией операции.

Условие тела (bodyCondition) операции ограничивает возвращаемый результат значением, вычисленным по спецификации bodyCondition. Это значение должно удовлетворять постусловиям, если таковые есть. bodyCondition отличается от постусловий тем, что bodyCondition может быть переопределено при переопределении операции, тогда как постусловия могут только добавляться при переопределении.

Операция может возбуждать исключение во время своего вызова. Когда исключение возбуждено, не следует предполагать, что постусловия или bodyCondition операции выполнены.

Операция может быть переопределена в специализации классификатора-носителя. Такое переопределение может добавлять новые предусловия или постусловия, добавлять новые raisedExceptions или иным образом уточнять спецификацию операции.

Различные системы соответствия типов применяют различные схемы того, как типы параметров и результатов могут изменяться при переопределении операции в специализации. Когда тип не может изменяться, это называется инвариантностью. Когда тип параметра может быть специализирован в специализированном типе, это называется ковариантностью. Когда тип параметра может быть обобщён в специализированном типе, это называется контравариантностью. В UML такие правила соответствия типов намеренно не заданы. Переопределённые параметры должны иметь совместимую кратность и то же направление, порядок и уникальность, что и переопределяемые параметры.

Если свойство isQuery истинно, вызов операции не должен изменять состояние экземпляра или любого другого элемента модели.

Операция может принадлежать классу, типу данных или интерфейсу, предоставляющему контекст для её возможного переопределения, и находиться в его пространстве имён. Владеющий классификатор операции предоставляет её контекст переопределения.

#### 9.6.3.2 Шаблонные операции

Операция специализирует шаблонизируемый элемент, чтобы поддерживать спецификацию шаблонных и связанных операций. Связанные операции должны принадлежать классификатору. Если исходная операция была определена с поведением, то связанный элемент должен принадлежать классификатору, согласованному с этим поведением. Это означает одно из трёх: (a) связанная операция появляется в том же классификаторе, что и шаблон; (b) связанная операция появляется в подтипе владельца шаблона; (c) шаблон был определён без побочных эффектов в статическом классе, и тогда связанная операция может появиться где угодно.

#### 9.6.3.3 Параметры шаблона операции

Операция может быть представлена шаблоном как формальный параметр шаблона через параметр шаблона операции (OperationTemplateParameter). Параметр шаблона операции — это вид параметра шаблона, в котором параметризуемым элементом является операция. Внутри шаблонного классификатора параметр шаблона операции может использоваться как любая другая доступная операция. Любые ссылки на параметр шаблона операции внутри шаблона окажутся ссылками на фактическую операцию в связанном классификаторе. Например, вызов параметра шаблона операции будет вызовом фактической операции.

Значение по умолчанию для параметра шаблона операции должно быть операцией с теми же типами параметров, направлениями и кратностями, что и у представляемой операции.

### 9.6.4 Нотация

Если операция показывается на диаграмме, она показывается как текстовая строка вида: [<visibility>] <name> ‘(‘ [<parameter-list>] ‘)’ [‘:’ [<return-type>] [‘[‘ <multiplicity-range> ‘]’]

[‘{‘ <oper-property> [‘,’ <oper-property>]* ‘}’]]

где:

- <visibility> — видимость операции (см. 7.4). <visibility> ::= ‘+’ | ‘-‘ | ‘#’ | ‘~’

- <name> — имя операции.

- <parameter-list> — список параметров операции в следующем формате: <parameter-list> ::= <parameter> [‘,’<parameter>]*

где <parameter> определено в 9.4.4.

- <return-type> — тип возвращаемого параметра, если операция его имеет.

- <multiplicity-range> — кратность возвращаемого типа (см. 7.5).

- <oper-property> указывает свойства операции. <oper-property> ::= ‘redefines’ <oper-name> | ‘query’ | ‘ordered’ | ‘unordered’ | ‘unique’ | ‘nonunique’ | ‘seq’ | ‘sequence’ | <oper-constraint>

где:

- ‘redefines’ <oper-name> означает, что операция переопределяет унаследованную операцию, идентифицируемую <oper-name>, причём <oper-name> может быть полным;

- ‘query’ означает, что операция не изменяет состояние системы;

- ‘ordered’ применяется, когда возвращаемый параметр многозначный, и означает, что его значения упорядочены;

- ‘unordered’ применяется, когда возвращаемый параметр многозначный, и означает, что его значения не упорядочены;

- ‘unique’ применяется, когда возвращаемый параметр многозначный, и означает, что его значения не имеют дубликатов;

- ‘nonunique’ применяется, когда возвращаемый параметр многозначный, и означает, что его значения могут иметь дубликаты;

- ‘seq’ или ‘sequence’ применяется, когда возвращаемый параметр многозначный, и означает, что его значения составляют упорядоченный мешок, то есть isUnique = false и isOrdered = true;

- <oper-constraint> — ограничение, применимое к операции. Список параметров может быть скрыт.

Параметры шаблона шаблонной операции находятся в списке между именем операции и параметрами операции. [<visibility>] <name> ‘<‘ <template-parameter-list> ‘>’ ‘(‘ [<parameter-list>] ‘)’ [‘:’ [<return-type>] [‘[‘ <multiplicity> ‘]’] [‘{‘ <oper-property> [‘,’ <oper-property>]* ‘}’]]

Связывания параметров шаблона связанной шаблонной операции находятся в списке между именем операции и параметрами операции. [<visibility>] <name> ‘<<‘ <binding-expression-list> ‘>>’ ‘(‘ [<parameter-list>] ‘)’ [‘:’ [<return-type>] [‘[‘ <multiplicity> ‘]’] [‘{‘ <oper-property> [‘,’ <oper-property>]* ‘}’]]

где < binding-expression-list> ::= <binding-expression> [‘,’ <binding-expression>]*, а <binding-expression> определено в 7.3.4.

В нотации формальных параметров шаблона и связываний параметров шаблона операция показывается как <operation-name> ‘(‘<parameter-list> ‘)’.

Параметр шаблона операции расширяет нотацию параметра шаблона, включая параметры операции:

<operation-template-parameter> ::= <parameter> [ ‘: Operation’] [‘=’ <default>] <parameter> ::= <operation-name> ‘(‘<parameter-list> ‘)’ <default> ::= <operation-name ‘(‘<parameter-list> ‘)’

Нотация на диаграммах классов для исключений и потоковых параметров операций содержит ключевые слова “exception” или “stream” в строке свойств.

## 9.7 Наборы обобщений

### 9.7.1 Краткое описание

Набор обобщений (GeneralizationSet) даёт способ группировать обобщения в ортогональные измерения. Набор обобщений может быть связан с классификатором, называемым его мощным типом (powertype). Эти приёмы дают дополнительную выразительную силу для организации иерархий классификации.

### 9.7.2 Абстрактный синтаксис

```text
                                                     PackageableElement
               + powertype   + powertypeExtent        GeneralizationSet       + generalizationSet   + generalization
  Classifier                                         + isCovering : Boolean                                            Generalization
               0..1                              *   + isDisjoint : Boolean   *                                   *
Figure 9.14 Generalization Sets
```

### 9.7.3 Семантика

Обобщения могут группироваться для представления ортогональных измерений обобщения. Каждая группа представлена набором обобщений. Свойство generalizationSet обозначает наборы обобщений, которым принадлежит данное обобщение. Все обобщения в конкретном наборе обобщений должны иметь один и тот же общий классификатор. Свойство isCovering набора обобщений задаёт, являются ли специфические классификаторы обобщений этого набора полными в следующем смысле: если isCovering истинно, то каждый экземпляр общего классификатора является экземпляром (по меньшей мере) одного из специфических классификаторов. Свойство isDisjoint задаёт, могут ли специфические классификаторы обобщений этого набора пересекаться в следующем смысле: если isDisjoint истинно, то никакой экземпляр любого из специфических классификаторов не может быть также экземпляром любого другого из специфических классификаторов. По умолчанию оба свойства ложны.

Набор обобщений может по выбору быть связан с классификатором, называемым его мощным типом. Это означает, что для каждого обобщения в наборе обобщений специализирующий классификатор однозначно связан с экземпляром мощного типа, то есть существует взаимно однозначное соответствие между экземплярами мощного типа и специализациями в наборе обобщений, так что экземпляры мощного типа и соответствующие классификаторы могут рассматриваться как семантически эквивалентные. Как реализуется эта семантическая эквивалентность и как поддерживается её целостность, в рамках UML не определено.

### 9.7.4 Нотация

Когда линии отношений обобщения именованы, это имя обозначает набор обобщений, которому принадлежит данное обобщение. Все отношения обобщения с одним и тем же именем набора обобщений являются частью одного и того же набора обобщений. Эта форма нотации изображена на рисунке 9.15.

### 9.8.3 Семантика

Спецификация экземпляра представляет возможное или фактическое существование экземпляров в моделируемой системе и полностью или частично описывает эти экземпляры.

Слот задаёт, что экземпляр, моделируемый спецификацией экземпляра, имеет значение или значения для конкретной структурной характеристики, которая должна быть структурной характеристикой, связанной с классификатором спецификации экземпляра, владеющей слотом, — как прямой атрибут, унаследованный атрибут, закрытый атрибут в обобщении или конец-член, если классификатор является ассоциацией, но за исключением переопределённых структурных характеристик. Значения в слоте должны соответствовать определяющей структурной характеристике слота (по типу, кратности и т. д.). Значения в слоте задаются с помощью спецификаций значения (см. раздел 8). Спецификация экземпляра может представлять:

- классификацию экземпляра одним или несколькими классификаторами, любой из которых может быть абстрактным;

- вид экземпляра, исходя из его классификаторов. Например, спецификация экземпляра, классификатором которой является класс, описывает экземпляр этого класса, тогда как спецификация экземпляра, классификатором которой является ассоциация, описывает связь этой ассоциации. Если классификаторы не заданы, то спецификация экземпляра не ограничивает вид представляемого экземпляра. Если заданы классификаторы разных видов, то семантика не определена;

- спецификацию значений структурных характеристик экземпляра, где значения содержатся в слотах. Не все структурные характеристики всех классификаторов спецификации экземпляра должны быть представлены слотами, и в этом случае спецификация экземпляра является частичным описанием;

- необязательную спецификацию того, как вычислить, вывести или сконструировать экземпляр, задаваемую спецификацией значения. Если такая спецификация значения задана, то представляемый экземпляр равен значению, получающемуся в результате вычисления этой спецификации значения. Если спецификация экземпляра имеет один или несколько классификаторов, то тип спецификации значения должен соответствовать по меньшей мере одному из этих классификаторов.

Спецификация экземпляра может задавать фактическое существование экземпляра в моделируемой системе. Либо спецификация экземпляра может давать иллюстрацию или пример возможного экземпляра в моделируемой системе. Назначение спецификации экземпляра — показать то, что представляет интерес в отношении экземпляра. Экземпляр соответствует каждому классификатору спецификации экземпляра и имеет свойства со значениями, указанными каждым слотом спецификации экземпляра. Отсутствие в спецификации экземпляра слота для некоторых свойств не означает, что представляемый экземпляр не имеет этого свойства, а лишь то, что это свойство не представляет интереса в модели. Аналогично фактический экземпляр мог бы соответствовать специализации моделируемого классификатора спецификации экземпляра, но этот факт может не представлять интереса в модели.

Спецификация экземпляра может представлять экземпляр в некоторый момент времени (снимок состояния). Изменения экземпляра могут моделироваться несколькими спецификациями экземпляра, по одной на каждый снимок.

Важно помнить, что спецификация экземпляра — это элемент модели, и её не следует путать с экземпляром, который она моделирует. Поскольку спецификация экземпляра может лишь частично определять свойства экземпляра, в моделируемой системе фактически может быть несколько экземпляров, удовлетворяющих требованиям спецификации экземпляра. С другой стороны, спецификация экземпляра может моделировать ситуацию, которая фактически не должна возникать в моделируемой системе, и в этом случае ни один экземпляр, отвечающий требованиям спецификации экземпляра, может никогда фактически не возникнуть в системе.

Значение экземпляра (InstanceValue) — это вид спецификации значения, значение которой задаётся спецификацией экземпляра. Каждое вычисление значения экземпляра считается дающим отдельный экземпляр, соответствующий спецификации экземпляра. Если спецификация экземпляра имеет спецификацию, то эта спецификация значения вычисляется, давая значение значения экземпляра. Иначе значение экземпляра вычисляется созданием значения, являющегося экземпляром каждого из классификаторов, указанных в спецификации экземпляра. Любые слоты в спецификации экземпляра затем предоставляют значения соответствующим структурным характеристикам экземпляра путём вычисления спецификаций значения, связанных с этими слотами. Структурная характеристика, для которой слот не задан, либо имеет значение, получаемое вычислением её defaultValue, если она является свойством с defaultValue, либо не имеет значения.

ПРИМЕЧАНИЕ. Значение экземпляра не владеет спецификацией экземпляра, на которую оно ссылается; несколько значений экземпляра могут ссылаться на одну и ту же спецификацию экземпляра.

### 9.8.4 Нотация

Спецификация экземпляра изображается нотацией, аналогичной нотации её классификаторов, но вместо имени классификатора появляется подчёркнутое объединение имени экземпляра (если оно есть), двоеточия (‘:’) и имени или имён классификаторов. Соглашение для показа нескольких классификаторов — разделять их имена запятыми.

Спецификация экземпляра, классификатором которой является ассоциация, представляет связь и показывается той же нотацией, что и ассоциация, но сплошной путь или пути соединяют спецификации экземпляра, а не классификаторы. Не обязательно показывать подчёркнутое имя там, где из её соединения со спецификациями экземпляра ясно, что она представляет связь, а не ассоциацию. Концы могут быть украшены именами концов. Стрелки навигации могут показываться, но если они показаны, они должны согласовываться с навигацией концов ассоциации.

ПРИМЕЧАНИЕ. Имена необязательны для классификаторов и спецификаций экземпляра. Отсутствие имени на диаграмме не обязательно отражает его отсутствие в лежащей в основе модели.

Стандартная нотация для анонимной спецификации экземпляра безымянного классификатора — подчёркнутое двоеточие (‘:’).

Если спецификация экземпляра имеет спецификацию значения в качестве своей спецификации, эта спецификация значения показывается либо после знака равенства (“=”), следующего за именем, либо без знака равенства под именем. Если спецификация экземпляра показывается с использованием охватывающей фигуры (например, прямоугольника), содержащей имя, спецификация значения показывается внутри охватывающей фигуры.

Слоты показываются нотацией, аналогичной нотации соответствующих структурных характеристик. Там, где структурная характеристика показывалась бы текстуально в разделе, слот для этой структурной характеристики может показываться текстуально как имя или полное имя структурной характеристики, за которым следуют знак равенства (‘=’) и спецификация значения. Другие свойства структурной характеристики, такие как её тип, могут по выбору показываться.

Значение экземпляра может появляться в текстовой или графической нотации. В текстовой, как может быть для значения слота, показывается имя спецификации экземпляра. Оно может отображаться как полное имя. В графической значение экземпляра представляется нотацией его спецификации экземпляра.

Значение слота, являющееся значением экземпляра, может также показываться графической нотацией, подобной нотации связи. Сплошной путь идёт от владеющей спецификации экземпляра к символу, представляющему значение экземпляра, которое является значением слота, а имя атрибута украшает целевой конец пути. Навигабельность, если она показана, должна быть только в направлении цели. Эта нотация может порождать визуальную неоднозначность с нотацией связи, когда единственные украшения находятся на целевом конце; в таких случаях модель следует проверить, чтобы определить наличие или отсутствие фактического экземпляра ассоциации.

Там, где спецификация экземпляра классифицирована структурированным классификатором (см. 11.2.3), она может содержать вложенные прямоугольники, представляющие экземпляры, играющие его роли. Строка имени такой вложенной спецификации экземпляра подчиняется следующему синтаксису:

{<name> [‘/’ <rolename>] | ‘/’ <rolename>} [‘:’ <classifiername> [‘,’ <classifiername>]*]

За именем спецификации экземпляра может следовать имя роли, которую играет экземпляр. Имя роли может присутствовать только тогда, когда экземпляр играет роль.

## 9.9 Описания классификаторов

### 9.9.1 AggregationKind (вид агрегации) [Enumeration]

#### 9.9.1.1 Описание

AggregationKind — это перечисление для указания вида агрегации свойства.

#### 9.9.1.2 Диаграммы

- Свойства

#### 9.9.1.3 Литералы

- **none**

  Указывает, что свойство не имеет агрегации.

- **shared**

  Указывает, что свойство имеет разделяемую агрегацию.

- **composite**

  Указывает, что свойство агрегировано композитно, то есть составной объект отвечает за существование и хранение составных объектов (частей).

### 9.9.2 BehavioralFeature (поведенческая характеристика) [Abstract Class]

#### 9.9.2.1 Описание

Поведенческая характеристика — это характеристика классификатора, задающая аспект поведения его экземпляров. Поведенческая характеристика реализуется поведением. Поведенческая характеристика задаёт, что классификатор будет отвечать на обозначенный запрос вызовом своего реализующего метода.

#### 9.9.2.2 Диаграммы

Характеристики, операции, сигналы, поведения

#### 9.9.2.3 Обобщения

Feature, Namespace

#### 9.9.2.4 Специализации

Operation, Reception

#### 9.9.2.5 Атрибуты

- concurrency : CallConcurrencyKind [1..1] = sequential

  Задаёт семантику параллельных вызовов одного и того же пассивного экземпляра (то есть экземпляра, происходящего от класса с isActive = false). Активные экземпляры управляют доступом к своим собственным поведенческим характеристикам.

- isAbstract : Boolean [1..1] = false

  Если истинно, то поведенческая характеристика не имеет реализации, и её должен предоставить более специфический классификатор. Если ложно, поведенческая характеристика должна иметь реализацию в классификаторе или должна быть унаследована.

#### 9.9.2.6 Концы ассоциаций

- method : Behavior [0..*] (opposite Behavior::specification)

  Поведение, реализующее эту поведенческую характеристику. Для конкретной пары «классификатор (как владелец поведения) — поведенческая характеристика (как спецификация поведения)» может быть не более одного поведения.

- ♦ ownedParameter : Parameter [0..*]{ordered, subsets Namespace::ownedMember} (opposite A_ownedParameter_ownerFormalParam::ownerFormalParam) упорядоченный набор формальных параметров этой поведенческой характеристики.

- ♦ ownedParameterSet : ParameterSet [0..*]{subsets Namespace::ownedMember} (opposite A_ownedParameterSet_behavioralFeature::behavioralFeature) наборы параметров, принадлежащие этой поведенческой характеристике.

- raisedException : Type [0..*] (opposite A_raisedException_behavioralFeature::behavioralFeature)

  Типы, представляющие исключения, которые могут возбуждаться при вызове этой поведенческой характеристики.

#### 9.9.2.7 Операции

- isDistinguishableFrom(n : NamedElement, ns : Namespace) : Boolean {redefines NamedElement::isDistinguishableFrom()} запрос isDistinguishableFrom() определяет, могут ли две поведенческие характеристики сосуществовать в одном пространстве имён. Он задаёт, что они должны иметь разные сигнатуры.

  ```ocl
  body: (n.oclIsKindOf(BehavioralFeature) and ns.getNamesOfMember(self)-
  >intersection(ns.getNamesOfMember(n))->notEmpty()) implies
  Set{self}->including(n.oclAsType(BehavioralFeature))->isUnique(ownedParameter->collect(p|
  Tuple { name=p.name,
  type=p.type,effect=p.effect,direction=p.direction,isException=p.isException,
  isStream=p.isStream,isOrdered=p.isOrdered,isUnique=p.isUnique,lower=p.lower,
  upper=p.upper }))
  ```

- inputParameters() : Parameter [0..*]{ordered} параметры ownedParameters с направлением in и inout.

  ```ocl
  body: ownedParameter->select(direction=ParameterDirectionKind::_'in' or
  direction=ParameterDirectionKind::inout)
  ```

- outputParameters() : Parameter [0..*]{ordered} параметры ownedParameters с направлением out, inout или return.

  ```ocl
  body: ownedParameter->select(direction=ParameterDirectionKind::out or
  direction=ParameterDirectionKind::inout or direction=ParameterDirectionKind::return)
  ```

#### 9.9.2.8 Ограничения

- **abstract_no_method**

  Когда isAbstract истинно, методов нет.

  ```ocl
  inv: isAbstract implies method->isEmpty()
  ```

### 9.9.3 CallConcurrencyKind (вид конкурентности вызовов) [Enumeration]

#### 9.9.3.1 Описание

CallConcurrencyKind — это перечисление, используемое для указания семантики параллельных вызовов поведенческой характеристики.

#### 9.9.3.2 Диаграммы

- Характеристики

#### 9.9.3.3 Литералы

- **sequential**

  С поведенческой характеристикой не связан никакой механизм управления конкурентностью, поэтому могут возникать конфликты

  параллельного доступа. Экземплярам, вызывающим поведенческую характеристику, нужно согласовывать работу так, чтобы в любой момент времени происходил только один вызов цели по любой поведенческой характеристике.

- **guarded**

  К одному экземпляру могут поступать несколько вызовов поведенческой характеристики, перекрывающихся по времени, но начаться разрешено только одному. Остальные блокируются, пока выполнение текущей поведенческой характеристики не завершится. Проектировщик системы отвечает за то, чтобы взаимные блокировки не возникали из-за одновременной блокировки.

- **concurrent**

  К одному экземпляру могут поступать несколько вызовов поведенческой характеристики, перекрывающихся по времени, и все они могут выполняться параллельно.

### 9.9.4 Classifier (классификатор) [Abstract Class]

#### 9.9.4.1 Описание

Классификатор представляет классификацию экземпляров по их характеристикам.

#### 9.9.4.2 Диаграммы

Классификаторы, шаблоны классификаторов, характеристики, экземпляры, наборы обобщений, исполняемые узлы, варианты использования,

структурированные классификаторы, классы, ассоциации, компоненты, кооперации, переопределение в машинах состояний,

типы данных, сигналы, интерфейсы, информационные потоки, артефакты, действия, действия приёма события, действия над объектами

#### 9.9.4.3 Обобщения

Namespace (пространство имён), Type (тип), TemplateableElement (шаблонизируемый элемент), RedefinableElement (переопределяемый элемент)

#### 9.9.4.4 Специализации

Association (ассоциация), StructuredClassifier (структурированный классификатор), BehavioredClassifier (классификатор с поведением), DataType (тип данных), Interface (интерфейс), Signal (сигнал), InformationItem (информационный элемент), Artifact (артефакт)

#### 9.9.4.5 Атрибуты

- isAbstract : Boolean [1..1] = false

  Если истинно, классификатор может быть создан только созданием одной из его специализаций. Абстрактный классификатор предназначен для использования другими классификаторами, например как цель ассоциаций или обобщений.

- isFinalSpecialization : Boolean [1..1] = false

  Если истинно, классификатор не может быть специализирован.

#### 9.9.4.6 Концы ассоциаций

- /attribute : Property [0..*]{ordered, union, subsets Classifier::feature, subsets A_redefinitionContext_redefinableElement::redefinableElement} (opposite A_attribute_classifier::classifier) все свойства, являющиеся прямыми (то есть не унаследованными и не импортированными) атрибутами классификатора.

- ♦ collaborationUse : CollaborationUse [0..*]{subsets Element::ownedElement} (opposite A_collaborationUse_classifier::classifier) использования кооперации, принадлежащие классификатору.

- /feature : Feature [0..*]{union, subsets Namespace::member} (opposite Feature::featuringClassifier)

  задаёт каждую характеристику, непосредственно определённую в классификаторе. Отметим, что в классификаторе могут быть члены типа Feature, которые здесь не включены, например унаследованные характеристики.

- /general : Classifier [0..*] (opposite A_general_classifier::classifier)

  обобщающие классификаторы для этого классификатора.

- ♦ generalization : Generalization [0..*]{subsets Element::ownedElement, subsets A_source_directedRelationship::directedRelationship} (opposite Generalization::specific) отношения обобщения для этого классификатора. Эти обобщения ведут к более общим классификаторам в иерархии обобщения.

- /inheritedMember : NamedElement [0..*]{subsets Namespace::member} (opposite A_inheritedMember_inheritingClassifier::inheritingClassifier) все элементы, унаследованные этим классификатором от его общих классификаторов.

- ♦ ownedTemplateSignature : RedefinableTemplateSignature [0..1]{subsets A_redefinitionContext_redefinableElement::redefinableElement, redefines TemplateableElement::ownedTemplateSignature} (opposite RedefinableTemplateSignature::classifier) необязательная переопределяемая сигнатура шаблона, задающая формальные параметры шаблона.

- ♦ ownedUseCase : UseCase [0..*]{subsets Namespace::ownedMember} (opposite A_ownedUseCase_classifier::classifier) варианты использования, принадлежащие этому классификатору.

- powertypeExtent : GeneralizationSet [0..*] (opposite GeneralizationSet::powertype)

  набор обобщений, мощным типом которого является этот классификатор.

- redefinedClassifier : Classifier [0..*]{subsets RedefinableElement::redefinedElement} (opposite A_redefinedClassifier_classifier::classifier) классификаторы, переопределённые этим классификатором.

- representation : CollaborationUse [0..1]{subsets Classifier::collaborationUse} (opposite A_representation_classifier::classifier) использование кооперации, указывающее кооперацию, которая представляет этот классификатор.

- ♦ substitution : Substitution [0..*]{subsets Element::ownedElement, subsets NamedElement::clientDependency} (opposite Substitution::substitutingClassifier) подстановки, принадлежащие этому классификатору.

- templateParameter : ClassifierTemplateParameter [0..1]{redefines ParameterableElement::templateParameter} (opposite ClassifierTemplateParameter::parameteredElement) параметр шаблона классификатора, представляющий этот элемент как формальный параметр.

- useCase : UseCase [0..*] (opposite UseCase::subject)

  набор вариантов использования, субъектом которых является этот классификатор.

#### 9.9.4.7 Операции

- allFeatures() : Feature [0..*] запрос allFeatures() даёт все характеристики в пространстве имён классификатора. Как правило, благодаря таким механизмам, как наследование, это будет большее множество, чем feature.

  ```ocl
  body: member->select(oclIsKindOf(Feature))->collect(oclAsType(Feature))->asSet()
  ```

- allParents() : Classifier [0..*] запрос allParents() даёт всех прямых и косвенных предков обобщённого классификатора.

  ```ocl
  body: parents()->union(parents()->collect(allParents())->asSet())
  ```

- conformsTo(other : Type) : Boolean {redefines Type::conformsTo()} запрос conformsTo() даёт истину для классификатора, который определяет тип, соответствующий другому. Это используется, например, в спецификации соответствия сигнатур для операций.

  ```ocl
  body: if other.oclIsKindOf(Classifier) then
  let otherClassifier : Classifier = other.oclAsType(Classifier) in
  self = otherClassifier or allParents()->includes(otherClassifier)
  else
  false
  endif
  ```

- general() : Classifier [0..*] общие классификаторы — те, на которые ссылаются отношения обобщения.

  ```ocl
  body: parents()
  ```

- hasVisibilityOf(n : NamedElement) : Boolean запрос hasVisibilityOf() определяет, виден ли именованный элемент в классификаторе. Неприватные члены видимы. Он вызывается только тогда, когда аргумент является чем-то, принадлежащим родителю.

  ```ocl
  pre: allParents()->including(self)->collect(member)->includes(n)
  ```

  ```ocl
  body: n.visibility <> VisibilityKind::private
  ```

- inherit(inhs : NamedElement [0..*]) : NamedElement [0..*] запрос inherit() определяет, как наследовать набор элементов, переданный как его аргумент. Он исключает переопределённые элементы из результата.

  ```ocl
  body: inhs->reject(inh |
  inh.oclIsKindOf(RedefinableElement) and
  ownedMember->select(oclIsKindOf(RedefinableElement))->
  select(redefinedElement->includes(inh.oclAsType(RedefinableElement)))
  ->notEmpty())
  ```

- inheritableMembers(c : Classifier) : NamedElement [0..*] запрос inheritableMembers() даёт всех членов классификатора, которые могут быть унаследованы в одном из его потомков, с учётом любых действующих ограничений видимости.

  ```ocl
  pre: c.allParents()->includes(self)
  ```

  ```ocl
  body: member->select(m | c.hasVisibilityOf(m))
  ```

- inheritedMember() : NamedElement [0..*] ассоциация inheritedMember выводится наследованием наследуемых членов родителей.

  ```ocl
  body: inherit(parents()->collect(inheritableMembers(self))->asSet())
  ```

- isTemplate() : Boolean {redefines TemplateableElement::isTemplate()} запрос isTemplate() возвращает, является ли этот классификатор фактически шаблоном.

  ```ocl
  body: ownedTemplateSignature <> null or general->exists(g | g.isTemplate())
  ```

- maySpecializeType(c : Classifier) : Boolean запрос maySpecializeType() определяет, может ли этот классификатор иметь отношение обобщения к классификаторам указанного типа. По умолчанию классификатор может специализировать классификаторы того же или более общего типа. Предполагается, что он будет переопределён классификаторами с иными ограничениями специализации.

  ```ocl
  body: self.oclIsKindOf(c.oclType())
  ```

- parents() : Classifier [0..*] запрос parents() даёт всех непосредственных предков обобщённого классификатора.

  ```ocl
  body: generalization.general->asSet()
  ```

- directlyRealizedInterfaces() : Interface [0..*] интерфейсы, непосредственно реализуемые этим классификатором

  ```ocl
  body: (clientDependency->
  select(oclIsKindOf(Realization) and supplier->forAll(oclIsKindOf(Interface))))->
  collect(supplier.oclAsType(Interface))->asSet()
  ```

- directlyUsedInterfaces() : Interface [0..*] интерфейсы, непосредственно используемые этим классификатором

  ```ocl
  body: (supplierDependency->
  select(oclIsKindOf(Usage) and client->forAll(oclIsKindOf(Interface))))->
  collect(client.oclAsType(Interface))->asSet()
  ```

- allRealizedInterfaces() : Interface [0..*] интерфейсы, реализуемые этим классификатором и всеми его обобщениями

  ```ocl
  body: directlyRealizedInterfaces()->union(self.allParents()-
  >collect(directlyRealizedInterfaces()))->asSet()
  ```

- allUsedInterfaces() : Interface [0..*] интерфейсы, используемые этим классификатором и всеми его обобщениями

  ```ocl
  body: directlyUsedInterfaces()->union(self.allParents()->collect(directlyUsedInterfaces()))-
  >asSet()
  ```

- isSubstitutableFor(contract : Classifier) : Boolean

  ```ocl
  body: substitution.contract->includes(contract)
  ```

- allAttributes() : Property [0..*]{ordered} запрос allAttributes даёт упорядоченный набор всех принадлежащих и унаследованных атрибутов классификатора. Все принадлежащие атрибуты появляются перед любыми унаследованными атрибутами, а атрибуты, унаследованные от любого более специфического родительского классификатора, появляются перед атрибутами любого более общего родительского классификатора. Однако если у классификатора несколько непосредственных родителей, то относительный порядок наборов атрибутов от этих родителей не определён.

  ```ocl
  body: attribute->asSequence()->union(parents()->asSequence().allAttributes())->select(p |
  member->includes(p))->asOrderedSet()
  ```

- allSlottableFeatures() : StructuralFeature [0..*] все структурные характеристики, связанные с классификатором, которые могут иметь слоты, включая прямые атрибуты, унаследованные атрибуты, закрытые атрибуты в обобщениях и концы-члены ассоциаций, но за исключением переопределённых структурных характеристик.

  ```ocl
  body: member->select(oclIsKindOf(StructuralFeature))->
  collect(oclAsType(StructuralFeature))->
  union(self.inherit(self.allParents()->collect(p | p.attribute)->asSet())->
  collect(oclAsType(StructuralFeature)))->asSet()
  ```

#### 9.9.4.8 Ограничения

- **specialize_type**

  Классификатор может специализировать только классификаторы допустимого типа.

  ```ocl
  inv: parents()->forAll(c | self.maySpecializeType(c))
  ```

- **maps_to_generalization_set**

  Классификатор, отображаемый на набор обобщений, не может быть ни специфическим, ни общим классификатором ни в одном из отношений обобщения, определённых для этого набора обобщений. Иначе говоря, мощный тип не может быть экземпляром самого себя, и его экземпляры не могут быть его подклассами.

  ```ocl
  inv: powertypeExtent->forAll( gs |
  gs.generalization->forAll( gen |
  not (gen.general = self) and not gen.general.allParents()->includes(self) and not
  (gen.specific = self) and not self.allParents()->includes(gen.specific)
  ))
  ```

- **non_final_parents**

  Родители классификатора должны быть нелистовыми.

  ```ocl
  inv: parents()->forAll(not isFinalSpecialization)
  ```

- **no_cycles_in_generalization**

  Иерархии обобщения должны быть направленными и ациклическими. Классификатор не может быть одновременно транзитивно общим и транзитивно специфическим классификатором одного и того же классификатора.

  ```ocl
  inv: not allParents()->includes(self)
  ```

### 9.9.5 ClassifierTemplateParameter (параметр шаблона классификатора) [Class]

#### 9.9.5.1 Описание

Параметр шаблона классификатора представляет классификатор как формальный параметр шаблона.

#### 9.9.5.2 Диаграммы

Шаблоны классификаторов

#### 9.9.5.3 Обобщения

TemplateParameter

#### 9.9.5.4 Атрибуты

- allowSubstitutable : Boolean [1..1] = true

  Ограничивает требуемое отношение между фактическим параметром и parameteredElement для этого формального параметра.

#### 9.9.5.5 Концы ассоциаций

- constrainingClassifier : Classifier [0..*] (opposite A_constrainingClassifier_classifierTemplateParameter::classifierTemplateParameter)

  Классификаторы, которые ограничивают аргумент, допустимый для параметра. Если атрибут allowSubstitutable истинен, то может быть подставлен любой классификатор, совместимый с этим ограничивающим классификатором; иначе это должен быть либо этот классификатор, либо одна из его специализаций. Если это свойство пусто, никаких ограничений на классификатор, который может использоваться как аргумент, нет.

- parameteredElement : Classifier [1..1]{redefines TemplateParameter::parameteredElement} (opposite Classifier::templateParameter) классификатор, представляемый этим параметром шаблона классификатора.

#### 9.9.5.6 Ограничения

- **has_constraining_classifier**

  Если allowSubstitutable истинно, то должен быть constrainingClassifier.

  ```ocl
  inv: allowSubstitutable implies constrainingClassifier->notEmpty()
  ```

- **parametered_element_no_features**

  У parameteredElement нет прямых характеристик, а если constrainingClassifier пуст, у него нет и обобщений.

  ```ocl
  inv: parameteredElement.feature->isEmpty() and (constrainingClassifier->isEmpty() implies
  parameteredElement.allParents()->isEmpty())
  ```

- **matching_abstract**

  Если parameteredElement не абстрактен, то классификатор, используемый как аргумент, не должен быть абстрактным.

  ```ocl
  inv: (not parameteredElement.isAbstract) implies templateParameterSubstitution.actual-
  >forAll(a | not a.oclAsType(Classifier).isAbstract)
  ```

- **actual_is_classifier**

  Аргумент параметра шаблона классификатора является классификатором.

  ```ocl
  inv:   templateParameterSubstitution.actual->forAll(a | a.oclIsKindOf(Classifier))
  ```

- **constraining_classifiers_constrain_args**

  Если есть какие-либо constrainingClassifiers, то каждый аргумент должен быть тем же самым, что и они, или их специализацией, а если allowSubstitutable истинно, то он также может быть подставляемым.

  ```ocl
  inv: templateParameterSubstitution.actual->forAll( a |
  let arg : Classifier = a.oclAsType(Classifier) in
  constrainingClassifier->forAll(
  cc |
  arg = cc or arg.conformsTo(cc) or (allowSubstitutable and
  arg.isSubstitutableFor(cc))
  )
  )
  ```

- **constraining_classifiers_constrain_parametered_element**

  Если есть какие-либо constrainingClassifiers, то parameteredElement должен быть тем же самым, что и они, или их специализацией, а если allowSubstitutable истинно, то он также может быть подставляемым.

  ```ocl
  inv: constrainingClassifier->forAll(
  cc | parameteredElement = cc or parameteredElement.conformsTo(cc) or
  (allowSubstitutable and parameteredElement.isSubstitutableFor(cc))
  )
  ```

### 9.9.7 Generalization (обобщение) [Class]

#### 9.9.7.1 Описание

Обобщение — это таксономическая связь между более общим классификатором и более специфическим классификатором. Каждый экземпляр специфического классификатора является также экземпляром общего классификатора. Специфический классификатор наследует характеристики более общего классификатора. Обобщение принадлежит специфическому классификатору.

#### 9.9.7.2 Диаграммы

Классификаторы, наборы обобщений

#### 9.9.7.3 Обобщения

DirectedRelationship

#### 9.9.7.4 Атрибуты

- isSubstitutable : Boolean [0..1] = true

  Указывает, может ли специфический классификатор использоваться везде, где может использоваться общий классификатор. Если истинно, трассы выполнения специфического классификатора должны быть надмножеством трасс выполнения общего классификатора. Если ложно, такого ограничения на трассы выполнения нет. Если значение не установлено, моделировщик не указал, есть ли такое ограничение.

#### 9.9.7.5 Концы ассоциаций

- general : Classifier [1..1]{subsets DirectedRelationship::target} (opposite A_general_generalization::generalization) общий классификатор в отношении обобщения.

- generalizationSet : GeneralizationSet [0..*] (opposite GeneralizationSet::generalization)

  представляет набор экземпляров обобщения. Обобщение может появляться во многих наборах обобщений.

- specific : Classifier [1..1]{subsets DirectedRelationship::source, subsets Element::owner} (opposite Classifier::generalization) специализирующий классификатор в отношении обобщения.

### 9.9.8 GeneralizationSet (набор обобщений) [Class]

#### 9.9.8.1 Описание

Набор обобщений — это упаковываемый элемент, экземпляры которого представляют наборы отношений обобщения.

#### 9.9.8.2 Диаграммы

Классификаторы, наборы обобщений

#### 9.9.8.3 Обобщения

PackageableElement

#### 9.9.8.4 Атрибуты

- isCovering : Boolean [1..1] = false

  Указывает (через связанные обобщения), покрывает ли набор специфических классификаторов конкретный общий классификатор. Когда isCovering истинно, каждый экземпляр конкретного общего классификатора является также экземпляром по меньшей мере одного из его специфических классификаторов для данного набора обобщений. Когда isCovering ложно, есть один или несколько экземпляров конкретного общего классификатора, которые не являются экземплярами по меньшей мере одного из его специфических классификаторов, определённых для набора обобщений.

- isDisjoint : Boolean [1..1] = false

  Указывает, имеют ли наборы специфических классификаторов в отношении обобщения общие экземпляры. Если isDisjoint истинно, специфические классификаторы конкретного набора обобщений не имеют общих членов; то есть их пересечение пусто. Если isDisjoint ложно, специфические классификаторы конкретного набора обобщений имеют один или несколько общих членов; то есть их пересечение непусто.

#### 9.9.8.5 Концы ассоциаций

- generalization : Generalization [0..*] (opposite Generalization::generalizationSet)

  обозначает экземпляры обобщения, являющиеся членами этого набора обобщений.

- powertype : Classifier [0..1] (opposite Classifier::powertypeExtent)

  обозначает классификатор, определённый как мощный тип для связанного набора обобщений, если таковой есть.

#### 9.9.8.6 Ограничения

- **generalization_same_classifier**

  Каждое обобщение, связанное с конкретным набором обобщений, должно иметь один и тот же общий классификатор.

  ```ocl
  inv: generalization->collect(general)->asSet()->size() <= 1
  ```

- **maps_to_generalization_set**

  Классификатор, отображаемый на набор обобщений, не может быть ни специфическим, ни общим классификатором ни в одном из отношений обобщения, определённых для этого набора обобщений. Иначе говоря, мощный тип не может быть экземпляром самого себя, и его экземпляры не могут быть его подклассами.

  ```ocl
  inv: powertype <> null implies generalization->forAll( gen |
  not (gen.general = powertype) and not gen.general.allParents()->includes(powertype) and
  not (gen.specific = powertype) and not powertype.allParents()->includes(gen.specific)
  )
  ```

### 9.9.9 InstanceSpecification (спецификация экземпляра) [Class]

#### 9.9.9.1 Описание

Спецификация экземпляра — это элемент модели, представляющий экземпляр в моделируемой системе. Спецификация экземпляра может выступать как цель развёртывания в отношении развёртывания, если она представляет экземпляр узла. Она может также выступать как развёртываемый артефакт, если она представляет экземпляр артефакта.

#### 9.9.9.2 Диаграммы

Экземпляры, типы данных, развёртывания

#### 9.9.9.3 Обобщения

DeploymentTarget, PackageableElement, DeployedArtifact

#### 9.9.9.4 Специализации

EnumerationLiteral

#### 9.9.9.5 Концы ассоциаций

- classifier : Classifier [0..*] (opposite A_classifier_instanceSpecification::instanceSpecification)

  классификатор или классификаторы представляемого экземпляра. Если указано несколько классификаторов, экземпляр классифицируется всеми ими.

- ♦ slot : Slot [0..*]{subsets Element::ownedElement} (opposite Slot::owningInstance)

  слот, дающий значение или значения структурной характеристики экземпляра. Спецификация экземпляра может иметь один слот на каждую структурную характеристику своих классификаторов, включая унаследованные характеристики. Моделировать слот для каждой структурной характеристики не обязательно, и в этом случае спецификация экземпляра является частичным описанием.

- ♦ specification : ValueSpecification [0..1]{subsets Element::ownedElement} (opposite A_specification_owningInstanceSpec::owningInstanceSpec) спецификация того, как вычислить, вывести или сконструировать экземпляр.

#### 9.9.9.6 Ограничения

- **deployment_artifact**

  Спецификация экземпляра может выступать как развёртываемый артефакт, если она представляет экземпляр артефакта.

  ```ocl
  inv: deploymentForArtifact->notEmpty() implies classifier->exists(oclIsKindOf(Artifact))
  ```

- **structural_feature**

  В спецификации экземпляра не более одного слота могут иметь один и тот же definingFeature.

  ```ocl
  inv: classifier->forAll(c | (c.allSlottableFeatures()->forAll(f | slot->select(s |
  s.definingFeature = f)->size() <= 1)))
  ```

- **defining_feature**

  definingFeature каждого слота — это структурная характеристика, связанная с классификатором спецификации экземпляра, включая прямые атрибуты, унаследованные атрибуты, закрытые атрибуты в обобщениях и концы-члены ассоциаций, но за исключением переопределённых структурных характеристик.

  ```ocl
  inv: slot->forAll(s | classifier->exists (c | c.allSlottableFeatures()->includes
  (s.definingFeature)))
  ```

- **deployment_target**

  Спецификация экземпляра может выступать как цель развёртывания, если она представляет экземпляр узла и функционирует как часть во внутренней структуре объемлющего узла.

  ```ocl
  inv: deployment->notEmpty() implies classifier->exists(node | node.oclIsKindOf(Node) and
  Node.allInstances()->exists(n | n.part->exists(p | p.type = node)))
  ```

### 9.9.11 Operation (операция) [Class]

#### 9.9.11.1 Описание

Операция — это поведенческая характеристика классификатора, задающая имя, тип, параметры и ограничения для вызова связанного поведения. Операция может вызывать как выполнение поведений-методов, так и другие поведенческие реакции. Операция специализирует шаблонизируемый элемент, чтобы поддерживать спецификацию шаблонных и связанных операций. Операция специализирует параметризуемый элемент, чтобы указать, что операция может быть представлена как формальный параметр шаблона и предоставлена как фактический параметр в связывании шаблона.

#### 9.9.11.2 Диаграммы

Операции, классы, протокольные машины состояний, типы данных, интерфейсы, артефакты, события, действия вызова

#### 9.9.11.3 Обобщения

TemplateableElement, ParameterableElement, BehavioralFeature

#### 9.9.11.4 Атрибуты

- /isOrdered : Boolean [1..1]

  Задаёт, упорядочен ли возвращаемый параметр, если он есть. Эта информация выводится из возвращаемого результата этой операции.

- isQuery : Boolean [1..1] = false

  Задаёт, оставляет ли выполнение поведенческой характеристики состояние системы неизменным (isQuery=true) или могут возникать побочные эффекты (isQuery=false).

- /isUnique : Boolean [1..1]

  Задаёт, уникален ли возвращаемый параметр, если он есть. Эта информация выводится из возвращаемого результата этой операции.

- /lower : Integer [0..1]

  Задаёт нижнюю кратность возвращаемого параметра, если он есть. Эта информация выводится из возвращаемого результата этой операции.

- /upper : UnlimitedNatural [0..1]

  Верхняя кратность возвращаемого параметра, если он есть. Эта информация выводится из возвращаемого результата этой операции.

#### 9.9.11.5 Концы ассоциаций

- ♦ bodyCondition : Constraint [0..1]{subsets Namespace::ownedRule} (opposite A_bodyCondition_bodyContext::bodyContext) необязательное ограничение на значения результата вызова этой операции.

- class : Class [0..1]{subsets Feature::featuringClassifier, subsets NamedElement::namespace, subsets RedefinableElement::redefinitionContext} (opposite Class::ownedOperation) класс, владеющий этой операцией, если таковой есть.

- datatype : DataType [0..1]{subsets Feature::featuringClassifier, subsets NamedElement::namespace, subsets RedefinableElement::redefinitionContext} (opposite DataType::ownedOperation) тип данных, владеющий этой операцией, если таковой есть.

- interface : Interface [0..1]{subsets Feature::featuringClassifier, subsets NamedElement::namespace, subsets RedefinableElement::redefinitionContext} (opposite Interface::ownedOperation) интерфейс, владеющий этой операцией, если таковой есть.

- ♦ ownedParameter : Parameter [0..*]{ordered, redefines BehavioralFeature::ownedParameter} (opposite Parameter::operation) параметры, принадлежащие этой операции.

- ♦ postcondition : Constraint [0..*]{subsets Namespace::ownedRule} (opposite A_postcondition_postContext::postContext) необязательный набор ограничений, задающих состояние системы при завершении операции.

- ♦ precondition : Constraint [0..*]{subsets Namespace::ownedRule} (opposite A_precondition_preContext::preContext) необязательный набор ограничений на состояние системы при вызове операции.

- raisedException : Type [0..*]{redefines BehavioralFeature::raisedException} (opposite A_raisedException_operation::operation) типы, представляющие исключения, которые могут возбуждаться при вызове этой операции.

- redefinedOperation : Operation [0..*]{subsets RedefinableElement::redefinedElement} (opposite A_redefinedOperation_operation::operation) операции, переопределяемые этой операцией.

- templateParameter : OperationTemplateParameter [0..1]{redefines ParameterableElement::templateParameter} (opposite OperationTemplateParameter::parameteredElement) параметр шаблона операции, представляющий этот элемент как формальный параметр.

- /type : Type [0..1]{} (opposite A_type_operation::operation)

  возвращаемый тип операции, если он есть. Эта информация выводится из возвращаемого результата этой операции.

#### 9.9.11.6 Операции

- isConsistentWith(redefiningElement : RedefinableElement) : Boolean {redefines RedefinableElement::isConsistentWith()} запрос isConsistentWith() задаёт для любых двух операций в контексте, где возможно переопределение, будет ли переопределение согласованным. Переопределяющая операция согласована с переопределяемой, если она имеет то же число принадлежащих параметров и для каждого параметра выполняется следующее: - Направление, порядок и уникальность совпадают. - Соответствующие типы ковариантны, контравариантны или инвариантны. - Кратности совместимы в зависимости от направления параметра.

  ```ocl
  pre: redefiningElement.isRedefinitionContextValid(self)
  ```

  ```ocl
  body: redefiningElement.oclIsKindOf(Operation) and
  let op : Operation = redefiningElement.oclAsType(Operation) in
  self.ownedParameter->size() = op.ownedParameter->size() and
  Sequence{1..self.ownedParameter->size()}->
  forAll(i |
  let redefiningParam : Parameter = op.ownedParameter->at(i),
  redefinedParam : Parameter = self.ownedParameter->at(i) in
  (redefiningParam.isUnique = redefinedParam.isUnique) and
  (redefiningParam.isOrdered = redefinedParam. isOrdered) and
  (redefiningParam.direction = redefinedParam.direction) and
  (redefiningParam.type.conformsTo(redefinedParam.type) or
  redefinedParam.type.conformsTo(redefiningParam.type)) and
  (redefiningParam.direction = ParameterDirectionKind::inout implies
  (redefinedParam.compatibleWith(redefiningParam) and
  redefiningParam.compatibleWith(redefinedParam))) and
  (redefiningParam.direction = ParameterDirectionKind::_'in' implies
  redefinedParam.compatibleWith(redefiningParam)) and
  ((redefiningParam.direction = ParameterDirectionKind::out or
  redefiningParam.direction = ParameterDirectionKind::return) implies
  redefiningParam.compatibleWith(redefinedParam))
  )
  ```

- isOrdered() : Boolean если у этой операции есть возвращаемый параметр, isOrdered равно значению isOrdered для этого параметра. Иначе isOrdered ложно.

  ```ocl
  body: if returnResult()->notEmpty() then returnResult()-> exists(isOrdered) else false endif
  ```

- isUnique() : Boolean если у этой операции есть возвращаемый параметр, isUnique равно значению isUnique для этого параметра. Иначе isUnique истинно.

  ```ocl
  body: if returnResult()->notEmpty() then returnResult()->exists(isUnique) else true endif
  ```

- lower() : Integer если у этой операции есть возвращаемый параметр, lower равно значению lower для этого параметра. Иначе lower не имеет значения.

  ```ocl
  body: if returnResult()->notEmpty() then returnResult()->any(true).lower else null endif
  ```

- returnResult() : Parameter [0..*] запрос returnResult() возвращает множество, содержащее возвращаемый параметр операции, если он есть, иначе возвращает пустое множество

  ```ocl
  body: ownedParameter->select (direction = ParameterDirectionKind::return)
  ```

- type() : Type если у этой операции есть возвращаемый параметр, type равно значению type для этого параметра. Иначе type не имеет значения.

  ```ocl
  body: if returnResult()->notEmpty() then returnResult()->any(true).type else null endif
  ```

- upper() : UnlimitedNatural если у этой операции есть возвращаемый параметр, upper равно значению upper для этого параметра. Иначе upper не имеет значения.

  ```ocl
  body: if returnResult()->notEmpty() then returnResult()->any(true).upper else null endif
  ```

#### 9.9.11.7 Ограничения

- **at_most_one_return**

  Операция может иметь не более одного возвращаемого параметра; то есть принадлежащего параметра с направлением 'return.'

  ```ocl
  inv: self.ownedParameter->select(direction = ParameterDirectionKind::return)->size() <= 1
  ```

- **only_body_for_query**

  bodyCondition может быть задано только для запросной операции.

  ```ocl
  inv: bodyCondition <> null implies isQuery
  ```

### 9.9.12 OperationTemplateParameter (параметр шаблона операции) [Class]

#### 9.9.12.1 Описание

Параметр шаблона операции представляет операцию как формальный параметр шаблона.

#### 9.9.12.2 Диаграммы

Операции

#### 9.9.12.3 Обобщения

TemplateParameter

### 9.9.13 Parameter (параметр) [Class]

#### 9.9.13.1 Описание

Параметр — это спецификация аргумента, используемого для передачи информации внутрь или наружу при вызове поведенческой характеристики. Параметры могут рассматриваться как присоединяемые элементы внутри коопераций.

#### 9.9.13.2 Диаграммы

Характеристики, операции, узлы объектов, выражения, поведения

#### 9.9.13.3 Обобщения

MultiplicityElement, ConnectableElement

#### 9.9.13.4 Атрибуты

- /default : String [0..1]

  строка, представляющая значение, которое следует использовать, когда для параметра не предоставлен аргумент.

- direction : ParameterDirectionKind [1..1] = in

  Указывает, передаётся ли параметр внутрь поведенческого элемента или наружу из него.

- effect : ParameterEffectKind [0..1]

  Задаёт эффект, который выполнения владельца параметра оказывают на объекты, передаваемые внутрь параметра или наружу через него.

- isException : Boolean [1..1] = false

  Указывает, может ли выходной параметр выдать значение в ущерб остальным выходам.

- isStream : Boolean [1..1] = false

  Указывает, может ли входной параметр принимать значения, пока выполняется его поведение, или может ли выходной параметр выдавать значения, пока выполняется поведение.

#### 9.9.13.5 Концы ассоциаций

- ♦ defaultValue : ValueSpecification [0..1]{subsets Element::ownedElement} (opposite A_defaultValue_owningParameter::owningParameter) задаёт спецификацию значения, представляющую значение, которое следует использовать, когда для параметра не предоставлен аргумент.

- operation : Operation [0..1]{subsets A_ownedParameter_ownerFormalParam::ownerFormalParam} (opposite Operation::ownedParameter) операция, владеющая этим параметром.

- parameterSet : ParameterSet [0..*] (opposite ParameterSet::parameter)

  наборы параметров, содержащие этот параметр. См. набор параметров.

#### 9.9.13.6 Операции

- default() : String [0..1] вывод для Parameter::/default

  ```ocl
  body: if self.type = String then defaultValue.stringValue() else null endif
  ```

#### 9.9.13.7 Ограничения

- **in_and_out**

  Только параметры in и inout могут иметь эффект delete. Только параметры out, inout и return могут иметь эффект create.

  ```ocl
  inv: (effect = ParameterEffectKind::delete implies (direction =
  ParameterDirectionKind::_'in' or direction = ParameterDirectionKind::inout))
  and
  (effect = ParameterEffectKind::create implies (direction = ParameterDirectionKind::out or
  direction = ParameterDirectionKind::inout or direction = ParameterDirectionKind::return))
  ```

- **not_exception**

  Входной параметр не может быть исключением.

  ```ocl
  inv: isException implies (direction <> ParameterDirectionKind::_'in' and direction <>
  ParameterDirectionKind::inout)
  ```

- **connector_end**

  Параметр может быть связан с концом коннектора только в контексте кооперации.

  ```ocl
  inv: end->notEmpty() implies collaboration->notEmpty()
  ```

- **reentrant_behaviors**

  Повторно входимые поведения не могут иметь потоковых параметров.

  ```ocl
  inv: (isStream and behavior <> null) implies not behavior.isReentrant
  ```

- **stream_and_exception**

  Параметр не может быть одновременно потоковым и исключением.

  ```ocl
  inv: not (isException and isStream)
  ```

- **object_effect**

  Параметры, типизированные типами данных, не могут иметь эффект.

  ```ocl
  inv: (type.oclIsKindOf(DataType)) implies (effect = null)
  ```

### 9.9.14 ParameterDirectionKind (вид направления параметра) [Enumeration]

#### 9.9.14.1 Описание

ParameterDirectionKind — это перечисление, определяющее литералы, используемые для указания направления параметров.

#### 9.9.14.2 Диаграммы

- Характеристики

#### 9.9.14.3 Литералы

- in Указывает, что значения параметра передаются вызывающей стороной.

- **inout**

  Указывает, что значения параметра передаются вызывающей стороной и (возможно, другие) значения передаются наружу вызывающей стороне.

- **out**

  Указывает, что значения параметра передаются наружу вызывающей стороне.

- **return**

  Указывает, что значения параметра передаются обратно вызывающей стороне как возвращаемые значения.

### 9.9.15 ParameterEffectKind (вид эффекта параметра) [Enumeration]

#### 9.9.15.1 Описание

ParameterEffectKind — это перечисление, указывающее эффект поведения на значения, передаваемые внутрь или наружу через его параметры.

#### 9.9.15.2 Диаграммы

- Характеристики

#### 9.9.15.3 Литералы

- **create**

  Указывает, что поведение создаёт значения.

- **read**

  Указывает, что у объектов, являющихся значениями параметра, во время выполнений поведения извлекаются значения их свойств, или связи, в которых они участвуют, или их классификаторы.

- **update**

  Указывает, что у объектов, являющихся значениями параметра, во время выполнений поведения изменяются значения их свойств, или связи, в которых они участвуют, или их классификация.

- **delete**

  Указывает, что объекты, являющиеся значениями параметра, не существуют после завершения выполнений поведения.

### 9.9.16 ParameterSet (набор параметров) [Class]

#### 9.9.16.1 Описание

Набор параметров обозначает альтернативные наборы входов или выходов, которые может использовать поведение.

#### 9.9.16.2 Диаграммы

Характеристики, поведения

#### 9.9.16.3 Обобщения

NamedElement

#### 9.9.16.4 Концы ассоциаций

- ♦ condition : Constraint [0..*]{subsets Element::ownedElement} (opposite A_condition_parameterSet::parameterSet) ограничение, которое должно быть выполнено, чтобы владелец параметров входного набора параметров начал выполнение с использованием значений, предоставленных для этих параметров, либо чтобы владелец параметров выходного набора параметров завершил выполнение, предоставив значения для этих параметров, если все предусловия и условия на входные наборы параметров были выполнены.

- parameter : Parameter [1..*] (opposite Parameter::parameterSet)

  параметры в наборе параметров.

#### 9.9.16.5 Ограничения

- **same_parameterized_entity**

  Параметры в наборе параметров должны быть все входами или все выходами одной и той же параметризуемой сущности, и набор параметров принадлежит этой сущности.

  ```ocl
  inv: parameter->forAll(p1, p2 | self.owner = p1.owner and self.owner = p2.owner and
  p1.direction = p2.direction)
  ```

- **input**

  Если у параметризуемой сущности есть входные параметры, входящие в набор параметров, то любые входы, не входящие в набор параметров, должны быть потоковыми. То же для выходных параметров.

  ```ocl
  inv: ((parameter->exists(direction = ParameterDirectionKind::_'in')) implies
  behavioralFeature.ownedParameter->select(p | p.direction = ParameterDirectionKind::_'in'
  and p.parameterSet->isEmpty())->forAll(isStream))
  and
  ((parameter->exists(direction = ParameterDirectionKind::out)) implies
  behavioralFeature.ownedParameter->select(p | p.direction = ParameterDirectionKind::out
  and p.parameterSet->isEmpty())->forAll(isStream))
  ```

- **two_parameter_sets**

  Два набора параметров не могут иметь в точности один и тот же набор параметров.

  ```ocl
  inv: parameter->forAll(parameterSet->forAll(s1, s2 | s1->size() = s2->size() implies
  s1.parameter->exists(p | not s2.parameter->includes(p))))
  ```

### 9.9.17 Property (свойство) [Class]

#### 9.9.17.1 Описание

Свойство — это структурная характеристика. Свойство, связанное через ownedAttribute с классификатором (иным, чем ассоциация), представляет атрибут и может также представлять конец ассоциации. Оно связывает экземпляр классификатора со значением или набором значений типа атрибута. Свойство, связанное через memberEnd с ассоциацией, представляет конец ассоциации. Тип свойства — это тип конца ассоциации. Свойство обладает способностью быть целью развёртывания в отношении развёртывания. Это позволяет моделировать развёртывание на иерархические узлы, имеющие свойства, функционирующие как внутренние части. Свойство специализирует параметризуемый элемент, чтобы указать, что свойство может быть представлено как формальный параметр шаблона и предоставлено как фактический параметр в связывании шаблона.

#### 9.9.17.2 Диаграммы

Классификаторы, свойства, инкапсулированные классификаторы, структурированные классификаторы, классы, ассоциации, типы данных,

сигналы, интерфейсы, профили, развёртывания, артефакты, данные конца связи, действия над объектами-связями

#### 9.9.17.3 Обобщения

ConnectableElement, DeploymentTarget, StructuralFeature

#### 9.9.17.4 Специализации

Port, ExtensionEnd

#### 9.9.17.5 Атрибуты

- aggregation : AggregationKind [1..1] = none

  Задаёт вид агрегации, применимый к свойству.

- /isComposite : Boolean [1..1] = false

  Если isComposite истинно, объект, содержащий атрибут, является контейнером для объекта или значения, содержащегося в атрибуте. Это производное значение, указывающее, является ли агрегация свойства композитной.

- isDerived : Boolean [1..1] = false

  Задаёт, является ли свойство производным, то есть может ли его значение или значения вычисляться из другой информации.

- isDerivedUnion : Boolean [1..1] = false

  Задаёт, является ли свойство производным как объединение всех свойств, которые ограничены быть его подмножествами.

- isID : Boolean [1..1] = false

  Истина указывает, что это свойство может использоваться для однозначной идентификации экземпляра содержащего класса.

#### 9.9.17.6 Концы ассоциаций

- association : Association [0..1]{subsets A_member_memberNamespace::memberNamespace} (opposite Association::memberEnd) ассоциация, членом которой является это свойство, если таковая есть.

- associationEnd : Property [0..1]{subsets Element::owner} (opposite Property::qualifier)

  обозначает необязательный конец ассоциации, которому принадлежит атрибут-квалификатор.

- class : Class [0..1]{subsets NamedElement::namespace, subsets A_ownedAttribute_structuredClassifier::structuredClassifier, subsets A_attribute_classifier::classifier} (opposite Class::ownedAttribute) класс, владеющий этим свойством, если таковой есть.

- datatype : DataType [0..1]{subsets NamedElement::namespace, subsets A_attribute_classifier::classifier} (opposite DataType::ownedAttribute) тип данных, владеющий этим свойством, если таковой есть.

- ♦ defaultValue : ValueSpecification [0..1]{subsets Element::ownedElement} (opposite A_defaultValue_owningProperty::owningProperty) спецификация значения, которая вычисляется, давая значение по умолчанию для свойства при создании экземпляра владеющего классификатора.

- interface : Interface [0..1]{subsets NamedElement::namespace, subsets A_attribute_classifier::classifier} (opposite Interface::ownedAttribute) интерфейс, владеющий этим свойством, если таковой есть.

- /opposite : Property [0..1] (opposite A_opposite_property::property)

  в случае, когда свойство является одним концом бинарной ассоциации, даёт другой конец.

- owningAssociation : Association [0..1]{subsets Feature::featuringClassifier, subsets NamedElement::namespace, subsets Property::association, subsets RedefinableElement::redefinitionContext} (opposite Association::ownedEnd) владеющая ассоциация этого свойства, если таковая есть.

- ♦ qualifier : Property [0..*]{ordered, subsets Element::ownedElement} (opposite Property::associationEnd)

  необязательный список упорядоченных атрибутов-квалификаторов для конца.

- redefinedProperty : Property [0..*]{subsets RedefinableElement::redefinedElement} (opposite A_redefinedProperty_property::property) свойства, переопределяемые этим свойством, если таковые есть.

- subsettedProperty : Property [0..*] (opposite A_subsettedProperty_property::property)

  свойства, подмножеством которых ограничено быть это свойство, если таковые есть.

#### 9.9.17.7 Операции

- isAttribute() : Boolean запрос isAttribute() истинен, если свойство определено как атрибут некоторого классификатора.

  ```ocl
  body: not classifier->isEmpty()
  ```

- isCompatibleWith(p : ParameterableElement) : Boolean {redefines ParameterableElement::isCompatibleWith()} запрос isCompatibleWith() определяет, совместимо ли это свойство с указанным параметризуемым элементом. Это свойство совместимо с параметризуемым элементом p, если вид этого свойства тот же, что и вид p, или является его подтипом. Кроме того, если p является типизированным элементом, то тип этого свойства должен соответствовать типу p.

  ```ocl
  body: self.oclIsKindOf(p.oclType()) and (p.oclIsKindOf(TypeElement) implies
  self.type.conformsTo(p.oclAsType(TypedElement).type))
  ```

- isComposite() : Boolean значение isComposite истинно только если aggregation имеет значение composite.

  ```ocl
  body: aggregation = AggregationKind::composite
  ```

- isConsistentWith(redefiningElement : RedefinableElement) : Boolean {redefines RedefinableElement::isConsistentWith()} запрос isConsistentWith() задаёт для любых двух свойств в контексте, где возможно переопределение, будет ли переопределение логически согласованным. Переопределяющее свойство согласовано с переопределяемым, если тип переопределяющего свойства соответствует типу переопределяемого свойства, а кратность переопределяющего свойства (если она указана) содержится в кратности переопределяемого свойства.

  ```ocl
  pre: redefiningElement.isRedefinitionContextValid(self)
  ```

  ```ocl
  body: redefiningElement.oclIsKindOf(Property) and
  let prop : Property = redefiningElement.oclAsType(Property) in
  (prop.type.conformsTo(self.type) and
  ((prop.lowerBound()->notEmpty() and self.lowerBound()->notEmpty()) implies
  prop.lowerBound() >= self.lowerBound()) and
  ((prop.upperBound()->notEmpty() and self.upperBound()->notEmpty()) implies
  prop.lowerBound() <= self.lowerBound()) and
  (self.isComposite implies prop.isComposite))
  ```

- isNavigable() : Boolean запрос isNavigable() указывает, возможно ли навигировать через это свойство.

  ```ocl
  body: not classifier->isEmpty() or association.navigableOwnedEnd->includes(self)
  ```

- opposite() : Property если это свойство является концом-членом бинарной ассоциации, то opposite даёт другой конец.

  ```ocl
  body: if association <> null and association.memberEnd->size() = 2
  then
  association.memberEnd->any(e | e <> self)
  else
  null
  endif
  ```

- subsettingContext() : Type [0..*] запрос subsettingContext() даёт контекст для подмножества свойства. Он состоит, в случае атрибута, из соответствующего классификатора, а в случае конца ассоциации — из всех классификаторов на других концах.

  ```ocl
  body: if association <> null
  then association.memberEnd->excluding(self)->collect(type)->asSet()
  else
  if classifier<>null
  then classifier->asSet()
  else Set{}
  endif
  endif
  ```

#### 9.9.17.8 Ограничения

- **subsetting_context_conforms**

  Подмножество может возникать только тогда, когда контекст свойства-подмножества соответствует контексту свойства, для которого задаётся подмножество.

  ```ocl
  inv: subsettedProperty->notEmpty() implies
  (subsettingContext()->notEmpty() and subsettingContext()->forAll (sc |
  subsettedProperty->forAll(sp |
  sp.subsettingContext()->exists(c | sc.conformsTo(c)))))
  ```

- **derived_union_is_read_only**

  Производное объединение доступно только для чтения.

  ```ocl
  inv: isDerivedUnion implies isReadOnly
  ```

- **multiplicity_of_composite**

  Кратность на составляющем конце композитной агрегации не должна иметь верхнюю границу больше 1.

  ```ocl
  inv: isComposite and association <> null implies opposite.upperBound() <= 1
  ```

- **redefined_property_inherited**

  Переопределённое свойство должно быть унаследовано от более общего классификатора.

  ```ocl
  inv: (redefinedProperty->notEmpty()) implies
  (redefinitionContext->notEmpty() and
  redefinedProperty->forAll(rp|
  ((redefinitionContext->collect(fc|
  fc.allParents()))->asSet())->collect(c| c.allFeatures())->asSet()->includes(rp)))
  ```

- **subsetting_rules**

  Свойство-подмножество может усиливать тип свойства, для которого задаётся подмножество, и его верхняя граница может быть меньше.

  ```ocl
  inv: subsettedProperty->forAll(sp |
  self.type.conformsTo(sp.type) and
  ((self.upperBound()->notEmpty() and sp.upperBound()->notEmpty()) implies
  self.upperBound() <= sp.upperBound() ))
  ```

- **binding_to_attribute**

  Связывание параметра шаблона-свойства, представляющего атрибут, должно быть связыванием с атрибутом.

  ```ocl
  inv: (self.isAttribute()
  and (templateParameterSubstitution->notEmpty())
  implies (templateParameterSubstitution->forAll(ts |
  ts.formal.oclIsKindOf(Property)
  and ts.formal.oclAsType(Property).isAttribute())))
  ```

- **derived_union_is_derived**

  Производное объединение является производным.

  ```ocl
  inv: isDerivedUnion implies isDerived
  ```

- **deployment_target**

  Свойство может быть целью развёртывания, если оно является видом узла и функционирует как часть во внутренней структуре объемлющего узла.

  ```ocl
  inv: deployment->notEmpty() implies owner.oclIsKindOf(Node) and Node.allInstances()-
  >exists(n | n.part->exists(p | p = self))
  ```

- **subsetted_property_names**

  Свойство не может задавать подмножество свойства с тем же именем.

  ```ocl
  inv: subsettedProperty->forAll(sp | sp.name <> name)
  ```

- **type_of_opposite_end**

  Если свойство является принадлежащим классификатору концом бинарной ассоциации, его владелец должен быть типом противоположного конца.

  ```ocl
  inv: (opposite->notEmpty() and owningAssociation->isEmpty()) implies classifier =
  opposite.type
  ```

- **qualified_is_association_end**

  Все квалифицированные свойства должны быть концами ассоциаций

  ```ocl
  inv: qualifier->notEmpty() implies association->notEmpty()
  ```

### 9.9.18 RedefinableElement (переопределяемый элемент) [Abstract Class]

#### 9.9.18.1 Описание

Переопределяемый элемент — это элемент, который, будучи определён в контексте классификатора, может быть переопределён более специфично или иначе в контексте другого классификатора, который специализирует (прямо или косвенно) контекстный классификатор.

#### 9.9.18.2 Диаграммы

Классификаторы, шаблоны классификаторов, характеристики, деятельности, варианты использования, переопределение в машинах состояний

#### 9.9.18.3 Обобщения

NamedElement

#### 9.9.18.4 Специализации

Classifier (классификатор), Feature (характеристика), RedefinableTemplateSignature (переопределяемая сигнатура шаблона), ActivityEdge (ребро деятельности), ActivityNode (узел деятельности), ExtensionPoint (точка расширения), Region (регион), State (состояние), Transition (переход)

#### 9.9.18.5 Атрибуты

- isLeaf : Boolean [1..1] = false

  Указывает, возможно ли дальнейшее переопределение переопределяемого элемента. Если значение истинно, то дальнейшее переопределение переопределяемого элемента невозможно.

#### 9.9.18.6 Концы ассоциаций

- /redefinedElement : RedefinableElement [0..*]{union} (opposite A_redefinedElement_redefinableElement::redefinableElement) переопределяемый элемент, который переопределяется этим элементом.

- /redefinitionContext : Classifier [0..*]{union} (opposite A_redefinitionContext_redefinableElement::redefinableElement) контексты, из которых этот элемент может быть переопределён.

#### 9.9.18.7 Операции

- isConsistentWith(redefiningElement : RedefinableElement) : Boolean запрос isConsistentWith() задаёт для любых двух переопределяемых элементов в контексте, где возможно переопределение, будет ли переопределение логически согласованным. По умолчанию это ложно; эта операция должна быть переопределена в подклассах переопределяемого элемента, чтобы определить условия согласованности.

  ```ocl
  pre: redefiningElement.isRedefinitionContextValid(self)
  ```

  ```ocl
  body: false
  ```

- isRedefinitionContextValid(redefinedElement : RedefinableElement) : Boolean запрос isRedefinitionContextValid() задаёт, надлежащим ли образом контексты переопределения этого переопределяемого элемента связаны с контекстами переопределения указанного переопределяемого элемента, чтобы этот элемент мог

  переопределить другой. По умолчанию по меньшей мере один из контекстов переопределения этого элемента должен быть специализацией по меньшей мере одного из контекстов переопределения указанного элемента.

  ```ocl
  body: redefinitionContext->exists(c | c.allParents()-
  >includesAll(redefinedElement.redefinitionContext))
  ```

#### 9.9.18.8 Ограничения

- **redefinition_consistent**

  Переопределяющий элемент должен быть согласован с каждым переопределяемым элементом.

  ```ocl
  inv: redefinedElement->forAll(re | re.isConsistentWith(self))
  ```

- **non_leaf_redefinition**

  Переопределяемый элемент может переопределять только нелистовые переопределяемые элементы.

  ```ocl
  inv: redefinedElement->forAll(re | not re.isLeaf)
  ```

- **redefinition_context_valid**

  По меньшей мере один из контекстов переопределения переопределяющего элемента должен быть специализацией по меньшей мере одного из контекстов переопределения для каждого переопределяемого элемента.

  ```ocl
  inv: redefinedElement->forAll(re | self.isRedefinitionContextValid(re))
  ```

### 9.9.19 RedefinableTemplateSignature (переопределяемая сигнатура шаблона) [Class]

#### 9.9.19.1 Описание

Переопределяемая сигнатура шаблона поддерживает добавление формальных параметров шаблона в специализации шаблонного классификатора.

#### 9.9.19.2 Диаграммы

#### 9.9.19.3 Обобщения

RedefinableElement, TemplateSignature

#### 9.9.19.4 Концы ассоциаций

- classifier : Classifier [1..1]{subsets RedefinableElement::redefinitionContext, redefines TemplateSignature::template} (opposite Classifier::ownedTemplateSignature) классификатор, которому принадлежит эта переопределяемая сигнатура шаблона.

- extendedSignature : RedefinableTemplateSignature [0..*]{subsets RedefinableElement::redefinedElement} (opposite A_extendedSignature_redefinableTemplateSignature::redefinableTemplateSignature) сигнатуры, расширяемые этой переопределяемой сигнатурой шаблона.

- /inheritedParameter : TemplateParameter [0..*]{subsets TemplateSignature::parameter} (opposite A_inheritedParameter_redefinableTemplateSignature::redefinableTemplateSignature) формальные параметры шаблона расширяемых сигнатур.

#### 9.9.19.5 Операции

- inheritedParameter() : TemplateParameter [0..*] вывод для RedefinableTemplateSignature::/inheritedParameter

  ```ocl
  body: if extendedSignature->isEmpty() then Set{} else extendedSignature.parameter->asSet()
  endif
  ```

- isConsistentWith(redefiningElement : RedefinableElement) : Boolean {redefines RedefinableElement::isConsistentWith()} запрос isConsistentWith() задаёт для любых двух переопределяемых сигнатур шаблона в контексте, где возможно переопределение, будет ли переопределение логически согласованным. Переопределяющая сигнатура шаблона всегда согласована с переопределяемой сигнатурой шаблона, так как переопределение лишь добавляет новые формальные параметры.

  ```ocl

  ```

  ```ocl

  ```

#### 9.9.19.6 Ограничения

- **redefines_parents**

  Если какой-либо из родительских классификаторов является шаблоном, то extendedSignature должна включать сигнатуру этого классификатора.

  ```ocl
  inv: classifier.allParents()->forAll(c | c.ownedTemplateSignature->notEmpty() implies self-
  >closure(extendedSignature)->includes(c.ownedTemplateSignature))
  ```

### 9.9.22 Substitution (подстановка) [Class]

#### 9.9.22.1 Описание

Подстановка — это связь между двумя классификаторами, означающая, что подставляющий классификатор соблюдает контракт, заданный классификатором-контрактом. Это подразумевает, что экземпляры подставляющего классификатора заменяемы во время выполнения там, где ожидаются экземпляры классификатора-контракта.

#### 9.9.22.2 Диаграммы

Классификаторы

#### 9.9.22.3 Обобщения

Realization

#### 9.9.22.4 Концы ассоциаций

- contract : Classifier [1..1]{subsets Dependency::supplier} (opposite A_contract_substitution::substitution)

  контракт, которому соблюдает подставляющий классификатор.

- substitutingClassifier : Classifier [1..1]{subsets Dependency::client, subsets Element::owner} (opposite Classifier::substitution) экземпляры подставляющего классификатора заменяемы во время выполнения там, где ожидаются экземпляры классификатора-контракта.
