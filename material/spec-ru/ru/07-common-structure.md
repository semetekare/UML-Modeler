## 7.1 Краткое описание

В этом пункте определяются базовые понятия моделирования, лежащие в основе всего структурного моделирования в UML. Многие определённые здесь метаклассы абстрактны и служат основой для специализированных конкретных классов, определённых в последующих пунктах. Однако чтобы дать примеры применения этих базовых понятий в UML, приходится использовать и эти конкретные конструкции моделирования, хотя они определены в более поздних пунктах. Там, где необходимо, даны соответствующие ссылки вперёд.

### 7.2.3 Семантика

#### 7.2.3.1 Элементы

Элемент — составная часть модели. Потомки элемента дают семантику, подходящую для понятия, которое они представляют.

Каждый элемент обладает неотъемлемой способностью владеть другими элементами. Когда элемент удаляется из модели, все принадлежащие ему элементы также обязательно удаляются из модели. Абстрактный синтаксис каждого вида элемента задаёт, какими другими видами элементов он может владеть. Каждый элемент в модели должен принадлежать ровно одному другому элементу этой модели, за исключением пакетов верхнего уровня модели (см. также пункт 12 о пакетах).

#### 7.2.3.2 Комментарии

Любой вид элемента может владеть комментариями. Принадлежащие элементу комментарии не добавляют семантики, но могут представлять сведения, полезные читателю модели.

#### 7.2.3.3 Связи

Связь — это элемент, задающий некоторого рода отношение между другими элементами. Потомки связи дают семантику, подходящую для понятия, которое они представляют.

Направленная связь представляет связь между набором исходных элементов модели и набором целевых элементов модели. Говорят, что направленная связь направлена от исходных элементов к целевым.

### 7.2.4 Нотация

Общей нотации для элемента, связей и направленных связей нет. Потомки этих классов определяют собственную нотацию. Для связей в большинстве случаев нотация — вариант линии, проведённой между связанными элементами. Для направленных связей линия обычно некоторым образом направлена от источника (источников) к цели (целям).

Комментарий показывается прямоугольником с загнутым правым верхним углом (это также называют «символом примечания»). Прямоугольник содержит тело комментария. Соединение с каждым аннотируемым элементом показывается отдельной пунктирной линией. Пунктирную линию, соединяющую символ примечания с аннотируемыми элементами, можно опустить, если это ясно из контекста или не важно на данной диаграмме.

### 7.3.3 Семантика

#### 7.3.3.1 Шаблоны

Шаблонизируемый элемент — это элемент, который может по выбору быть определён как шаблон и связан с другими шаблонами. Шаблон — это шаблонизируемый элемент, параметризованный с помощью сигнатуры шаблона. Такой шаблон может использоваться для порождения других элементов модели с помощью отношений связывания шаблона.

Шаблон нельзя использовать так же, как нешаблонный элемент того же вида (например, шаблонный класс нельзя использовать как тип типизированного элемента). Шаблонный элемент может использоваться только для порождения связанных элементов или как часть спецификации другого шаблона (например, шаблонный класс может специализировать другой шаблонный класс).

Сигнатура шаблона шаблона определяет набор параметров шаблона, которые могут быть связаны с фактическими элементами модели в связанном элементе для этого шаблона. Связанный элемент — это шаблонизируемый элемент, имеющий одно или несколько таких связываний шаблона.

Полностью связанный элемент — это связанный элемент, все связывания шаблона которого связывают все параметры шаблона связываемого шаблона. Полностью связанный элемент — обычный элемент, и его можно использовать так же, как несвязанный (и нешаблонный) элемент того же вида. Например, полностью связанный элемент шаблона класса может использоваться как тип типизированного элемента.

Частично связанный элемент — это связанный элемент, хотя бы одно связывание шаблона которого не связывает параметр шаблона связываемого шаблона. Частично связанный элемент по-прежнему считается шаблоном, параметризованным оставшимися параметрами шаблона, не связанными его связываниями шаблона.

#### 7.3.3.2 Сигнатуры шаблонов

Параметры шаблона сигнатуры шаблона задают формальные параметры, которые будут замещены фактическими параметрами (или значением по умолчанию) при связывании. Параметр шаблона определяется в терминах параметризуемого элемента, содержащегося в шаблоне, которому принадлежит сигнатура шаблона, частью которой является параметр шаблона. Говорят, что такой элемент представляется параметром шаблона.

Представляемый параметризуемый элемент может принадлежать шаблону прямо или косвенно либо может принадлежать самому параметру шаблона — в ситуациях, когда у элемента иначе нет отношения принадлежности в модели шаблона. В любом случае параметризуемый элемент имеет смысл только в контексте шаблона — в контексте связывания он фактически заменяется фактическим элементом. Таким образом, на параметризуемый элемент, представляемый параметром шаблона, нельзя ссылаться вне его владеющего шаблона или других шаблонов, имеющих доступ к внутреннему устройству исходного шаблона (например, если шаблон специализирован). Подклассы сигнатуры шаблона могут также добавлять дополнительные правила, ограничивающие, какой вид параметризуемого элемента можно использовать для параметра шаблона в контексте конкретного вида шаблона.

Параметр шаблона может также ссылаться на параметризуемый элемент как на значение по умолчанию для этого формального параметра в любом связывании шаблона, которое не даёт явной подстановки параметра шаблона для этого параметра. Подобно представляемому параметризуемому элементу, параметризуемый элемент по умолчанию может принадлежать либо непосредственно шаблону, либо самому параметру шаблона. Параметр шаблона может владеть этим параметризуемым элементом по умолчанию даже в ситуациях, когда представляемый параметризуемый элемент не принадлежит параметру шаблона.

#### 7.3.3.3 Связывания шаблона

Связывание шаблона — это связь между шаблонизируемым элементом и шаблоном, задающая подстановки фактических параметризуемых элементов вместо формальных параметров шаблона шаблона. Подстановка параметра шаблона задаёт фактический параметр, который подставляется вместо формального параметра шаблона в контексте связывания шаблона. Если в этом связывании для формального параметра не задан фактический параметр, то используется параметризуемый элемент по умолчанию для этого формального параметра шаблона (если он задан). У связанного элемента может быть несколько связываний, возможно с одним и тем же шаблоном. Кроме того, связанный элемент может содержать элементы помимо связываний. Подробности того, как развёртывания нескольких связываний и любые другие элементы, принадлежащие связанному элементу, объединяются вместе, чтобы полностью задать связанный элемент, специфичны для подклассов шаблонизируемого элемента. Общий принцип состоит в том, что связывания вычисляются по отдельности, давая

промежуточные результаты (по одному на каждое связывание), которые затем объединяются, давая окончательный результат. Именно способ объединения специфичен для каждого вида шаблонизируемого элемента.

Шаблонизируемый элемент может содержать и сигнатуру шаблона, и связывания шаблона. Таким образом, шаблонизируемый элемент может быть одновременно шаблоном и связанным элементом.

Соответствующий инструмент может требовать, чтобы все формальные параметры шаблона были связаны в рамках связывания шаблона (полное связывание), либо может допускать связывание только подмножества формальных параметров шаблона (частичное связывание). В случае полного связывания у связанного элемента может быть собственная сигнатура шаблона, и параметры шаблона из неё могут предоставляться как фактические параметры связывания шаблона. В случае частичного связывания несвязанные формальные параметры шаблона действуют как формальные параметры шаблона связанного элемента, который, таким образом, остаётся шаблоном.

ПРИМЕЧАНИЕ. Параметр шаблона со значением по умолчанию никогда не может быть несвязанным, так как у него есть неявное связывание со значением по умолчанию, даже если для него не задана явная подстановка параметра шаблона.

#### 7.3.3.4 Семантика связанного элемента

Связывание шаблона означает, что связанный элемент имеет те же ограничения корректной построенности и ту же семантику, как если бы содержимое шаблона, которому принадлежит целевая сигнатура шаблона, было скопировано в связанный элемент с замещением любых параметризуемых элементов, представляемых как формальные параметры шаблона, соответствующими параметризуемыми элементами, указанными как фактические параметры шаблона в связывании шаблона. Однако связанный элемент не содержит явно элементы модели, подразумеваемые развёртыванием шаблонов, с которыми он связан. Тем не менее можно определить развёрнутый связанный элемент, получающийся в результате фактического применения подстановок параметров шаблона для связанного элемента к целевым шаблонам.

Формально развёрнутый связанный элемент для связанного элемента с единственным связыванием шаблона и без элементов помимо тех, что из этого связывания, строится так:

1. Скопировать шаблон, связанный с сигнатурой шаблона, являющейся целью связывания шаблона. Для настоящих целей копия элемента модели — это экземпляр того же метакласса, что и исходный элемент модели, со следующими значениями:

a    значения всех композитных свойств (принадлежащих атрибутов и принадлежащих концов ассоциаций) являются копиями (в том же

смысле) соответствующих значений из исходного элемента;

b    значения всех некомпозитных свойств совпадают с соответствующими значениями из исходного

элемента, за исключением того, что ссылки на элементы, принадлежащие (прямо или косвенно) исходному

элементу, заменяются ссылками на копии этих элементов, созданные как указано выше, а

ссылки на сам исходный элемент заменяются ссылками на копию.

2. Если копия специализирует какие-либо элементы, являющиеся шаблонами, то перенаправить отношения обобщения на эквивалентные связанные элементы для общих элементов, используя то же связывание шаблона. Если копия — операция, у которой есть связанный метод, также являющийся шаблоном, то заменить этот метод эквивалентным связанным элементом, используя то же связывание шаблона.

ПРИМЕЧАНИЕ. Необходимо, чтобы метод шаблонной операции тоже был шаблоном, предположительно с параметрами

шаблона, соответствующими параметрам операции. В частности, параметры шаблона операции, как правило,

используются для параметризации типов параметров операции, но метод операции не ссылается

напрямую на параметры операции, которая его задаёт. Напротив, у метода есть собственный

список ownedParameter, который должен соответствовать списку операции (см. подпункт 13.2). Таким образом, типы

параметров метода нужно шаблонизировать отдельно, чтобы они соответствовали шаблонной параметризации операции.

3. Для каждого элемента, принадлежащего копии прямо или косвенно, заменить любую ссылку на parameteredElement параметра шаблона копии ссылкой на фактический элемент, связанный с параметром в связывании шаблона. Если у фактического элемента есть своё связывание шаблона, то ссылаться на эквивалентный связанный элемент.

4. Удалить из сигнатуры шаблона копии все параметры шаблона, на которые есть ссылки в связывании шаблона. Если это удалило бы все параметры шаблона из сигнатуры шаблона, то удалить сигнатуру шаблона полностью.

Если у связанного элемента более одного связывания шаблона, то для каждого связывания шаблона можно определить свой развёрнутый связанный элемент. Затем общий развёрнутый связанный элемент строится объединением всех развёрнутых связанных элементов, специфичных для отдельных связываний шаблона, с любыми другими элементами, содержащимися в исходном связанном элементе. Как отмечено ранее, то, как выполняется это объединение, зависит от вида связываемого шаблонизируемого элемента.

Включение связанного элемента в модель не требует автоматически, чтобы соответствующий развёрнутый связанный элемент был включён в модель. Однако если развёрнутый связанный элемент, построенный как указано выше, нарушает какие-либо ограничения корректной построенности, то исходный связанный элемент также считается некорректно построенным.

С другой стороны, если связанный элемент предназначен для шаблона пространства имён, то может понадобиться возможность ссылаться на члены связанного элемента, рассматриваемого как само пространство имён. Например, для связанного элемента шаблона класса может понадобиться ссылаться на операции этого класса, например из действия вызова операции.

ПРИМЕЧАНИЕ. Ссылаться на операцию из шаблона недостаточно, так как каждый связанный элемент шаблона класса должен считаться имеющим собственную действующую копию операций шаблона.

Чтобы accommodate такую ситуацию, в модель допускается включать развёрнутый связанный элемент для связанного элемента в дополнение к самому связанному элементу. В этом случае у развёрнутого связанного элемента должна быть зависимость реализации (см. подпункт 7.7) на связанный элемент, который он развёртывает. Развёрнутый связанный элемент должен быть построен (вручную моделировщиком или автоматически инструментом) согласно правилам, приведённым выше. Ссылки, которые затем делаются как обычно из других элементов модели на видимые члены развёрнутого связанного элемента, считаются семантически эквивалентными действующим ссылкам на соответствующие неявные члены исходного связанного элемента. Любые связи, сделанные напрямую к развёрнутому связанному элементу, семантически эквивалентны связям, сделанным к самому связанному элементу.

### 7.3.4 Нотация

Если у шаблонизируемого элемента есть параметры шаблона, на символ шаблонизируемого элемента накладывается маленький пунктирный прямоугольник, обычно в правом верхнем углу нотации (если это возможно). Пунктирный прямоугольник содержит список формальных параметров шаблона. Список параметров не должен быть пустым, хотя он может быть опущен при представлении. Любые другие разделы в нотации шаблонизируемого элемента выглядят как обычно.

Список формальных параметров шаблона может показываться списком через запятую либо по одному формальному параметру шаблона на строку. Общая нотация параметра шаблона — строка, отображаемая в списке параметров шаблона для шаблона: <template-parameter> ::= <template-param-name> [‘:’ <parameter-kind> ] [‘=’ <default>]

где <parameter-kind> — имя метакласса для представляемого элемента. Синтаксис <template-param-name> и <default> зависит от вида параметризуемого элемента для этого параметра шаблона.

Связанный элемент имеет ту же графическую нотацию, что и другие элементы того же вида. Связывание шаблона показывается пунктирной стрелкой с хвостом на связанном элементе и наконечником на шаблоне и ключевым словом «bind». Информация о связывании может отображаться списком подстановок параметров шаблона через запятую: <template-param-substitution> ::= <template-param-name> ‘->’ <actual-template-parameter>

где синтаксис <template-param-name> — имя или полное имя parameteredElement формального параметра шаблона, а вид <actual-template-parameter> зависит от вида параметризуемого элемента для этого параметра шаблона.

Альтернативное представление связываний для связанного элемента — включение информации о связывании в нотацию связанного элемента. Имя связанного элемента расширяется так, чтобы содержать выражения связывания со следующим синтаксисом: [<element-name> ‘:’] <binding-expression> [‘,’ <binding-expression>]* <binding-expression> ::= <template-element-name> ‘<‘ <template-param-substitution> [‘,’<template-param- substitution]*‘>’

а <template-param-substitution> определена, как указано выше.

### 7.4.3 Семантика

#### 7.4.3.1 Пространства имён

Пространство имён даёт контейнер для именованных элементов, которые называются его ownedMembers. Пространство имён может также импортировать именованные элементы из других пространств имён, и в этом случае они вместе с ownedMembers являются членами импортирующего пространства имён. Если член пространства имён с именем N является именованным элементом с именем x, то на этого члена можно ссылаться полным именем вида N::x.

Когда нужно различение, простое имя, не квалифицированное именами пространств имён, может называться неквалифицированным именем. Внутри пространства имён неквалифицированные имена могут использоваться для ссылок на члены этого пространства имён и на внешние имена, которые не скрыты. Внешнее имя — это имя именованного элемента, на который можно ссылаться неквалифицированным именем в непосредственно объемлющем пространстве имён. Внешнее имя скрыто, если только оно не отличимо от всех членов внутреннего пространства имён. (Обсуждение различимости см. ниже в разделе «Именованные элементы».)

Поскольку пространство имён само является именованным элементом, полное имя именованного элемента может включать несколько имён пространств имён, например N1::N2::x.

Ограничения ownedRule пространства имён представляют правила корректной построенности для ограничиваемых элементов (см. подпункт 7.6 об ограничениях). Эти ограничения вычисляются при определении того, корректно ли построены ограничиваемые элементы.

#### 7.4.3.2 Именованные элементы

Именованный элемент — это элемент модели, который может иметь имя. Имя может использоваться для идентификации именованного элемента в пространствах имён, где его имя доступно.

ПРИМЕЧАНИЕ. Имя именованного элемента необязательно, что допускает возможность отсутствия имени (что отличается от пустого имени).

Именованные элементы могут появляться в пространстве имён согласно правилам, задающим, чем один именованный элемент отличим от другого. Правило по умолчанию таково: два члена различимы, если у них разные имена или если у них одинаковые имена, но их метаклассы различны и ни один не является (прямым или косвенным) подклассом другого. Это правило может быть переопределено для конкретных случаев, например для операций, различаемых по сигнатуре (см. подпункт 9.6).

Видимость именованного элемента даёт средство ограничения использования элемента — либо в пространствах имён, либо при доступе к элементу. Она предназначена для использования вместе с механизмами импорта, обобщения и доступа.

Именованный элемент может, помимо явного имени, быть связан со строковым выражением (см. подпункт 8.3), которое может использоваться для задания вычисляемого имени именованного элемента. В шаблоне (см. подпункт 7.3) именованный элемент может иметь связанное строковое выражение, подвыражения которого могут быть параметризуемыми элементами, представляемыми параметрами шаблона. Когда шаблон связывается, представляемые подвыражения замещаются фактическими значениями, подставленными вместо параметров шаблона. Затем значением строкового выражения становится строка, получающаяся конкатенацией значений подвыражений, и она даёт имя именованного элемента. У именованного элемента может быть связано и имя, и nameExpression. В этом случае имя может использоваться как псевдоним именованного элемента, например при ссылке на элемент в выражении ограничения. (Это избавляет от необходимости использовать в текстовой поверхностной нотации строковые выражения, что часто громоздко, хотя и не исключает их.)

#### 7.4.3.3 Упаковываемые элементы и импорт

Упаковываемый элемент — это именованный элемент, который может принадлежать пакету непосредственно (см. пункт 12 о пакетах). Любой такой элемент может служить параметром шаблона (см. подпункт 7.3 о шаблонах).

Импорт элемента — это направленная связь между импортирующим пространством имён и упаковываемым элементом. Она добавляет имя упаковываемого элемента в импортирующее пространство имён. Видимость импорта элемента может быть такой же, как у импортируемого элемента, или более ограниченной.

В случае конфликта имени с внешним именем (элементом, определённым в объемлющем пространстве имён и доступным по его неквалифицированному имени во вложенных пространствах имён) в импортирующем пространстве имён внешнее имя скрывается импортом элемента, и неквалифицированное имя относится к импортированному элементу. К внешнему имени можно обратиться по его полному имени. Импорт пакета — это направленная связь между импортирующим пространством имён и пакетом, указывающая, что импортирующее пространство имён добавляет имена членов пакета в своё пространство имён. Концептуально импорт пакета эквивалентен наличию импорта элемента для каждого отдельного члена импортируемого пространства имён, если только нет

отдельно определённого импорта элемента. Если для элемента есть импорт элемента, он имеет приоритет над возможным импортом того же элемента через импорт пакета.

Если в результате импортов элементов или импортов пакетов в пространство имён были бы импортированы неразличимые элементы, эти элементы не добавляются в импортирующее пространство имён, и их имена должны быть квалифицированы, чтобы их можно было использовать в этом пространстве имён. Если имя импортированного элемента неразличимо с элементом, принадлежащим импортирующему пространству имён, этот элемент не добавляется в импортирующее пространство имён, и его имя должно быть квалифицировано, чтобы его можно было использовать.

Элемент, импортированный открыто, является открытым членом импортирующего пространства имён. Это означает, что если пространство имён — пакет, то импорт пакета его другим пространством имён приведёт к дальнейшему импорту этих открыто импортированных членов в другое пространство имён — в дополнение к открытым ownedMembers пакета.

ПРИМЕЧАНИЕ. Пространство имён не может импортировать само себя и не может импортировать какие-либо из своих собственных ownedMembers. Это означает, что именованный элемент не может приобрести псевдоним в своём владеющем пространстве имён.

### 7.4.4 Нотация

#### 7.4.4.1 Пространства имён

Общей нотации для пространств имён нет. Конкретные виды пространств имён имеют собственную особую нотацию.

Соответствующие инструменты могут по выбору разрешать использовать нотацию «круга с плюсом», определённую в подпункте 12.2.4 для показа принадлежности пакету, также и для показа принадлежности другим видам пространств имён (например, для показа nestedClassifiers и ownedBehaviors классов).

#### 7.4.4.2 Выражения имён

Связанное с именованным элементом nameExpression может показываться двумя способами — в зависимости от того, требуется ли псевдоним. Обе нотации иллюстрируются на рисунке 7.6.

- Без псевдонима: строковое выражение появляется как имя элемента модели.

- С псевдонимом: и строковое выражение, и псевдоним показываются везде, где обычно появляется имя. Псевдоним даётся первым, а строковое выражение — под ним.

В обоих случаях строковое выражение появляется между знаками “$”. Спецификация выражений в UML поддерживает использование в абстрактном синтаксисе альтернативных языков строковых выражений — они должны иметь тип String и могут быть некоторой структурой выражений-операторов с операндами. Нотация для этого обсуждается в подпункте 8.3 о выражениях. В контексте шаблонов подвыражения строкового выражения (обычно строковые литералы), параметризованные в шаблоне, показываются в угловых скобках.

#### 7.4.4.3 Импорт

Импорт пакета или импорт элемента показывается пунктирной стрелкой с открытым наконечником от импортирующего пространства имён к импортируемому пакету или элементу. Ключевое слово «import» показывается рядом с пунктирной стрелкой, если видимость открытая; иначе показывается ключевое слово «access», обозначающее закрытую видимость. Псевдоним может показываться после ключевого слова «import» или под ним. Если импортируемый элемент для импорта элемента — пакет, перед ключевым словом может по выбору стоять “element”, то есть «element import».

Как альтернатива пунктирной стрелке, импорт пакета или импорт элемента можно показать текстом, однозначно идентифицирующим импортируемый пакет или элемент, в фигурных скобках — под именем пространства имён или после него. Текстовый синтаксис импорта пакета: ‘{import ’ <qualified-name> ‘}’ | ‘{access ’ <qualified-name> ‘}’ Текстовый синтаксис импорта элемента: ‘{element import’ <qualified-name> ‘}’ | ‘{element access ’ <qualified-name> ‘}’

По выбору может показываться и псевдоним, если он есть: ‘{element import ’ <qualified-name> ‘ as ’ <alias> ‘}’ | ‘{element access ’ <qualified-name> ‘as’ <alias> ‘}’

#### 7.5.3.1 Типы и типизированные элементы

Тип задаёт набор допустимых значений, называемых экземплярами типа. В зависимости от вида типа экземпляры типа могут создаваться и уничтожаться во времени. Однако правила того, что составляет экземпляр типа, остаются фиксированными определением этого типа. Все типы в UML — классификаторы (см. пункт 9).

Типизированный элемент — это именованный элемент, который некоторым образом представляет конкретные значения. В зависимости от вида типизированного элемента фактические представляемые им значения могут изменяться во времени. Примеры видов типизированного элемента включают спецификацию значения, непосредственно задающую набор значений (см. пункт 8), и структурную характеристику, представляющую значения, хранимые как часть структуры экземпляров владеющего ею классификатора (см. подпункт 9.4).

Если у типизированного элемента есть связанный тип, то любое значение, представляемое типизированным элементом (в любой момент времени), должно быть экземпляром заданного типа. Типизированный элемент без связанного типа может представлять любое значение.

#### 7.5.3.2 Кратности

Элемент кратности — это элемент, который может быть создан некоторым образом для представления набора значений. В зависимости от вида элемента кратности значения в наборе могут изменяться во времени. Примеры видов элементов кратности включают структурную характеристику, имеющую значения в контексте экземпляра владеющего ею классификатора (см. подпункт 9.4), и переменную, имеющую значения в контексте выполнения деятельности (см. подпункт 15.2).

Мощность набора — число значений, содержащихся в этом наборе. Кратность элемента кратности задаёт допустимые мощности представляемого им набора. Кратность — это ограничение на мощность, которая не должна быть меньше нижней границы и не должна быть больше верхней границы, заданных для кратности (если только кратность не неограниченна, и тогда на верхнюю границу ограничения нет). Нижняя и верхняя границы кратности элемента кратности задаются спецификациями значения (см. пункт 8), которые должны вычисляться в целое значение для lowerBound и в значение UnlimitedNatural для

upperBound (см. пункт 21 о примитивных типах). Элемент кратности неограничен, если его upperBound имеет значение UnlimitedNatural «неограниченно» (“*”). Элемент кратности многозначен, если его upperBound больше 1 (включая неограниченность). Элемент кратности, не являющийся многозначным, может представлять не более одного значения.

Элемент кратности может задавать кратность, обе границы которой равны нулю. Это ограничивает допустимую мощность нулём, то есть требует, чтобы создание экземпляра этого элемента не содержало значений. Это полезно в контексте обобщений (см. подпункт 9.2) для ограничения мощностей более общего классификатора. Это применимо (но не ограничиваясь этим) к переопределению свойств, существующих в более общих классификаторах.

Если элемент кратности задан как упорядоченный (то есть isOrdered истинно), то набор значений в создании экземпляра этого элемента упорядочен. Эта упорядоченность подразумевает, что есть отображение положительных целых на элементы набора значений. Если элемент кратности не многозначен, значение isOrdered не имеет семантического эффекта.

Если элемент кратности задан как неупорядоченный (то есть isOrdered ложно), то никаких предположений о порядке значений в создании экземпляра этого элемента делать нельзя.

Если элемент кратности задан как уникальный (то есть isUnique истинно), то набор значений в создании экземпляра этого элемента должен быть уникальным. То есть никакие два значения в наборе не могут быть равны, причём равенство объектов (экземпляров классов) основано на идентичности объектов, а равенство значений данных (экземпляров типов данных) и экземпляров сигналов — на значении (см. также подпункты 10.2, 10.3 и 11.4 о типах данных, сигналах и классах соответственно). Если элемент кратности не многозначен, значение isUnique не имеет семантического эффекта.

В совокупности свойства isOrdered и isUnique позволяют задать, что набор значений в создании экземпляра элемента кратности относится к одному из четырёх видов. Таблица 7.1 показывает традиционные названия, данные каждому из этих видов наборов.

### 7.5.4 Нотация

#### 7.5.4.1 Элемент кратности

Конкретная нотация элемента кратности определена для каждого конкретного вида элемента кратности. В общем случае нотация включает спецификацию кратности, которая показывается текстовой строкой, содержащей границы кратности, и нотацию для показа необязательных указаний упорядоченности и уникальности. Границы кратности могут показываться в формате: <lower-bound> ‘..’ <upper-bound>

где <lower-bound> — спецификация значения типа Integer, а <upper-bound> — спецификация значения типа UnlimitedNatural. Символ звёздочки (*) используется в составе спецификации кратности для представления неограниченной верхней границы.

Если кратность связана с элементом кратности, нотация которого — текстовая строка (например, атрибут), строка кратности помещается в квадратные скобки ([ ]) как часть этой текстовой строки.

Если кратность связана с элементом кратности, appearing как символ (например, конец ассоциации), строка кратности отображается без квадратных скобок и может размещаться рядом с символом элемента.

Если нижняя граница равна верхней, альтернативная нотация — использовать строку, содержащую только верхнюю границу. Например, “1” семантически эквивалентно кратности “1..1”. Кратность с нижней границей ноль и не указанной верхней границей может использовать альтернативную нотацию с одной звёздочкой “*” вместо кратности “0..*”.

Конкретная нотация для указаний упорядоченности и уникальности может различаться в зависимости от конкретного вида элемента кратности. Общая нотация — использовать текстовую аннотацию, содержащую “ordered” или “unordered” для задания упорядоченности, и “unique” или “nonunique” для задания уникальности.

Следующая BNF определяет общий синтаксис строки кратности, включая указатели порядка и уникальности: <multiplicity> ::= <multiplicity-range> [ [ ‘{‘ <order-designator> [‘,’ <uniqueness-designator> ] ‘}’ ] | [ ‘{‘ <uniqueness-designator> [‘,’ <order-designator> ] ‘}’ ] ] <multiplicity-range> ::= [ <lower> ‘..’ ] <upper> <lower> ::= <value-specification> <upper> ::= <value-specification> <order-designator> ::= ‘ordered’ | ‘unordered’ <uniqueness-designator> ::= ‘unique’ | ‘nonunique’

О текстовой нотации спецификаций значения см. также пункт 8.

## 7.6 Ограничения

### 7.6.1 Краткое описание

Ограничение — это утверждение, указывающее ограничение, которое должно удовлетворяться любой допустимой реализацией модели, содержащей это ограничение. Ограничение присоединено к набору constrainedElements и представляет дополнительную семантическую информацию об этих элементах.

### 7.6.3 Семантика

Спецификация ограничения задаётся спецификацией значения (см. пункт 8) типа Boolean. При вычислении спецификации можно ссылаться на constrainedElements ограничения, а также на контекст ограничения.

В общем случае существует много возможных видов контекста для ограничения. Контекст ограничения определяет, когда вычисляется спецификация ограничения. Например, ограничение, являющееся предусловием операции, вычисляется в начале вызова операции, а ограничение, являющееся постусловием, вычисляется по завершении вызова (см. подпункт 9.6 об операциях).

Ограничение вычисляется вычислением его спецификации. Если спецификация вычисляется как истинная, то ограничение в этот момент удовлетворено. Если спецификация вычисляется как ложная, то ограничение не удовлетворено, и реализация модели, в которой происходит вычисление, недопустима.

### 7.6.4 Нотация

Некоторые виды ограничений предопределены в UML, другие могут определяться пользователем. Спецификация определяемого пользователем ограничения часто выражается текстовой строкой на некотором языке, синтаксис и истолкование которой определены этим языком. В некоторых ситуациях может подойти формальный язык (например, OCL) или язык программирования (например, Java), в других может использоваться естественный язык. Такая спецификация может представляться непрозрачным выражением с соответствующими языком и телом (см. подпункт 8.3). Затем ограничение может нотироваться текстуально в фигурных скобках ({}) согласно следующей BNF: <constraint> ::= ‘{‘ [ <name> ‘:’ ] <boolean-expression> ‘ }’

где <name> — имя ограничения, а <boolean-expression> — соответствующая текстовая нотация спецификации ограничения. В самом общем случае строка ограничения помещается в символ примечания и присоединяется к каждому из символов constrainedElements пунктирными линиями. (Пример см. на рисунке 7.14.)

Для ограничения, применимого к одному constrainedElement (например, к одному классу или одной ассоциации), строка ограничения может размещаться непосредственно рядом с символом constrainedElement, предпочтительно рядом с именем, если оно есть. Инструмент должен давать возможность определить constrainedElement. Для элемента, нотация которого — текстовая строка (например, атрибут и т. д.), строка ограничения может следовать за текстовой строкой элемента. Тогда элемент, аннотированный таким образом, — единственный constrainedElement ограничения. (Рисунок 7.15 показывает строку ограничения, следующую за атрибутом внутри символа класса.) Для ограничения, применимого к двум элементам (например, к двум классам или двум ассоциациям), ограничение может показываться пунктирной линией между элементами с меткой — строкой ограничения. (Пример см. на рисунке 7.16.) Если ограничение показано пунктирной линией между двумя элементами, то на одном конце может размещаться наконечник. Направление стрелки — существенная информация внутри ограничения. Элемент у хвоста стрелки отображается на

первую позицию, а элемент у головы стрелки — на вторую позицию в наборе constrainedElement.

Для трёх или более путей одного вида (например, путей обобщения или путей ассоциаций) строка ограничения может присоединяться к пунктирной линии, пересекающей все пути.

### 7.7.1 Краткое описание

### 7.7.3 Семантика

#### 7.7.3.1 Зависимость

Зависимость означает, что семантика клиентов не полна без поставщиков. Наличие отношений зависимости в модели не имеет никаких семантических следствий во время выполнения. Вся семантика даётся в терминах именованных элементов, участвующих в отношении, а не в терминах их экземпляров.

#### 7.7.3.2 Использование

Использование — это зависимость, в которой один именованный элемент требует другого именованного элемента (или набора именованных элементов) для своей полной реализации или работы. Использование не задаёт, как клиент использует поставщика, кроме самого факта, что поставщик используется определением или реализацией клиента.

#### 7.7.3.3 Абстракция

Абстракция — это зависимость, связывающая два именованных элемента или набора именованных элементов, представляющих одно и то же понятие на разных уровнях абстракции или с разных точек зрения. Отношение может быть задано как отображение между поставщиками и клиентами. В зависимости от конкретного стереотипа абстракции отображение может быть формальным или неформальным и может быть однонаправленным или двунаправленным. Абстракция имеет предопределённые стереотипы («Derive», «Refine» и «Trace»), определённые в стандартном профиле (см. пункт 22). Если у абстракции более одного клиента, поставщик отображается в набор клиентов как в группу. Например, класс уровня анализа мог бы быть разбит на несколько классов уровня проектирования. Ситуация аналогична, если поставщиков более одного.

#### 7.7.3.4 Реализация

Реализация — это специализированная зависимость-абстракция между двумя наборами именованных элементов, один из которых представляет спецификацию (поставщик), а другой — реализацию этой спецификации (клиент). Реализация может использоваться для моделирования пошагового уточнения, оптимизаций, преобразований, шаблонов, синтеза моделей, композиции каркасов и т. д. Реализация означает, что набор клиентов является реализацией набора поставщиков, который служит

спецификацией. Смысл «реализации» строго не определён, а скорее подразумевает более уточнённую или развитую форму в некотором контексте моделирования. Можно задать отображение между элементами спецификации и реализации, хотя оно не обязательно вычислимо.

### 7.7.4 Нотация

Зависимость показывается пунктирной стрелкой между двумя элементами модели. Элемент модели у хвоста стрелки (клиент) зависит от элемента модели у наконечника (поставщик). Стрелка может быть помечена необязательным ключевым словом или стереотипом и необязательным именем (см. рисунок 7.18).

### 7.8.8 MultiplicityElement (элемент кратности) [Abstract Class]

#### 7.8.8.1 Описание

Кратность — это определение замкнутого интервала неотрицательных целых, начинающегося с нижней границы и заканчивающегося (возможно бесконечной) верхней границей. Элемент кратности содержит эту информацию, чтобы задать допустимые мощности для создания экземпляра элемента.

#### 7.8.8.2 Диаграммы

Типы, деятельности, структурированные классификаторы, характеристики, действия

#### 7.8.8.3 Обобщения

Element

#### 7.8.8.4 Специализации

Variable, ConnectorEnd, Parameter, StructuralFeature, Pin

#### 7.8.8.5 Атрибуты

- isOrdered : Boolean [1..1] = false

  Для многозначной кратности этот атрибут задаёт, являются ли значения в создании экземпляра этого элемента кратности последовательно упорядоченными.

- isUnique : Boolean [1..1] = true

  Для многозначной кратности этот атрибут задаёт, являются ли значения в создании экземпляра этого элемента кратности уникальными.

- /lower : Integer [1..1]

  нижняя граница интервала кратности.

- /upper : UnlimitedNatural [1..1]

  верхняя граница интервала кратности.

#### 7.8.8.6 Концы ассоциаций

- ♦ lowerValue : ValueSpecification [0..1]{subsets Element::ownedElement} (opposite A_lowerValue_owningLower::owningLower) спецификация нижней границы для этой кратности.

- ♦ upperValue : ValueSpecification [0..1]{subsets Element::ownedElement} (opposite A_upperValue_owningUpper::owningUpper) спецификация верхней границы для этой кратности.

#### 7.8.8.7 Операции

- compatibleWith(other : MultiplicityElement) : Boolean операция compatibleWith принимает другую кратность как вход. Она возвращает истину, если другая кратность шире или совпадает с данной.

  ```ocl
  body: (other.lowerBound() <= self.lowerBound()) and ((other.upperBound() = *) or
  (self.upperBound() <= other.upperBound()))
  ```

- includesMultiplicity(M : MultiplicityElement) : Boolean запрос includesMultiplicity() проверяет, включает ли эта кратность все мощности, допускаемые указанной кратностью.

  ```ocl
  pre: self.upperBound()->notEmpty() and self.lowerBound()->notEmpty() and M.upperBound()-
  >notEmpty() and M.lowerBound()->notEmpty()
  ```

  ```ocl
  body: (self.lowerBound() <= M.lowerBound()) and (self.upperBound() >= M.upperBound())
  ```

- is(lowerbound : Integer, upperbound : UnlimitedNatural) : Boolean операция is определяет, равны ли верхняя и нижняя границы диапазонов заданным.

  ```ocl
  body: lowerbound = self.lowerBound() and upperbound = self.upperBound()
  ```

- isMultivalued() : Boolean запрос isMultivalued() проверяет, имеет ли эта кратность верхнюю границу больше единицы.

  ```ocl
  pre: upperBound()->notEmpty()
  ```

  ```ocl
  body: upperBound() > 1
  ```

- lower() : Integer [0..1] производный атрибут lower должен равняться lowerBound.

  ```ocl
  body: lowerBound()
  ```

- lowerBound() : Integer [1..1] запрос lowerBound() возвращает нижнюю границу кратности как целое, а именно integerValue от lowerValue, если оно задано, и 1 иначе.

  ```ocl
  body: if (lowerValue=null or lowerValue.integerValue()=null) then 1 else
  lowerValue.integerValue() endif
  ```

- upper() : UnlimitedNatural [0..1] производный атрибут upper должен равняться upperBound.

  ```ocl
  body: upperBound()
  ```

- upperBound() : UnlimitedNatural [1..1] запрос upperBound() возвращает верхнюю границу кратности для ограниченной кратности как неограниченное натуральное, а именно unlimitedValue от upperValue, если оно задано, и 1 иначе.

  ```ocl
  body: if (upperValue=null or upperValue.unlimitedValue()=null) then 1 else
  upperValue.unlimitedValue() endif
  ```

#### 7.8.8.8 Ограничения

- **upper_ge_lower**

  Верхняя граница должна быть больше или равна нижней.

  ```ocl
  inv: upperBound() >= lowerBound()
  ```

- **lower_ge_0**

  Нижняя граница должна быть неотрицательным целым литералом.

  ```ocl
  inv: lowerBound() >= 0
  ```

- **value_specification_no_side_effects**

  Если для lowerValue или upperValue используется нелитеральная спецификация значения, то её вычисление не должно иметь побочных эффектов.

  Не выражается в OCL

- **value_specification_constant**

  Если для lowerValue или upperValue используется нелитеральная спецификация значения, то эта спецификация должна быть константным выражением.

  Не выражается в OCL

- **lower_is_integer**

  Если она не пуста, то lowerValue должно иметь целое значение.

  ```ocl
  inv: lowerValue <> null implies lowerValue.integerValue() <> null
  ```

- **upper_is_unlimitedNatural**

  Если оно не пусто, то upperValue должно иметь значение UnlimitedNatural.

  ```ocl
  inv: upperValue <> null implies upperValue.unlimitedValue() <> null
  ```

состояний, взаимодействия, сообщения, линии жизни, вхождения, фрагменты, информационные потоки, развёртывания,

#### 7.8.9.4 Специализации

#### 7.8.9.5 Атрибуты

- name : String [0..1]

  имя именованного элемента.

- /qualifiedName : String [0..1]

  имя, позволяющее идентифицировать именованный элемент в иерархии вложенных пространств имён. Оно строится из имён содержащих пространств имён, начиная с корня иерархии и заканчивая именем самого именованного элемента.

- visibility : VisibilityKind [0..1]

  определяет, виден ли именованный элемент вне владеющего пространства имён и как.

#### 7.8.9.6 Концы ассоциаций

- /clientDependency : Dependency [0..*]{subsets A_source_directedRelationship::directedRelationship} (opposite Dependency::client) указывает зависимости, которые ссылаются на этот именованный элемент как на клиента.

- ♦ nameExpression : StringExpression [0..1]{subsets Element::ownedElement} (opposite A_nameExpression_namedElement::namedElement) строковое выражение, используемое для задания имени этого именованного элемента.

- /namespace : Namespace [0..1]{union, subsets A_member_memberNamespace::memberNamespace, subsets Element::owner} (opposite Namespace::ownedMember) задаёт пространство имён, которому принадлежит именованный элемент.

#### 7.8.9.7 Операции

- allNamespaces() : Namespace [0..*]{ordered} запрос allNamespaces() даёт последовательность пространств имён, в которые вложен именованный элемент, двигаясь наружу.

  ```ocl
  body: if owner.oclIsKindOf(TemplateParameter) and
  owner.oclAsType(TemplateParameter).signature.template.oclIsKindOf(Namespace) then
  let enclosingNamespace : Namespace =
  owner.oclAsType(TemplateParameter).signature.template.oclAsType(Namespace) in
  enclosingNamespace.allNamespaces()->prepend(enclosingNamespace)
  else
  if namespace->isEmpty()
  then OrderedSet{}
  else
  namespace.allNamespaces()->prepend(namespace)
  endif
  endif
  ```

- allOwningPackages() : Package [0..*] запрос allOwningPackages() возвращает множество всех объемлющих пространств имён этого именованного элемента, двигаясь наружу, которые являются пакетами, вплоть до первого такого пространства имён, не являющегося пакетом (не включая его).

  ```ocl
  body: if namespace.oclIsKindOf(Package)
  then
  let owningPackage : Package = namespace.oclAsType(Package) in
  owningPackage->union(owningPackage.allOwningPackages())
  else
  null
  endif
  ```

- isDistinguishableFrom(n : NamedElement, ns : Namespace) : Boolean запрос isDistinguishableFrom() определяет, могут ли два именованных элемента логически сосуществовать в одном пространстве имён. По умолчанию два именованных элемента различимы, если (а) их типы таковы, что ни один не является видом другого, или (б) у них разные имена.

  ```ocl
  body: (self.oclIsKindOf(n.oclType()) or n.oclIsKindOf(self.oclType())) implies
  ns.getNamesOfMember(self)->intersection(ns.getNamesOfMember(n))->isEmpty()
  ```

- qualifiedName() : String когда у именованного элемента есть имя и у всех его содержащих пространств имён есть имена, qualifiedName строится из имени именованного элемента и имён содержащих пространств имён.

  ```ocl
  body: if self.name <> null and self.allNamespaces()->select( ns | ns.name=null )->isEmpty()
  then
  self.allNamespaces()->iterate( ns : Namespace; agg: String = self.name |
  ns.name.concat(self.separator()).concat(agg))
  else
  null
  endif
  ```

- separator() : String запрос separator() даёт строку, используемую для разделения имён при построении qualifiedName.

  ```ocl
  body: '::'
  ```

- clientDependency() : Dependency [0..*]

  ```ocl
  body: Dependency.allInstances()->select(d | d.client->includes(self))
  ```

#### 7.8.9.8 Ограничения

- **visibility_needs_ownership**

  Если именованный элемент принадлежит чему-либо иному, чем пространство имён, у него нет видимости. Элемент, не принадлежащий ничему (и потому обязанный быть пакетом, так как это единственный вид именованного элемента, переопределяющий mustBeOwned()), может иметь видимость.

  ```ocl
  inv: (namespace = null and owner <> null) implies visibility = null
  ```

- **has_qualified_name**

  Когда есть имя и у всех содержащих пространств имён есть имена, qualifiedName строится из имени именованного элемента и имён содержащих пространств имён.

  ```ocl
  inv: (name <> null and allNamespaces()->select(ns | ns.name = null)->isEmpty()) implies
  qualifiedName = allNamespaces()->iterate( ns : Namespace; agg: String = name |
  ns.name.concat(self.separator()).concat(agg))
  ```

- **has_no_qualified_name**

  Если имени нет или у одного из содержащих пространств имён нет имени, qualifiedName отсутствует.

  ```ocl
  inv: name=null or allNamespaces()->select( ns | ns.name=null )->notEmpty() implies
  qualifiedName = null
  ```

### 7.8.10 Namespace (пространство имён) [Abstract Class]

#### 7.8.10.1 Описание

Пространство имён — это элемент модели, который владеет набором именованных элементов, идентифицируемых по имени, и/или импортирует его.

#### 7.8.10.2 Диаграммы

Пространства имён, ограничения, поведенческие машины состояний, пакеты, фрагменты, классификаторы, характеристики, структурированные

действия

#### 7.8.10.3 Обобщения

NamedElement

#### 7.8.10.4 Специализации

Region, State, Transition, Package, InteractionOperand, BehavioralFeature, Classifier, StructuredActivityNode

#### 7.8.10.5 Концы ассоциаций

- ♦ elementImport : ElementImport [0..*]{subsets Element::ownedElement, subsets A_source_directedRelationship::directedRelationship} (opposite ElementImport::importingNamespace) ссылается на импорты элементов, принадлежащие пространству имён.

- /importedMember : PackageableElement [0..*]{subsets Namespace::member} (opposite A_importedMember_namespace::namespace) ссылается на упаковываемые элементы, которые пространство имён импортирует.

- /member : NamedElement [0..*]{union, subsets Namespace::member} (opposite A_member_memberNamespace::memberNamespace)

  ссылается на члены пространства имён — как принадлежащие ему, так и импортированные.

- ♦ ownedMember : NamedElement [0..*]{ordered, subsets Element::ownedElement} (opposite NamedElement::namespace) ссылается на элементы, принадлежащие пространству имён.

- ♦ ownedRule : Constraint [0..*]{subsets Namespace::member, subsets Element::ownedElement} (opposite Constraint::context) задаёт ограничения, принадлежащие пространству имён, — правила корректной построенности его элементов.

- ♦ packageImport : PackageImport [0..*]{subsets Element::ownedElement, subsets A_source_directedRelationship::directedRelationship} (opposite PackageImport::importingNamespace) ссылается на импорты пакетов, принадлежащие пространству имён.

#### 7.8.10.6 Операции

- excludeCollisions(imps : PackageImport [0..*]) : PackageableElement [0..*] запрос excludeCollisions() принимает набор импортов пакетов и отбрасывает те импортированные элементы, имена которых неразличимы.

  ```ocl
  body: imps->reject(imp1      | imps->exists(imp2 | not imp1.isDistinguishableFrom(imp2, self)))
  ```

- getNamesOfMember(element : NamedElement) : String [0..*] запрос getNamesOfMember() даёт набор имён, под которыми элемент известен в пространстве имён.

  ```ocl
  body: if self.ownedMember ->includes(element)
  then Set{element.name}
  else let elementImports : Set(ElementImport) = self.elementImport->select(ei |
  ei.importedElement = element) in
  if elementImports->notEmpty()
  then
  elementImports->collect(el | el.getName())->asSet()
  else
  self.packageImport->select(pi |
  pi.importedPackage.visibleMembers().oclAsType(NamedElement)->includes(element))-> collect(pi
  | pi.importedPackage.getNamesOfMember(element))->asSet()
  endif
  endif
  ```

- importMembers(imps : PackageImport [0..*]) : PackageableElement [0..*] запрос importMembers() возвращает упаковываемые элементы, импортированные в это пространство имён импортами пакетов, с учётом правил исключения совпадений.

  ```ocl
  body: self.excludeCollisions(imps)->select(imp | self.ownedMember->forAll(mem |
  imp.isDistinguishableFrom(mem, self)))
  ```

- importedMember() : PackageableElement [0..*] вывод для Namespace::/importedMember

  ```ocl
  body: self.importMembers(elementImport.importedElement->asSet()-
  >union(packageImport.importedPackage->collect(p | p.visibleMembers()))->asSet())
  ```

- membersAreDistinguishable() : Boolean запрос membersAreDistinguishable() определяет, различимы ли все члены этого пространства имён.

  ```ocl
  body: member->forAll( memb |
  member->excluding(memb)->forAll(other |
  memb.isDistinguishableFrom(other, self)))
  ```

#### 7.8.10.7 Ограничения

- **members_distinguishable**

  Все члены пространства имён различимы внутри него.

  ```ocl
  inv: membersAreDistinguishable()
  ```

- **cannot_import_self**

  Пространство имён не может иметь импорт пакета самого себя.

  ```ocl
  inv: packageImport.importedPackage.oclAsType(Namespace)->excludes(self)
  ```

- **cannot_import_ownedMembers**

  Пространство имён не может иметь импорт элемента на один из своих ownedMembers.

  ```ocl
  inv: elementImport.importedElement.oclAsType(Element)->excludesAll(ownedMember)
  ```

### 7.8.11 PackageImport (импорт пакета) [Class]

#### 7.8.11.1 Описание

Импорт пакета — это связь, импортирующая все не закрытые члены пакета в пространство имён, которому принадлежит импорт пакета, так что на эти элементы можно ссылаться по их неквалифицированным именам в импортирующем пространстве имён.

#### 7.8.11.2 Диаграммы

Пространства имён, профили

#### 7.8.11.3 Обобщения

DirectedRelationship

#### 7.8.11.4 Атрибуты

- visibility : VisibilityKind [1..1] = public

  задаёт видимость импортируемых упаковываемых элементов внутри импортирующего пространства имён, то есть будут ли импортированные элементы в свою очередь видимы другим пространствам имён. Если импорт пакета открытый, импортированные элементы будут видимы вне импортирующего пространства имён, а если закрытый — нет.

#### 7.8.11.5 Концы ассоциаций

- importedPackage : Package [1..1]{subsets DirectedRelationship::target} (opposite A_importedPackage_packageImport::packageImport) задаёт пакет, чьи члены импортируются в пространство имён.

- importingNamespace : Namespace [1..1]{subsets DirectedRelationship::source, subsets Element::owner} (opposite Namespace::packageImport) задаёт пространство имён, которое импортирует члены из пакета.

#### 7.8.11.6 Ограничения

- **public_or_private**

  Видимость импорта пакета — либо public, либо private.

  ```ocl
  inv: visibility = VisibilityKind::public or visibility = VisibilityKind::private
  ```

#### 7.8.16.1 Описание

Связывание шаблона — это направленная связь между шаблонизируемым элементом и шаблоном. Связывание шаблона задаёт подстановки параметров шаблона фактических параметров вместо формальных параметров шаблона.

#### 7.8.16.2 Диаграммы

- ♦ parameterSubstitution : TemplateParameterSubstitution [0..*]{subsets Element::ownedElement} (opposite TemplateParameterSubstitution::templateBinding) подстановки параметров шаблона, принадлежащие этому связыванию шаблона.

- signature : TemplateSignature [1..1]{subsets DirectedRelationship::target} (opposite A_signature_templateBinding::templateBinding) сигнатура шаблона для шаблона, являющегося целью этого связывания шаблона.

  ```ocl
  inv: parameterSubstitution->forAll(b | signature.parameter->includes(b.formal))
  ```

- **one_parameter_substitution**

  Связывание шаблона содержит не более одной подстановки параметра шаблона для каждого формального параметра шаблона целевой сигнатуры шаблона.

  ```ocl
  inv: signature.parameter->forAll(p | parameterSubstitution->select(b | b.formal = p)->size()
  <= 1)
  ```

  ```ocl

  parameter.ownedParameteredElement->asSet())
  ```

- **unique_parameters**

  Имена параметров сигнатуры шаблона уникальны.

  ```ocl
  inv: parameter->forAll( p1, p2 | (p1 <> p2 and
  p1.parameteredElement.oclIsKindOf(NamedElement) and
  p2.parameteredElement.oclIsKindOf(NamedElement) ) implies
  p1.parameteredElement.oclAsType(NamedElement).name <>
  p2.parameteredElement.oclAsType(NamedElement).name)
  ```

### 7.8.23 Usage (использование) [Class]

#### 7.8.23.1 Описание

Использование — это зависимость, в которой элемент-клиент требует элемент-поставщик (или набор элементов) для своей полной реализации или работы.

#### 7.8.23.2 Диаграммы

#### 7.8.23.3 Обобщения

Dependency

### 7.8.24 VisibilityKind (вид видимости) [Enumeration]

#### 7.8.24.1 Описание

VisibilityKind — тип-перечисление, определяющее литералы для определения видимости элементов в модели.

#### 7.8.24.2 Диаграммы

- Пространства имён

#### 7.8.24.3 Литералы

- **public**

  Именованный элемент с видимостью public виден всем элементам, которые могут обращаться к содержимому владеющего им пространства имён.

- **private**

  Именованный элемент с видимостью private виден только внутри владеющего им пространства имён.

- **protected**

  Именованный элемент с видимостью protected виден элементам, имеющим отношение обобщения к владеющему им пространству имён.

- **package**

  Именованный элемент с видимостью package виден всем элементам в пределах ближайшего объемлющего пакета (при условии что другие владеющие элементы имеют надлежащую видимость). Вне ближайшего объемлющего пакета именованный элемент, помеченный как имеющий видимость package, не виден. Помечать видимостью package можно только именованные элементы, не принадлежащие пакетам.
