# 8 Значения

> **UML 2.5.1** (formal/2017-12-05) · Раздел 8 · печатные стр. 69–98 · PDF стр. 111–140

## 8.1 Краткое описание

В этом пункте описывается спецификация значений. В общем случае спецификация значения — это элемент модели, который семантически считается дающим ноль или более значений. Тип и число значений должны быть подходящими для контекста, в котором используется спецификация значения (как определено ограничениями, заданными в этом контексте).

Следующие подпункты описывают различные виды спецификаций значения, доступные в UML.

## 8.2 Литералы

### 8.2.1 Краткое описание

Литеральная спецификация — это спецификация значения, задающая литеральное значение. Для каждого из стандартных примитивных типов UML существует свой вид литеральной спецификации с соответствующей текстовой литеральной нотацией, плюс литерал «null», представляющий «отсутствие значения».

### 8.2.2 Абстрактный синтаксис

```text
                                           TypedElement               PackageableElement
                                                       ValueSpecification
                                                       LiteralSpecification
    LiteralNull                       LiteralInteger                          LiteralUnlimitedNatural
                                  + value : Integer = 0                     + value : UnlimitedNatural = 0
                  LiteralString                           LiteralBoolean                                      LiteralReal
            + value : String [0..1]                 + value : Boolean = false                                + value : Real
Figure 8.1 Literals
```

### 8.2.3 Семантика

Существует шесть видов литеральных спецификаций:

1. Литерал null (LiteralNull) предназначен для явного моделирования отсутствия значения. В контексте элемента кратности с нижней границей кратности 0 это соответствует пустому множеству (то есть множеству без значений). Он эквивалентен указанию отсутствия значений для элемента.

2. Строковый литерал (LiteralString) задаёт постоянное значение примитивного типа String. Хотя строка задаётся как последовательность символов, строковые значения в UML считаются примитивными, поэтому их внутренняя структура не задаётся в составе семантики UML.

3. Целочисленный литерал (LiteralInteger) задаёт постоянное значение примитивного типа Integer.

4. Логический литерал (LiteralBoolean) задаёт постоянное значение примитивного типа Boolean.

5. Литерал неограниченного натурального (LiteralUnlimitedNatural) задаёт постоянное значение примитивного типа UnlimitedNatural.

6. Вещественный литерал (LiteralReal) задаёт постоянное значение примитивного типа Real.

О дальнейшем обсуждении стандартных примитивных типов UML см. также пункт 21.

### 8.2.4 Нотация

Литеральные спецификации нотируются текстуально.

- Нотация литерала null зависит от места его использования. Часто он появляется как слово “null”. Другие нотации описаны в других местах для конкретных применений.

- Строковый литерал показывается как последовательность символов в двойных кавычках. Строковое значение — это последовательность символов без кавычек. Используемый набор символов не задан.

- Целочисленный литерал показывается как последовательность цифр, представляющая десятичную запись целого значения.

- Логический литерал показывается либо словом “true”, либо словом “false” в соответствии со своим значением.

- Литерал неограниченного натурального показывается либо последовательностью цифр, либо звёздочкой (*), где звёздочка обозначает неограниченно. Отметим, что «неограниченно» обозначает отсутствие предела у значения некоторого элемента (например, верхней границы кратности), а не значение «бесконечность».

- Вещественный литерал показывается в десятичной или научной нотации. Десятичная нотация состоит из необязательного знака (+/-), за которым следуют ноль или более цифр, затем необязательно точка (.) и одна или более цифр. Научная нотация состоит из десятичной нотации, за которой следует буква “e” или “E” и показатель степени, состоящий из необязательного знака и одной или более цифр. Научная нотация выражает вещественное число, равное указанному десятичной нотацией перед показателем, умноженному на 10 в степени показателя.

  Эта нотация задаётся следующими правилами EBNF: <natural-literal> ::= ('0'..'9')+ <decimal-literal> ::= ['+' | '-' ] <natural-literal> | ['+' | '-' ] [<natural-literal>] '.' <natural-literal> <real-literal> ::= <decimal-literal> [ ('e' | 'E') ['+' | '-' ] <natural-literal> ]

## 8.3 Выражения

### 8.3.1 Краткое описание

Выражения — это спецификации значения, задающие значения, получающиеся в результате вычисления.

### 8.3.2 Абстрактный синтаксис

```text
                    {ordered, subsets ownedElement}
                                           + operand
                                                              ValueSpecification
                                                         *
                                                                                       OpaqueExpression
                       0..1            Expression                             + body : String [*] {ordered, nonunique}
              + expression         + symbol : String [0..1]                   + language : String [*] {ordered}
          {subsets owner}                                       + opaqueExpression *                           + opaqueExpression
                                                                                                           *
                    {subsets owner}
                 + owningExpression
                                   0..1                                                                        {readOnly}
                                                                         + behavior   0..1              0..1   + /result
                              *      StringExpression
                                                                               Behavior                 Parameter
                + subExpression
   {ordered, subsets ownedElement}
                                  TemplateableElement
Figure 8.2 Expressions
```

### 8.3.3 Семантика

#### 8.3.3.1 Выражения

Выражение задаётся древовидной структурой. Каждый узел этой древовидной структуры состоит из символа и необязательного набора операндов. Если операндов нет, выражение представляет терминальный узел. Если операнды есть, выражение представляет оператор, заданный символом, применённый к этим операндам.

Выражение вычисляется так: сначала вычисляется каждый из его операндов, затем выполняется операция, обозначенная символом выражения, над полученными значениями операндов. Однако фактическое истолкование символа зависит от контекста использования выражения, и настоящая спецификация не даёт никаких стандартных определений символов. Соответствующий инструмент может определять конкретный набор символов, для которых он даёт истолкования, либо просто трактовать все выражения как неистолкованные.

#### 8.3.3.2 Строковые выражения

Строковое выражение (StringExpression) — это выражение, задающее строковое значение, получаемое конкатенацией списка подстрок. Подстроки задаются либо списком операндов-литералов строк, либо списком подвыражений-строковых выражений (но смешивать эти два способа не разрешается). Строковое значение строкового выражения получается конкатенацией по порядку строковых значений либо операндов, либо подвыражений — в зависимости от того, что задано.

Строковые выражения предназначены для задания имён именованных элементов в контексте шаблонов. Как всё строковое выражение, так и одно или несколько его подвыражений могут использоваться как параметризуемые элементы параметров шаблона, что позволяет параметризовать имя именованного элемента внутри шаблона. Дальнейшее обсуждение этого см. в семантике именованных элементов в подпункте 7.4.3.

#### 8.3.3.3 Непрозрачные выражения

Непрозрачное выражение (OpaqueExpression) задаёт вычисление набора значений либо в терминах поведения UML, либо на основе текстового утверждения на языке, отличном от UML.

У непрозрачного выражения может быть тело, состоящее из последовательности текстовых строк, представляющих альтернативные способы вычисления значений непрозрачного выражения. Соответствующая последовательность строк языка может использоваться для указания языков, на которых следует истолковывать каждую из строк тела. Языки сопоставляются со строками тела по порядку. Спецификация UML не определяет, как строки тела истолковываются относительно какого-либо языка, хотя другие спецификации могут определять конкретные строки языка, используемые для указания истолкования согласно этим спецификациям (например, “OCL” для выражений, истолковываемых согласно спецификации OCL). Отметим также, что указывать языки не обязательно. Если они не указаны, то истолкование любых строк тела должно определяться неявно из формы тела или из контекста использования непрозрачного выражения.

Непрозрачное выражение может также задаваться поведением UML (см. подпункт 13.2), которое ограничено так, чтобы иметь только входные параметры и возвращаемый параметр. Значения непрозрачного выражения получаются вызовом поведения и возвратом значений на возвращаемом параметре. Входные параметры могут использоваться для передачи данных в поведение. Однако какие именно данные передаются, зависит от контекста использования непрозрачного выражения. Например, параметры могли бы предоставлять данные событий поведению непрозрачного выражения, используемого как сторож на ребре деятельности или как спецификация сторожа на переходе. Точный механизм этого в настоящей спецификации далее не определён, но для вычисления непрозрачного выражения, поведение которого имеет один или несколько входных параметров, инструмент должен предоставлять механизм определения значений всех входных параметров как зависящую от инструмента функцию от непрозрачного выражения и его поведения. Такое поведение может также обращаться к данным через элементы своего поведенческого описания, например читая значения атрибутов объекта-контекста.

Если у непрозрачного выражения более одной строки тела или есть поведение в дополнение к одной или нескольким строкам тела, то любое из тел или поведение может использоваться для вычисления непрозрачного выражения. Спецификация UML не определяет, как делается этот выбор.

### 8.3.4 Нотация

#### 8.3.4.1 Выражения

Выражение без операндов нотируется просто своим символом (в отличие от строкового литерала символ не заключается в кавычки). Выражение с операндами может нотироваться своим символом, за которым следуют круглые скобки, содержащие его операнды по порядку, разделённые запятыми. Однако в конкретных контекстах соответствующий инструмент может допускать особые нотации, включая инфиксные операторы.

О нотации использования строковых выражений с именованными элементами см. подпункт 7.4.4.

#### 8.3.4.2 Непрозрачные выражения

Если у непрозрачного выражения есть одна или несколько строк тела, они используются для отображения непрозрачного выражения в контексте содержащего его элемента. Спецификация UML не определяет синтаксис таких строк, но если для строки тела задан соответствующий язык, соответствующий инструмент может обеспечивать синтаксис этого языка. Соответствующий инструмент может также ограничивать допустимые языки или предполагать некоторый язык по умолчанию.

Если для непрозрачного выражения заданы языки, имя языка может отображаться в фигурных скобках ({}) перед строкой тела, которой оно соответствует. Однако не требуется, чтобы языки непрозрачного выражения отображались.

Если у языка есть спецификация, определяющая его имя, то имя языка, используемое в непрозрачном выражении, следует писать и капитализировать точно так, как оно указано в спецификации этого языка. Например, используйте “OCL”, а не “ocl”.

### 8.3.5 Примеры

#### 8.3.5.1 Выражения

xor else plus(x,1)

x+1

#### 8.3.5.2 Непрозрачные выражения

a>0 {OCL} i > j and self.size > i среднее число отработанных часов в неделю

## 8.4 Время

### 8.4.1 Краткое описание

В этом подпункте определяются выражения времени и длительности, дающие значения на основе простой модели времени. Эта простая модель времени предназначена как приближение для ситуаций, в которых более сложные аспекты времени и измерения времени можно безопасно игнорировать. Например, во многих распределённых системах нет глобального понятия времени, есть только понятие локального времени относительно каждого распределённого элемента системы. Эта относительность времени в простой модели времени не учитывается, как и эффекты, возникающие из-за несовершенных часов с конечным разрешением, переполнений, дрейфа, расхождения и т. д. Предполагается, что приложения, для которых такие характеристики существенны, будут использовать более сложную модель времени, предоставляемую подходящим профилем.

### 8.4.2 Абстрактный синтаксис

```text
                   {subsets ownedElement}                                       {subsets ownedElement}
                                   + expr                                       + expr
                                                       ValueSpecification
                                           0..1                                  0..1
      {subsets owner}                                                                                    {subsets owner}
     + timeExpression 0..1                                                                          0..1 + duration
                     TimeExpression                                                           Duration
           + timeExpression     0..1                                                         0..1 + duration
                                                      PackageableElement
                                   + observation          Observation       + observation
                                                  *                         *
                      TimeObservation                                                   DurationObservation
                  + firstEvent : Boolean = true                                    + firstEvent : Boolean [0..2]
          + timeObservation *                                                                 *   + durationObservation
                                                                            + event
                                        + event                              {ordered}
                                                        NamedElement
                                              1
                                                                            1..2
Figure 8.3 Time and Duration
```

### 8.4.3 Семантика

#### 8.4.3.1 Время

Структурные конструкции моделирования UML используются для моделирования свойств сущностей в конкретные моменты времени. В противоположность этому поведенческие конструкции моделирования используются для моделирования того, как эти свойства изменяются во времени. Событие — это спецификация чего-то, что может произойти в конкретный момент времени, когда нечто интересующее происходит в связи с моделируемыми свойствами и поведениями, — например, изменение значения свойства или начало выполнения деятельности.

Время в этом понимании — просто координата, упорядочивающая вхождения событий. Каждому вхождению события можно приписать значение временной координаты, и на этом основании можно говорить, что оно раньше, позже или одновременно с другим вхождением события.

Длительность — это промежуток времени между двумя вхождениями событий, вычисляемый как разность временных координат этих событий. Если у элемента модели есть поведенческий эффект, то этот эффект может происходить в течение некоторой длительности. Начальное событие этой длительности называется входом в элемент, а конечное событие — выходом из элемента.

#### 8.4.3.2 Наблюдения

Наблюдение обозначает наблюдение событий, которые могут происходить относительно некоторой другой части модели. Наблюдение ведётся над именованным элементом в модели. Интересующие события — это вход в указанный именованный элемент и выход из него. Если указанный именованный элемент не является поведенческим элементом, то длительность между входом в именованный элемент и выходом из него считается нулевой, но в остальном настоящая спецификация не определяет, какие конкретные события наблюдаются у элемента.

Существует два вида наблюдений: наблюдения времени и наблюдения длительности.

Наблюдение времени наблюдает либо вход в конкретный именованный элемент, либо выход из него. Если firstEvent истинно, то наблюдается событие входа, иначе наблюдается событие выхода. Результат наблюдения времени — время, в которое происходит наблюдаемое событие.

Наблюдение длительности наблюдает длительность относительно одного или двух именованных элементов. Если наблюдается один элемент, наблюдаемая длительность — между последовательными вхождениями событий входа и выхода элемента. Если наблюдаются два элемента, длительность — между событием входа или выхода первого элемента и последующим событием входа или выхода второго элемента. В последнем случае для наблюдения длительности должны быть также заданы два соответствующих значения firstEvent так, чтобы, если firstEvent=true для наблюдаемого элемента, наблюдалось событие входа, иначе — событие выхода.

#### 8.4.3.3 Выражение времени

Выражение времени — это спецификация значения, вычисляемая в временную координату для момента времени, возможно относительно некоторого заданного набора наблюдений.

Если у выражения времени есть expr, то оно вычисляется, давая результат выражения времени. expr должно вычисляться в единственное значение, но UML не определяет никакого конкретного типа или единиц, которые это значение должно иметь. expr может ссылаться на наблюдения, связанные с выражением времени, но стандартная нотация для таких ссылок не определена. Если у выражения времени есть expr, но нет наблюдений, то expr вычисляется в постоянную времени.

Если у выражения времени нет expr, то оно должно иметь одно наблюдение времени, и результат этого наблюдения является значением выражения времени.

#### 8.4.3.4 Длительность

Длительность — это спецификация значения, вычисляемая в некоторую длительность времени, возможно относительно некоторого заданного набора наблюдений.

Если у длительности есть expr, то оно вычисляется, давая результат выражения длительности. expr должно вычисляться в единственное значение, но UML не определяет никакого конкретного типа или единиц, которые это значение должно иметь. expr может ссылаться на наблюдения, связанные с длительностью, но стандартная нотация для таких ссылок не определена. Если у длительности есть expr, но нет наблюдений, то expr вычисляется в постоянную длительности.

Если у длительности нет expr, то она должна иметь одно наблюдение длительности, и результат этого наблюдения является значением длительности.

### 8.4.4 Нотация

#### 8.4.4.1 Наблюдения

Наблюдение может обозначаться прямой линией, присоединённой к именованному элементу, на который оно ссылается. Наблюдению даётся имя, которое показывается рядом с неприсоединённым концом линии. Дополнительные соглашения нотации наблюдений даны в других местах относительно конструкций моделирования, в которых они обычно используются (например, взаимодействий, см. подпункт 17.2).

#### 8.4.4.2 Выражения времени и длительности

Выражение времени или длительность обозначается текстовым представлением своего expr, если оно у него есть (см. подпункт 8.3.5). Это представление — формула для вычисления значения времени или длительности, которая может включать имена связанных наблюдений и константы. Если у выражения времени или длительности нет expr, то оно просто представляется своим единственным связанным наблюдением.

Длительность — это значение относительного времени, заданное в зависящем от реализации текстовом формате. Часто длительность — неотрицательное целочисленное выражение, представляющее число «тактов времени», которые могут истечь за эту длительность.

### 8.4.5 Примеры

Время часто представляется числовой координатой, и в этом случае expr выражения времени должно вычисляться в числовое значение, единицы которого могут предполагаться в модели по соглашению (например, время всегда в секундах). Либо для моделирования значений времени с конкретными единицами (например, Second, Day и т. д.) могут использоваться типы данных, и тогда expr выражения времени должно иметь соответствующий один из этих типов.

Длительность — это значение относительного времени и, как таковое, часто представляется неотрицательным числом, например целочисленным счётчиком числа «тактов времени» эталонных часов, истёкших за длительность. В этом случае expr выражения длительности должно вычисляться в неотрицательное числовое значение. Значение длительности может также использоваться для представления значения временной координаты как длительности от некоторого фиксированного «начала» времени. См. также рисунок 8.5 в подпункте 8.5.5.

## 8.5 Интервалы

### 8.5.1 Краткое описание

Интервал — диапазон между двумя значениями, прежде всего для использования в ограничениях, утверждающих, что некоторый другой элемент имеет значение в заданном диапазоне. Интервалы могут быть определены для любого типа значений, но особенно полезны для значений времени и длительности в составе соответствующих ограничений времени и ограничений длительности.

### 8.5.3 Семантика

#### 8.5.3.1 Интервалы

Интервал — это спецификация значения, заданная с помощью двух других спецификаций значения: min и max. Интервал вычисляется так: сначала вычисляется каждая из составляющих его спецификаций значения, которые должны вычисляться в единственное значение. Затем значением интервала становится диапазон от значения min до значения max — то есть множество всех значений, больших или равных min и меньших или равных max (которое может быть пустым множеством). Отметим, что, хотя синтаксически для min и max интервала допускаются любые спецификации значения любого типа, стандартное семантическое истолкование даётся только для интервалов, у которых спецификации значения min и max имеют один и тот же тип и на этом типе определён полный порядок.

Существует две специализации интервала для использования с ограничениями времени. Временной интервал задаёт диапазон между двумя значениями времени, заданными выражениями времени. Интервал длительности задаёт диапазон между двумя значениями длительности, заданными длительностями.

#### 8.5.3.2 Ограничение интервала

Ограничение интервала определяет ограничение, спецификация которого задана интервалом (см. также подпункт 7.6 об ограничениях). Утверждается, что constrainedElements ограничения интервала имеют значения в пределах диапазона, заданного интервалом этого ограничения интервала. Если у constrainedElement значение вне этого диапазона, то ограничение интервала нарушено. Если какой-либо constrainedElement нельзя истолковать как имеющий значение либо его значение не того же типа, что диапазон, заданный ограничением интервала, то ограничение интервала не имеет стандартного семантического истолкования. Существует две специализации ограничения интервала для использования в задании ограничений времени. Ограничение времени определяет ограничение интервала на одном constrainedElement, в котором ограничивающий интервал — временной интервал. Ограничение длительности определяет ограничение интервала на одном или двух constrainedElements, в котором ограничивающий

интервал — интервал длительности. Если constrainedElements два, то начало наблюдаемой длительности может быть между событием в первом constrainedElement и событием во втором.

### 8.5.4 Нотация

#### 8.5.4.1 Интервалы

Интервал нотируется текстуально текстовыми представлениями двух своих спецификаций значения, разделёнными “..”: <interval> ::= <min-value> ‘ ..’ <max-value> Временной интервал показывается нотацией интервала, где каждый элемент-спецификация значения — выражение времени. Интервал длительности показывается нотацией интервала, где каждый элемент-спецификация значения — длительность. (О нотации выражений времени и длительностей см. подпункт 8.4.4.)

#### 8.5.4.2 Ограничения интервала

Ограничение интервала показывается как аннотация своего constrainedElement. Для ограничения интервала может использоваться общая нотация ограничений (см. подпункт 7.6.4), причём интервал-спецификация обозначается текстуально, как указано выше. Для ограничений времени и ограничений длительности определены особые нотационные конструкции, приведённые ниже.

Ограничение времени одного constrainedElement может показываться как маленькая линия между графическим представлением constrainedElement и текстовым представлением временного интервала ограничения времени. Ограничение длительности может также показываться графической нотацией, связывающей его constrainedElements. Однако используемая нотация зависит от вида диаграммы, на которой появляется ограничение длительности (о нотации на диаграммах последовательности см. подпункт 17.8, о нотации на диаграммах синхронизации — подпункт 17.11).

#### 8.6.16.3 Обобщения

ValueSpecification

#### 8.6.16.4 Атрибуты

- body : String [0..*]

  текстовое определение поведения непрозрачного выражения, возможно на нескольких языках.

- language : String [0..*]

  задаёт языки, используемые для выражения текстовых тел непрозрачного выражения. Языки сопоставляются со строками тела по порядку. Истолкование тела зависит от языков. Если языки не указаны, они могут подразумеваться из тела выражения или из контекста.

#### 8.6.16.5 Концы ассоциаций

- behavior : Behavior [0..1] (opposite A_behavior_opaqueExpression::opaqueExpression)

  задаёт поведение непрозрачного выражения как поведение UML.

- /result : Parameter [0..1]{} (opposite A_result_opaqueExpression::opaqueExpression)

  если непрозрачное выражение задано с помощью поведения UML, то это ссылается на единственный требуемый возвращаемый параметр этого поведения. Когда поведение завершает выполнение, значения на этом параметре дают результат вычисления непрозрачного выражения.

#### 8.6.16.6 Операции

- isIntegral() : Boolean запрос isIntegral() указывает, предназначено ли выражение порождать целое.

  ```ocl
  body: false
  ```

- isNonNegative() : Boolean запрос isNonNegative() указывает, имеет ли целочисленное выражение неотрицательное значение.

  ```ocl
  pre: self.isIntegral()
  ```

  ```ocl
  body: false
  ```

- isPositive() : Boolean запрос isPositive() указывает, имеет ли целочисленное выражение положительное значение.

  ```ocl
  pre: self.isIntegral()
  ```

  ```ocl
  body: false
  ```

- result() : Parameter [0..1] вывод для OpaqueExpression::/result

  ```ocl
  body: if behavior = null then
  null
  else
  behavior.ownedParameter->first()
  endif
  ```

- value() : Integer запрос value() даёт целое значение для выражения, предназначенного порождать целое.

  ```ocl
  pre: self.isIntegral()
  ```

  ```ocl
  body: 0
  ```

#### 8.6.16.7 Ограничения

- **language_body_size**

  Если атрибут language не пуст, то размеры массивов body и language должны совпадать.

  ```ocl
  inv: language->notEmpty() implies (_'body'->size() = language->size())
  ```

- **one_return_result_parameter**

  Поведение должно иметь ровно один возвращаемый параметр результата.

  ```ocl
  inv: behavior <> null implies
  behavior.ownedParameter->select(direction=ParameterDirectionKind::return)->size() = 1
  ```

- **only_in_or_return_parameters**

  Поведение может иметь только непотоковые параметры in или return.

  ```ocl
  inv: behavior <> null implies behavior.ownedParameter->forAll(not isStream and
  (direction=ParameterDirectionKind::in or direction=ParameterDirectionKind::return))
  ```

### 8.6.17 StringExpression (строковое выражение) [Class]

#### 8.6.17.1 Описание

Строковое выражение — это выражение, задающее строковое значение, получаемое конкатенацией последовательности операндов со строковыми значениями или последовательности подвыражений, некоторые из которых могут быть параметрами шаблона.

#### 8.6.17.2 Диаграммы

Выражения, пространства имён

#### 8.6.17.3 Обобщения

TemplateableElement, Expression

#### 8.6.17.4 Концы ассоциаций

- owningExpression : StringExpression [0..1]{subsets Element::owner} (opposite StringExpression::subExpression) строковое выражение, подвыражением которого является это строковое выражение.

- ♦ subExpression : StringExpression [0..*]{ordered, subsets Element::ownedElement} (opposite StringExpression::owningExpression) строковые выражения, составляющие это строковое выражение.

#### 8.6.17.5 Операции

- stringValue() : String {redefines ValueSpecification::stringValue()} запрос stringValue() возвращает строку, получающуюся конкатенацией по порядку всех составляющих строковых значений всех операндов или подвыражений, входящих в строковое выражение.

  ```ocl
  body: if subExpression->notEmpty()
  then subExpression->iterate(se; stringValue: String = '' |
  stringValue.concat(se.stringValue()))
  else operand->iterate(op; stringValue: String = '' | stringValue.concat(op.stringValue()))
  endif
  ```

#### 8.6.17.6 Ограничения

- **operands**

  Все операнды строкового выражения должны быть строковыми литералами

  ```ocl
  inv: operand->forAll (oclIsKindOf (LiteralString))
  ```

- **subexpressions**

  Если у строкового выражения есть подвыражения, оно не может иметь операндов, и наоборот (это избавляет от необходимости определять порядок сопоставления операндов и подвыражений).

  ```ocl
  inv: if subExpression->notEmpty() then operand->isEmpty() else operand->notEmpty() endif
  ```

#### 8.6.22.1 Описание

Спецификация значения — это спецификация (возможно пустого) множества значений. Спецификация значения — параметризуемый элемент, который может быть представлен как формальный параметр шаблона и предоставлен как фактический параметр в связывании шаблона.

  ```ocl

  ```

- isCompatibleWith(p : ParameterableElement) : Boolean {redefines ParameterableElement::isCompatibleWith()} запрос isCompatibleWith() определяет, совместима ли эта спецификация значения с указанным параметризуемым элементом. Эта спецификация значения совместима с параметризуемым элементом p, если вид этой спецификации значения тот же, что и вид p, или является его подтипом. Кроме того, если p — типизированный элемент, то тип этой спецификации значения должен соответствовать типу p.

  ```ocl
  body: self.oclIsKindOf(p.oclType()) and (p.oclIsKindOf(TypedElement) implies
  ```

- isComputable() : Boolean запрос isComputable() определяет, можно ли вычислить спецификацию значения в модели. Эту операцию нельзя полностью определить в OCL. Ожидается, что соответствующая реализация сможет вычислить по меньшей мере значение всех литеральных спецификаций.


  ```ocl
  body: false
  ```

